Execute a shell command in the current working directory. Returns stdout and stderr. Output is truncated to last 2000 lines or 50KB (whichever is hit first). If truncated, full output is saved to a temp file. Optionally provide a timeout in seconds.

# Foreground vs background (CRITICAL)

Default is FOREGROUND: the agent is BLOCKED until the command exits (or until the soft wait, then auto-promote — see Modes).

NEVER run a process that does not exit on its own in the foreground without `run_in_background: true`.

MUST set `run_in_background: true` for anything that keeps the console open / runs until killed, including:
- Dev servers: npm/pnpm/yarn/bun run dev|start, vite, next dev, nuxt, webpack-dev-server
- Watchers: *--watch*, nodemon, vitest --watch, jest --watch
- Containers: docker compose up (without -d), docker run (without -d)
- Make/scripts that serve: make dev, make serve, rails s, flask run, uvicorn (no oneshot)
- Tunnels / REPL / follow: ssh -N, tail -f, python -i

Decision:
- Will this process exit on its own within about a minute? → foreground (optional hard `timeout`)
- Will it keep running until killed? → `run_in_background: true`
- Unsure? → `run_in_background: true`

Do NOT use shell `&`, `nohup`, or manual disown; use `run_in_background`.
Do NOT poll with long `sleep` while waiting on a foreground server — that hangs the agent.

# Modes

1. `run_in_background: true` — starts immediately as a background task; returns task ID. Use `task_output` / `task_stop`. When the command finishes you receive a `<task-notification>`. Ignores timeout.
2. `timeout: N` — foreground with hard kill after N seconds (bounded work: builds, one-shot tests).
3. Neither set — foreground soft wait (default 45s). If still running, auto-promoted to a background task (same as background after the wait). Quick commands still return inline when they exit before the soft wait.

Do NOT use `run_in_background` for quick one-shot commands — the result arrives faster inline.

IMPORTANT: NEVER use shell for operations that have dedicated tools. Use the right tool:
- File reading: ALWAYS use `read` (NEVER cat, head, tail, less, more)
- File editing: ALWAYS use `edit` (NEVER sed, awk, perl -i)
- File writing: ALWAYS use `write` (NEVER echo >, cat <<EOF, tee)
- File search by name: ALWAYS use `find` (NEVER shell find, fd, locate)
- File content search: ALWAYS use `grep` (NEVER shell grep, rg, ag, ack)
- Directory listing: ALWAYS use `ls` or `dir_tree` (NEVER shell ls, tree)
- PDF text extraction: ALWAYS use `extract_text_from_pdf` (NEVER pdftotext, pdf2txt, pdfinfo)
- Image text extraction: ALWAYS use `extract_text_from_img` (NEVER tesseract, ocrmypdf)
- Skill invocation: ALWAYS use `invoke_skill` (NEVER shell find/locate/mdfind to search for skill files)

Use shell ONLY for: running scripts, package managers (npm, pip, cargo, etc.), git commands, compilers, interpreters, complex piping, or commands with no dedicated tool equivalent.

# Skill / Scene Directory Protection

Skill and scene directories are READ-ONLY. NEVER write output files, temp files, logs, or any generated content into skill or scene directories.

Protected paths (NEVER write here):
- ~/.vetta/agent/skills/ and its subdirectories
- ~/.vetta/skills/ and its subdirectories
- ~/.vetta/scenes/ and its subdirectories
- .vetta/skills/ under the current project

When a skill or scene needs to produce output files (e.g. generated PDFs, images, reports), ALWAYS write them to the user's working directory (cwd) or a subdirectory thereof. For example, write to `./output.pdf` instead of placing the file inside the skill folder.

# Git Safety Protocol

When running git commands, follow these rules strictly:
- NEVER run destructive git commands without explicit user request:
  - `git reset --hard` - destroys uncommitted changes
  - `git push --force` / `git push -f` - can overwrite remote history
  - `git checkout .` / `git restore .` - discards all local changes
  - `git clean -fd` - deletes untracked files permanently
  - `git branch -D` - force-deletes a branch
  - `git stash drop` - permanently discards stashed changes
- NEVER skip hooks: do NOT use `--no-verify` or `--no-gpg-sign` unless user explicitly asks
- NEVER use `git add -A` or `git add .` - these can stage unrelated files. ALWAYS add specific files by path
- NEVER amend commits unless user explicitly requests it - amending can destroy the previous commit
- Before any destructive operation, consider if there is a safer alternative

On Windows, this tool uses PowerShell by default.
