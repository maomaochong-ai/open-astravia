# 内容创作画布参考分析

本目录记录 `content-creation` preset 在进入下一轮实现前，对四个本地参考项目所做的设计分析。分析目标是建立共同的产品与架构语境，后续提出“像某项目的节点、面板或操作”时，可以落到明确的设计对象，而不是仅凭界面印象调整。

当前实施架构见 [画布交互架构](./canvas-interaction-architecture.md)、[内容生成与插件凭据架构](./generation-architecture.md) 与 [模型目录和适配器](./model-adapters.md)。

## 分析边界

- 聚焦无限画布、节点或画布对象、连接关系、节点操作、属性与生成面板、模型接入、任务状态、素材回流和 Agent 操作。
- 暂不分析多轨时间线、剪辑轨道、播放头、片段吸附和导出编排。
- 只参考产品行为、信息架构和技术边界，不复制源代码、样式资产或品牌表达。
- 模型清单是所分析提交中的实现快照，不作为本插件未来必须写死的产品清单。

## 四种设计的核心差异

| 维度 | Open-AI Canvas | TwitCanva | Nodetool | Loomic |
| --- | --- | --- | --- | --- |
| 用户心智 | 在空间中完成脚本、参考、生成和加工 | 把文本/媒体串成生成链 | 搭建可重复执行的数据流程序 | 在白板上直接创作并让 AI 操作对象 |
| 画布主实体 | 富媒体创作节点 | 固定类型媒体节点 | 注册表提供的计算节点 | Excalidraw 原生元素与生成占位元素 |
| 连接语义 | 内容引用与创作上下文，部分节点有专用端口 | `parentIds` 表示上游输入，规则写在前端 | 输入/输出槽位带类型，连接由元数据验证 | 没有工作流连线，依靠空间选择和 Agent 上下文 |
| 参数入口 | 节点内提示词面板、浮动工具条、专项弹层 | 节点下方内联控制面板 | 属性元数据自动选择控件并直接显示在节点内 | 选中占位对象后，在对象下方打开浮动生成面板 |
| 结果表达 | 生成结果成为新节点或复用空媒体节点，并保留关系 | 结果写回当前节点 | 输出实时渲染在节点中，可继续向下游传递 | 占位对象被原生图片或可播放视频对象替换 |
| 模型策略 | 按协议与能力动态过滤渠道模型 | 前端维护能力矩阵，并按输入模式过滤 | Provider/模型/节点包注册，模型选择器独立 | Provider 注册表汇总模型，面板从服务端获取 |
| Agent 策略 | 结构化画布操作，执行前可预览影响 | 侧边聊天辅助，画布协议相对弱 | Agent 本身也是节点，另有图规划与工作流工具 | Agent 可检查、操作画布并提交生成任务 |

## 对 `content-creation` 的实施基线

当前 preset 已有 React Flow 画布、领域命令、项目仓库和 Agent 工具，但它只验证了插件接入、状态流和持久化。参考项目表明，下一阶段不应继续只增加静态节点卡片，而应补齐以下稳定边界。

### 1. 保留图编辑器内核，扩展“创作节点”而不是改造成纯计算图

继续以 React Flow 作为连接、选择、拖拽、缩放和视口基础。节点对用户应表现为文本、素材、生成器、处理器、组织容器和输出，而不是暴露底层 API 调用。Nodetool 的强类型端口适合成为内部约束，Open-AI Canvas 的富媒体节点适合作为用户体验层。

### 2. 把节点定义从项目实例中分离

建议形成独立 `NodeDefinitionRegistry`：

- 稳定标识、类别、图标和默认尺寸；
- 输入/输出端口及内容类型；
- 属性 schema 与默认值；
- 可用操作和结果渲染器；
- 可接受的 Provider 能力，而不是具体模型名；
- 简洁模式与专业模式的可见性。

项目 JSON 只保存节点实例、端口连接和用户参数，不保存 UI 组件或 Provider 实现。

### 3. 使用节点绑定的两层交互

综合参考实现和本插件对画布视野的要求，节点交互拆成两层：

1. 节点卡片：标题、内容预览、端口、状态、最常用参数。
2. 选中/悬浮工具条：复制、变体、下载、保存素材、重试、删除，以及类型专属快捷操作。

节点主体作为随画布缩放的内容缩略图，提示词节点在其中展示提示词摘要，媒体节点展示占位、生成状态或结果。完整提示词、模型、比例、质量、时长和参考素材由节点下方的锚定操作面板承载；面板只在单选时出现，保持固定屏幕尺寸而不随画布缩放，因此在缩小视野下仍可直接操作。

### 4. 模型必须通过能力注册表接入

插件不应在节点组件中判断模型字符串。建议拆分：

- `ProviderAdapter`：鉴权、提交、轮询/流式返回、错误归一化；
- `ModelDescriptor`：模态、能力、输入限制、尺寸/比例/时长、费用提示；
- `CapabilityResolver`：根据节点类型、连接输入和当前模式过滤模型；
- `GenerationRequestMapper`：把稳定的领域参数映射为供应商参数。

节点保存的是选中的模型引用和领域参数；Provider 特有参数放在命名空间下，避免污染所有节点。

### 5. 生成任务和内容资产必须是独立领域对象

生成不是一次组件内的 `fetch`。至少需要：

- `GenerationJob`：queued/running/succeeded/failed/cancelled、进度、尝试次数和外部任务 ID；
- `Artifact`：图片、视频、音频、文本或文档的持久化描述；
- 节点与任务、节点与产物之间的引用；
- 页面恢复后的任务重连；
- 生成结果插入策略：写回原节点、创建变体节点或创建下游结果节点。

Open-AI Canvas 的任务恢复与结果节点、Loomic 的后台队列、Nodetool 的运行消息流共同证明这是画布可靠性的核心，而不是后续优化项。

### 6. Agent 与 UI 共用命令，但增加预览和授权

保留当前 `ContentCreationWorkspace.dispatch()` 单一写入口。后续将操作扩展为节点、连接、视口、选择、生成和素材命令，并为 Agent 批量操作增加：

- 影响摘要；
- 删除与付费生成提示；
- 批次 ID 与可撤销边界；
- 操作结果和任务 ID 回传。

### 7. 自由创作能力作为画布对象层，而不是替代节点图

Loomic 证明了自由绘图、原生图片对象和空间 Agent 上下文的价值。建议后续把注释、形状、手绘、Frame/Section 作为“非执行画布对象”加入同一项目模型，但不因此放弃端口与数据流。执行节点与自由对象需要有明确的数据边界，例如把选中图片或绘图转换为节点输入。

## 下一轮建议顺序

1. 节点定义注册表与强类型端口。
2. 节点库、拖线后兼容节点菜单、空白处快捷添加。
3. 富媒体节点卡片、悬浮工具条和节点锚定的类型化编辑器。
4. Provider/Model 能力注册表与一个真实生成适配器。
5. GenerationJob、Artifact、任务恢复和结果插入策略。
6. Agent 操作预览、批次撤销和付费操作确认。
7. Frame、绘图、注释等非执行画布对象。

这个顺序先建立可扩展内核，再增加供应商和创作工具；避免每接一个模型或节点，就在 React 组件中增加一组条件分支。
