# Open-AI Canvas 画布设计分析

## 结论

Open-AI Canvas 是四个参考项目中最接近“内容创作工作台”的实现。它没有把画布做成纯计算图，而是把文本、角色参考、分镜脚本、图片、视频、音频、绘图和空间分组放在同一创作平面中。连接既表示输入依赖，也表达“这个素材是下一个生成步骤的参考”。

对 `content-creation` 最有价值的不是其具体视觉样式，而是三点：富媒体节点本身就是主要工作界面；生成结果继续留在画布并保留来源关系；简单模式与专业模式共用领域模型，只调整可见能力。

## 1. 画布定位与页面结构

项目将画布定义为 AI 影视/短剧创作空间。界面主体保持全屏，主要控制以浮动层存在：

- 顶栏承担项目、工作模式、搜索、任务和 Agent 等全局入口；
- 底部浮动 Dock 提供选择/手型、撤销/重做、添加、素材、外观和清理操作；
- 节点的高频动作出现在节点上方的悬浮工具条；
- 完整参数通过节点附近的提示词/设置面板或专项编辑弹层呈现；
- 脚本节点可以在一个大节点内承载结构化分镜表格，而不是把每个字段拆成小节点。

这是一种“空间优先”的信息架构：全局面板尽量不永久占据画布，用户注意力留在内容和关系上。

## 2. 节点体系

核心类型定义在 `web/src/types/canvas.ts`：

| 节点类型 | 用户语义 | 主要内容/行为 |
| --- | --- | --- |
| `Text` | 创意、提示词、说明或生成文本 | 可直接编辑、调用文本模型、转为图片生成 |
| `Image` | 参考图或生成图 | 上传、生成、编辑、裁剪、蒙版、超分、视角、保存素材 |
| `Video` | 参考视频或生成视频 | 上传/生成、下载、提取尾帧、作为后续视频参考 |
| `Audio` | 音频素材或生成音频 | 上传/生成、下载、作为媒体参考 |
| `Drawing` | 手绘或基于图片的标注 | 进入独立绘图编辑器，可由已有图片快速创建 |
| `Script` | 分镜脚本/镜头表 | 在节点内部管理镜号、时长、画面描述、台词和镜头生成 |
| `Config` | 生成配置 | 专业模式下集中表达生成参数，不作为普通媒体结果 |
| `Skill` | 可复用创作技能 | 保存技能信息并参与生成上下文 |
| `Frame` | 空间分组/背板 | 包含和移动子节点，复制时可携带内容，不参与普通连接 |

节点实例包含位置、宽高、父 Frame，以及庞大的 `CanvasNodeMetadata`。元数据覆盖提示词、模型、尺寸、质量、时长、参考素材、任务、分镜、角色、导演参数、批次与版本等。

优点是功能集中、落地快；缺点是所有节点共享一个不断扩大的元数据接口。对 Vetta 应吸收其领域覆盖面，但用按节点类型区分的参数 schema 和命名空间扩展替代单一“万能 metadata”。

## 3. 连接与上下文解析

连接记录来源/目标节点、端口 ID 和锚点比例。连接不仅用于画线，生成执行器会遍历相连节点，把它们解析为：

- 文本提示词；
- 图片、视频和音频参考；
- 绘图内容；
- 配置节点参数；
- 分镜行或镜头上下文；
- 角色、场景和其他项目资源。

值得借鉴的操作是“从端口拖到空白区域后创建兼容节点”。快速创建时，新节点按来源节点和端口锚点自动摆放并立即连线；从分镜专用端口创建视频节点时，还会把镜头描述、时长和工作流语义写入新节点。

连接控制器还处理：

- 防止 Frame 参与普通数据连接；
- 配置节点之间的非法连接提示；
- 已有连接的锚点更新；
- 图片输出直接创建带底图的 Drawing 节点；
- 脚本行与下游媒体节点的专用端口映射。

这说明端口不能只有 `source/target` 两个视觉方向，还应有稳定端口 ID、内容类型和业务角色。

## 4. 节点 UI 与操作面板

### 节点渲染结构

Open-AI Canvas 没有把节点当成一个带边框的单层卡片。普通节点的渲染被拆成几个彼此独立的空间层：

1. `CanvasProjectWorldLayers` 先按可见节点列表渲染，Frame 走独立组件，普通内容节点进入 `CanvasNode`；连线位于单独的 SVG/Leafer 图层，不与节点内容共同布局。
2. `CanvasNode` 的最外层只负责世界坐标、宽高、层级、悬停和拖拽，不负责裁剪。这样标题、缩放柄和连接轨可以安全地伸到节点边界之外。
3. `NodeExternalHeader` 位于内容壳层上方，标题与类型图标不挤占媒体面积；标题按视口反向缩放保持屏幕可读尺寸，并在远景隐藏，避免遮挡画布。
4. `CometCard`/`canvas-node-shell` 才是节点视觉壳层，负责圆角、边框、阴影、选中/关联状态和媒体裁剪。图片与视频尽量铺满主体，状态与资源信息以角标覆盖，不再嵌套一层通用表单卡片。
5. `NodeContent` 先处理 loading/error，再按节点类型选择内容渲染器；角色、分镜、配置等特殊内容通过显式的自定义渲染入口接入。外壳不需要理解每种业务字段。
6. 左右 `ConnectionSideRail` 位于视觉壳层之外。连接轨在悬停时出现，使用较大的透明交互区域、较小的圆形 `+` 视觉点，并根据指针在节点侧边的位置记录锚点比例；输入、输出能力仍由节点类型限制。
7. `CanvasNodeHoverToolbar` 不是节点内部子面板，而是画布覆盖层。它根据节点和容器的真实边界定位，拖拽时隐藏，因此不会改变节点尺寸，也不会参与连接锚点测量。

它还专门控制渲染成本：`CanvasNode` 使用 memo；渲染模型先做视口裁剪；拖拽、低缩放或大量媒体时关闭较重空间效果；图片接近视口后才解析资源。这些优化共同保证“媒体是节点主体”不会直接演变成整张画布持续重渲染。

对当前 preset 的直接落点是采用“外层交互容器 + 内层裁剪壳”的结构。端口、标题工具条和参数工具条属于外层；媒体和文档表面属于内层。端口 DOM 必须保持稳定，空闲时保留可发现的连接点，悬停或选中时再展示端口名称。

### 底部 Dock

`canvas-toolbar.tsx` 的添加入口按“创作节点”和“资源”组织，而不是暴露技术 Provider：

- 文本、绘图、分镜脚本；
- 专业模式中的 Frame、导演台和音频；
- 图片与视频；
- 上传、我的素材和项目角色。

外观面板管理主题、背景和图像信息；删除选择与清空画布也在全局 Dock 中。

### 节点悬浮工具条

`canvas-node-hover-toolbar.tsx` 根据节点类型和当前内容动态生成动作：

- 通用：信息、重试、保存素材、下载、锁定、删除；
- 文本：文本生成、放大编辑、文生图、字号；
- 空媒体：上传；
- 视频：替换、提取尾帧；
- 图片：标注、蒙版、表情、肖像质感、裁剪、分割、放大、超分、视角、查看、反推提示词等。

图片快捷动作可以由用户配置。这个设计比固定塞入所有按钮更适合不断增长的内容工具。

### 右键菜单

右键菜单区分空白、节点和连接：

- 空白处添加节点、上传或打开素材；
- 节点复制、创建参数变体、粘贴和删除；
- Frame 的复制/删除文案强调会影响内部内容；
- 连接只暴露删除，避免在边上堆积不相关操作。

### 提示词与参数面板

`canvas-node-prompt-panel.tsx` 将提示词、资源提及、模型选择与模态专属参数放在同一锚定面板中。模型选择器读取渠道配置并按能力过滤；图片、视频、音频分别打开不同的设置 Popover。

对 Vetta 的启示是：节点检查器不应是一个所有节点共用的静态表单。它需要由节点 schema 和模型能力共同决定字段，同时保留一个靠近节点的快速编辑形态。

## 5. 用户操作流程

典型流程不是“一次生成并下载”，而是：

1. 添加文本、角色图或脚本节点；
2. 通过拖线或节点动作创建图片/视频节点；
3. 相连节点自动成为生成上下文；
4. 在节点旁选择模型与参数并提交；
5. 输出写入空目标节点，或创建新的结果节点并连回来源；
6. 对结果继续裁剪、蒙版、超分、视角或提取尾帧；
7. 将满意结果保存为项目素材，再供其他节点引用。

生成结果留在空间中形成可回看、可分叉的创作路径，这比覆盖当前预览更适合探索式内容创作。

## 6. 模型与 Provider 架构

该项目的核心不是写死模型名称，而是“渠道 + 模型目录 + 协议 + 能力”。`web/src/lib/model-protocols.ts` 定义了文本、图片、视频和音频协议：

- 文本：OpenAI Chat Completions、OpenAI Responses；
- 图片：OpenAI Images、火山方舟图片、即梦官方图片；
- 音频：OpenAI Audio Speech；
- 视频：OpenAI/NewAPI Videos、NewAPI 媒体任务与 Video Generations、xAI Video、火山方舟/即梦视频、Gemini Veo 长任务。

协议描述提交路径、轮询路径、内容类型和可接受媒体。具体模型从用户配置的渠道和模型目录读取，Model Picker 再按 `text/image/video/audio` 能力筛选。

这种设计适合多供应商，但需要避免“协议能力”和“具体模型限制”混为一层。Vetta 应进一步把模型支持的参考图数量、比例、时长、音频、首尾帧等限制放入 `ModelDescriptor`，由同一个 Resolver 同时服务 UI 校验和请求映射。

## 7. 生成任务、批次和恢复

项目定义生成批次、批次项以及独立后台任务。节点状态为 idle/loading/success/error，元数据保存任务 ID、进度、阶段、错误和时间信息。

`use-canvas-generation.ts` 的关键行为包括：

- 同一目标的新请求会中止前一个前端请求；
- 后台任务可以显式取消并查看日志；
- 页面重新加载后按任务 ID或项目最近任务恢复；
- 找不到任务时把节点转为可理解的错误状态；
- 成功的媒体结果自动同步到项目素材；
- 停止生成和取消后台任务具有不同语义。

这部分应直接进入 Vetta 的下一阶段基础设施，而不是等真实模型增多后补救。

## 8. Agent 操作协议

`web/src/lib/canvas/canvas-agent-ops.ts` 使用结构化操作：添加/更新/删除节点、删除连接、连接节点、设置视口、选择节点和触发文本/图片/视频/音频生成。

执行前会计算受影响节点、删除数量和生成数量，并提示：

- 删除可按 Agent 批次撤销；
- 生成可能产生费用；
- 画布撤销不会取消已提交的后台任务。

这与 Vetta 当前“UI 与 Agent 共用命令入口”的方向一致。需要补的是批次预览、危险操作授权、生成费用提示和任务取消边界。

## 9. 应吸收与应避免

### 应吸收

- 创作节点而非 API 节点的用户语言；
- 文本、媒体、脚本、绘图、Frame 同处一个空间；
- 拖线后创建兼容节点；
- 节点卡片、悬浮工具条、专项面板的三层交互；
- 简洁/专业模式共用底层模型；
- 结果节点、变体分叉和自动素材回流；
- 后台任务恢复与 Agent 操作预览。

### 应避免

- 把所有节点字段持续堆入一个巨型 metadata；
- 在组件内根据模型字符串分支协议和参数；
- 让分镜、角色等特定业务逻辑渗透所有通用画布模块；
- 把过多图片工具固定显示在悬浮条上。

## 10. 对 `content-creation` 的具体落点

1. 以当前 React Flow 为内核，先补 `Text/Media/Generator/Processor/Frame/Output` 六类节点定义。
2. 把生成节点的输入端口拆为 prompt、image、video、audio、config 等稳定角色。
3. 增加“拖线到空白处”的兼容节点菜单。
4. 将当前 `NodeInspector` 改为 schema 驱动，并增加节点上方的快捷操作条。
5. GenerationJob 与 Artifact 独立建模，结果默认创建下游变体节点；空目标节点可选择复用。
6. Agent 批量命令执行前返回影响摘要，生成命令独立返回任务 ID。
