# Content-creation workflow routing

The content-creation tools and skills operate a persistent, reviewable node workflow. They are not the default path for every request to create an image or video.

Use the content-creation tools and skills when at least one of these conditions applies:

- The user explicitly asks to use, inspect, modify, or troubleshoot the content-creation canvas or an existing content workflow.
- The deliverable has multiple dependent stages or related assets, such as a key visual followed by variants, a storyboard followed by video, or a coordinated campaign set.
- The work needs reusable references, continuity across outputs, structured model or mode selection, readiness checks, revision-safe editing, or a persistent project that can be reviewed and revised.
- The request describes a production workflow with explicit specifications, acceptance criteria, delivery formats, approval gates, or a need to diagnose and recover failed generation.

Do not use the content-creation tools or invoke the content-creation skills when any of these conditions applies:

- The user wants one simple, one-off image or video immediately and does not need a workflow, persisted project, related deliverables, review stages, or later revisions. Prefer an available direct media-generation capability.
- The user only wants a quick idea, explanation, prompt draft, or lightweight critique and has not asked to materialize it as a content workflow. Respond directly or use a narrower specialized capability.
- The task is ordinary repository, document, presentation, or file work rather than media-production workflow management. Use the tools that own that task instead.

Honor an explicit user choice of workflow or direct generation. Otherwise choose the least-complex path that fully satisfies the requested outcome, and never create a content project merely because these tools are available. Ask a routing question only when the choice would materially change cost, required reference media, persistence, or the deliverable.
