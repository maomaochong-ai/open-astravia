# Compose specialized recipes into campaigns

Do not merge several recipes by concatenating their prompts. Compose their artifacts and gates.

## Recipe contract

For each selected recipe record:

- job and requested deliverables;
- required user inputs and reversible defaults;
- authority assets and reference roles;
- cheap exploration nodes;
- approval/quality gate;
- dependent expensive nodes;
- parallel branches;
- delivery checks;
- capability-dependent or external steps;
- fallback deliverable.

## Common compositions

### Logo to brand launch

Brand strategy -> logo hypotheses -> selected mark -> palette/type/system -> application proofs -> social/ad assets -> delivery guide.

The selected mark is authority. Application mockups cannot become a source of truth for logo geometry or colors.

### Product listing to launch campaign

Product authority -> compliant listing views + lifestyle/detail proof -> selected campaign hero -> motion proof -> product film -> social/platform compositions.

Listing assets can run in parallel after product fidelity passes. Campaign motion waits for the hero gate.

### Creator/UGC campaign

Person authority + product authority -> credible composite stills -> hook/script hypotheses -> selected performance direction -> video proof -> vertical variants/covers/copy.

Keep verified claims and product handling fixed across script variants. Do not scale several videos from an unapproved face/product composite.

### Character/photo story system

Identity ledger -> neutral anchor -> pose/expression/environment pack -> selected keyframes -> motion clips -> timeline -> social stills/covers.

Reject drift at the first asset where it appears. Do not use a later attractive but inconsistent image as authority without explicit reselection.

### Storyboard/tutorial production

Objective/process -> beat list -> character/product and environment authorities -> storyboard/composite board -> riskiest motion proof -> step clips or supported multi-beat generation -> timeline -> delivery exports.

### Long-form distribution

Source video/transcript -> candidate highlight table -> ranked/deduped selection -> timeline trims/crops -> covers/captions -> platform delivery audit.

## Stage graph rules

- Share an authority node rather than regenerating the same product, person, logo, room, or character in every branch.
- Run parallel only when nodes do not depend on an unresolved choice.
- Mark rejected candidates as rejected rather than deleting evidence of the selection.
- When an authority changes, invalidate only descendants whose assumptions changed.
- Put unsupported Provider work in an explicit external/pending deliverable note; never represent it as a successful node.

## Budget allocation

- High strategic uncertainty: 3-4 cheap hypotheses and one proof.
- High identity/product risk: fewer concepts, stronger authority checks, riskiest branch first.
- High format count: approve one master before fan-out.
- High motion uncertainty: one short representative motion proof before sequence rendering.
- Hard deadline: protect must-have deliverables first and define a still/static fallback.

## Delivery manifest

Return a manifest with asset/shot name, source authority, purpose, channel, ratio, duration/resolution, status, review verdict, and remaining external work. A campaign is incomplete when a file exists but its intended job, lineage, or review result is unknown.
