# Structural and dimensional control

## Treat structure as a reference role

A sketch, wireframe, grid, plan, elevation, or blockout may define placement and proportion without defining final style. State both:

- inherit: layout, silhouette, camera, spatial relations, or grid;
- ignore: handwriting, placeholder content, gray materials, guides, labels, or rough rendering.

## Sketch or wireframe to final

Specify the final artifact, target fidelity, exact elements, typography, and constraints. Preserve the structural hierarchy before adding finish. For UI mockups, require plausible components, spacing, state, data, and exact copy rather than concept-art shapes.

## Grid-controlled assets

State rows, columns, reading order, cell purpose, gaps/borders, and whether identity/style must remain constant. Use for sprites, contact sheets, layouts, and modular brand systems.

## Dimensional translation

- Plan/elevation -> 3D view: preserve room/structure relationships; define camera, materials, light, and which spaces must remain visible.
- Sketch -> product/character volume: preserve silhouette and functional geometry; state material behavior and intended viewpoint.
- 3D/blockout -> final rendering: preserve camera, blocking, proportion, occlusion, and cuts; replace only material, lighting, environment, and finish.
- 3D -> technical 2D: select plan/elevation/section/exploded view, line hierarchy, labels, and scale cues.

Generated architecture and technical diagrams are visual concepts, not construction truth. Do not claim dimensional accuracy without a deterministic CAD/BIM validation step.

## Quality gate

Compare the result against the structural source for relative positions, proportions, axes, perspective, counts, and protected empty regions before judging style.
