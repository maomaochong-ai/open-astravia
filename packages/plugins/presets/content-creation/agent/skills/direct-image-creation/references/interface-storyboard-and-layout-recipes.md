# Interface, storyboard, and layout recipes

## UI mockup

Start from product behavior, not an aesthetic label.

1. Record platform/viewport, audience, user goal, screen state, navigation model, primary action, data/content requirements, and accessibility constraints.
2. Define a compact design system: type roles, spacing unit, color roles, control shapes, density, and elevation/border behavior.
3. Describe layout tracks and named components. Use realistic copy and data; do not use decorative dashboard noise.
4. Generate a pure interface view without hands, desks, device glamour shots, or nested marketing presentation unless explicitly requested.
5. Review hierarchy, action discoverability, component consistency, contrast, touch targets, text fit, and whether the screen can plausibly perform its stated job.

An image mockup is not implementation. Hand off accepted structure to a code/design workflow when interaction or exact responsive behavior is required.

## URL or screenshot redesign

Inspect the actual page or screenshot before proposing changes. Extract brand cues, information architecture, content hierarchy, core components, and current usability problems.

1. Decide what must remain: brand, copy, product facts, navigation, or information architecture.
2. Write a redesign hypothesis tied to observable problems.
3. Produce desktop and mobile views from the same content/component contract, not two unrelated designs.
4. Explain the changed hierarchy, spacing, CTA, navigation, responsive behavior, and accessibility implications.
5. If the URL cannot be inspected, require a screenshot or clearly label the output as a concept based only on the provided description.

## Storyboard keyframes

1. Convert the premise into an arc: setup, trigger, escalation, climax, resolution.
2. Give each frame a job, beat, shot size, camera axis, subject action, environment state, continuity anchors, and intended handoff.
3. Keep the exact continuity block in every independent prompt.
4. Generate composition-first frames in parallel only when their shared authority assets are already approved.
5. Return frames in narrative order with captions and note which frames are suitable as start/end anchors for video.

Do not animate, upscale, or add audio unless the user asks to continue into `$direct-video-creation`.

## Composite production board

Use a composite board when one downstream model must see several kinds of guidance at once. Assign zones such as character turnaround, environment plate, prop/product details, ordered action panels, palette, and compact technical icons.

- Keep labels large and minimal.
- Give each zone a distinct job and adequate resolution.
- Preserve one authority source per recurring subject.
- Approve the board itself before using it as an expensive generation reference.
- Do not assume a dense board is readable by every model; inspect capability and test a proof output.

## Dense information board

For style guides, color boards, infographics, and reference sheets, separate verified structured content from image generation. Define the grid, panel titles, exact short labels, and data authority first. Generated diagrams are visual drafts; verify numbers, labels, arrows, and claims before delivery.

## Exact text made from physical objects

Record the literal string, capitalization, spacing, and line breaks. Use a simple background, orthographic/top-down composition when suitable, uniform object grammar, and enough space between words. Inspect every character and rerun only the text/layout layer when possible.
