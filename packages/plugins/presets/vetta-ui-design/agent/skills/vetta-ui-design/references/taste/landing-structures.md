# Landing structures

Read when the product type is `landing`. Pick ONE structure before writing the
frame and name it in the direction line. A named structure bundles heading
placement, body composition, dividers, button voice and imagery into one
decision, which is how two landing pages for two briefs end up as different
sites instead of the same template recoloured.

Do not default to Specimen-style editorial (numbered margin labels + huge serif)
unless the brief is editorial; do not default to Bento for everything SaaS.
When the brief is vague, choose among the first ten.

## The structures

1. **Bento Grid** — irregular grid of mixed-span tiles (features, a quote, a
   stat, a crop of the product). Hero is a fixed-height block, not full height.
   *For* many equally valid entry points. *Not for* a one-idea product.
2. **Long Document** — reads like a memo or essay: continuous prose, inline
   section heads, almost no cards. *For* considered products, manifestos of a
   founder, anything with an argument.
3. **Marquee Hero** — one oversized statement or visual owns the first screen;
   below it the page turns into a list, grid or prose. *For* a single bold idea.
4. **Stat-Led** — a very large figure paired with a worded headline that says
   what it means; sections each anchored by a supporting number or chart. *Only*
   with real numbers from the user.
5. **Workbench** — the product UI in use is the main content: a guided tour of
   real screens with short annotations. *For* tools where seeing is believing.
6. **Conversational FAQ** — bold questions, short honest answers, the page as an
   interview. *For* products that need explaining or trust.
7. **Manifesto** — polemical large type, declaration first, product second.
   *For* studios, movements, opinionated tools.
8. **Photographic** — one large image per fold, text as small annotation. *For*
   physical products, places, food, fashion — with real imagery in `assets/`.
9. **Quote-Led** — the hero is a customer's pull-quote with attribution. *For*
   products whose proof is people — with real quotes.
10. **Specimen** — numbered margin labels, huge serif, asymmetric spans,
    hairlines, typographic CTA. *For* type, design and editorial brands only.
11. **Catalogue** — a uniform grid of variations of one thing (SKUs, palettes,
    templates). *For* inventory as the pitch.
12. **Letter** — first person, opens with a greeting, no buttons above the fold.
    *For* small teams, launches, personal products.
13. **Index-First** — the page is a list of links; no hero. *For* hubs, docs roots,
    personal sites.
14. **Narrative Workflow** — numbered stages of how the product is used over time.
    *For* processes and multi-step products.
15. **Split Studio** — every block is a diptych, text one side, proof the other,
    alternating sides down the page.
16. **Feature Stack** — a pinned left column of labels, a right column of product
    detail per label. *For* deep single products.
17. **Type Specimen** — the typeface itself is the design. *For* foundries and
    design systems.
18. **Portfolio Grid** — filterable project cards. *For* studios and designers.
19. **Map / Diagram** — one large spatial diagram organises the page (flow,
    floor plan, system map). *For* infrastructure, logistics, spaces.
20. **Ecosystem Index** — featured / latest / by category surfaces. *For*
    marketplaces and communities.
21. **Component Playground** — live preview + copyable snippet blocks. *For*
    UI kits and developer libraries.

## Chrome that fits the structure

- **Nav:** a masthead (large centred wordmark, date/issue row, double rule) for
  editorial; a content-sized floating pill detached from the edges for product
  sites; wordmark + two links only when there are two destinations; a side rail
  for long documents; a slim top bar with a ⌘K search for developer products.
- **Footer:** a closing statement sentence; a single inline line (wordmark ·
  tagline · credit); a dense colophon for editorial; a letter-style sign-off for
  personal brands. Link columns only for a genuine hub.

## The hero

- As tall as its content. The headline, a lede of about two lines and the primary
  action all fit in the first ~800 px of a 1440-wide frame.
- Bias it: headline left with the visual right, or headline across and the lede
  offset — not every element on one centre line.
- A number is never the only words in a hero; pair it with a worded headline.
- A product visual is a real screen built as components from this design (or an
  image in `assets/`), not a drawn browser window.

## If it is a SaaS page

What should be present (not a fixed order, and the structure decides how each
looks): hero · proof (logos or a real quote) · features · one testimonial block
with name, role and company · pricing with actual prices · FAQ · one closing
action. Skip what the brief does not support; a bakery has no pricing tiers.
