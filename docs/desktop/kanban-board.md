# 看板（Kanban）功能介绍

> 系统插件 `kanban`，随 Vetta Desktop 发布。侧边栏「更多」→「看板」进入，也可以把它 pin 到左上方常驻。

## 它解决什么问题

对话一多就没人管得住。同一个项目里开了七八个会话，跨项目又有另一批，过两天你已经想不起来「那个改登录页的需求」当初开在哪个会话、做完没有。真正丢的不是记录，是**全局视角**。

看板给你一块总览：所有需求横着摆在三条泳道上，一眼看清什么还在打磨、什么正在跑、什么等你验收。发任务也不必先找一个会话进去——在看板顶部敲一行就行。

## 三条泳道

```text
┌──────────────┐   ┌──────────────┐   ┌──────────────┐
│    灵感池     │──▶│   正在处理    │──▶│    待检查     │
│ 草稿 / 待认领 │   │  ≤ 并发上限   │   │  等你验收     │
└──────────────┘   └──────────────┘   └──────────────┘
```

### 灵感池

想到什么就往里塞，不用一次写清楚。每条需求有两个状态：

| 状态 | 含义 | Agent 行为 |
| --- | --- | --- |
| **草稿** | 你还在打磨 | **不碰**。这是草稿状态存在的全部意义——一个明确的「别动它」信号 |
| **待认领** | 需求说清楚了，可以开工 | 可以自行认领 |

点卡片上的状态标签就能在两者之间切换。新加的需求默认是草稿。

### 正在处理

从灵感池拉过来，或者直接在这条泳道里手动添加。每张卡片背后是一个**真实会话**——点卡片就跳进那个对话页，可以随时接管、追问、纠偏。

卡片上实时显示状态：

| 标记 | 含义 |
| --- | --- |
| **已派单** | 会话已建立，还没开始跑 |
| **运行中**（脉冲点） | Agent 正在这条会话里干活 |
| **等待中** | 会话空闲——通常是 Agent 停下来等你，或这一轮已经结束 |
| **失败** | 派单出错，卡片上会显示原因 |

### 待检查

Agent 做完就把卡片推到这里，并附一段**交付说明**：做了什么、有哪些已知风险、什么没覆盖。这是需求的交付区，每张卡有两个动作：

- **验收通过** → 卡片归档。板面保持干净，但交付历史不蒸发——右上角「已归档」随时回看、恢复或删除。
- **打回** → 写一段反馈（哪里不对、期望什么），卡片退回「正在处理」，反馈**发往原会话**——Agent 带着完整上下文修正，不用从头理解需求。修完再次提交到「待检查」。

## 发布器：与 AI 输入栏同款

看板底部悬浮着一个**与会话页 AI 输入栏同款的胶囊输入框**——同样的卡片形态、focus 光晕和快捷键肌肉记忆，因为看板本身就是一个对话入口：

- **回车** → 记入灵感池（默认草稿，先记下来再打磨）
- **⌘回车** → 标为待认领并**立即派发**，跳过打磨直接开工（无名额时禁用）
- **Shift+回车** → 换行写需求正文（首行是标题，其余是正文）

输入框下沿可以选目标项目、点按循环优先级。顶部工具带还有：搜索（按标题/正文/标签过滤三条泳道）、并发步进器（带名额用量环）、归档回看、详细新建。

## Agent 自己派单

看板不替 Agent 排期。哪条先做、能不能并行、要不要等前一条做完，全由 Agent 在对话里自己判断；看板只负责**给它准确的板面**并在它越界时**明确拒绝**。（想让看板自己派单、不用先开口，见下面的「自动认领」。）

四个工具：

| 工具 | 作用 |
| --- | --- |
| `kanban_list_tasks` | 读板面快照：待认领项（含优先级与阻塞情况）、在跑的任务、待检查的交付、还剩几个并发名额 |
| `kanban_add_task` | 往灵感池加需求（默认落草稿） |
| `kanban_claim_task` | 认领一条待认领需求：建会话、卡片进「正在处理」、需求正文作为首轮 prompt 发出去 |
| `kanban_submit_task` | 把卡片提交到「待检查」，交还并发名额 |

被拒绝时理由是**可执行的**，Agent 据此决定等还是换：

- `wip-full` — 名额满了，先等已有任务交付
- `blocked` — 依赖的卡片还没进「待检查」，先做依赖
- `draft` — 还是草稿，别碰

所以你可以直接跟 Agent 说「看一下看板，把能做的都做了」，它会自己读板、按优先级挑、在名额允许时并行开好几条，做完一条交一条、再接下一条。

## 自动认领

默认**关闭**。关着的时候，「待认领」只是解除了 Agent 的禁令，本身不会让任何任务开跑——要么你手动派发，要么你在某个会话里让 Agent 读板认领。

页面右上角的「自动认领」按钮打开后，看板自己盯着灵感池：只要有卡片是「待认领」、依赖已满足、并发还有名额、目标项目可解析，看板就直接建会话把它派出去（卡片标记为 Agent 认领）。新卡片标成待认领、有任务交付腾出名额、上调并发上限，都会立刻触发下一轮。

几个边界：

- 一次只派一条，派完再看名额，所以并发上限不会被绕过。
- 草稿一律不碰，和手动派单是同一道闸门。
- 没有可用目标项目、或建会话失败的卡片会被**跳过**而不是反复重试；你编辑那张卡（比如补上项目）之后它重新参与。
- 开关是持久化的：开着自动认领关掉应用，下次打开会把这期间攒下的待认领卡片接着派。所以它会在你不看着的时候真的花钱跑任务——这也是它默认关闭的原因。

## 并发上限

页面右上角设置，默认 **5**。

这个数只约束「正在处理」泳道上**同时未交付**的任务数（已派单 / 运行中 / 等待中都算占用，已交付和失败不算）。它**不影响 Vetta 其它任何地方的并发** —— 批量任务、自动化、你手动开的会话都不受它管。

WIP 上限不是性能开关，是**注意力开关**：同时跑十条你根本来不及验收，卡片会堆在「待检查」里发霉。三到五条通常是能真正跟住的量。

## 依赖顺序

编辑需求时可以勾选它**依赖**哪些卡片。被依赖的卡片进入「待检查」之前，这条不会被派发——Agent 想认领会被 `blocked` 挡回去，卡片上也会直接显示「等待：xxx」。

用来表达真实的先后关系，比如「先把数据模型定下来，再做接口」。删除一张卡片时，其它卡片对它的依赖会被自动清掉，不会留下永远解不开的锁。

## 其它

- **拖拽**：卡片可以在泳道之间、泳道内部任意拖动。从灵感池拖进「正在处理」等价于手动派单，同样走并发闸门。
- **优先级 / 标签 / 目标项目**：每张卡片可以指定优先级（低/中/高）、标签、以及在哪个项目里执行；不指定则用看板默认项目。
- **中断**：运行中的卡片可以直接在看板上打断当前回合。
- **跨重启**：看板存在插件私有存储里。重启后「运行中」会降级为「等待中」——会话不跨进程存活，由你决定继续还是重派，而不是显示一个其实已经没在跑的任务。
