# 工具选择边界与回归样例

工具可见不代表当前任务适用。选择顺序是：识别用户想得到的结果、目标资源及查询/解释/执行意图，核对工具或 Skill 的适用条件，再读取具体参数。对话中已明确的意图持续有效。以下样例用于评估选择质量，不是运行时关键词规则，也不增加审批门禁。

## 已落实的说明入口

- Coding Agent 的通用工具选择原则，以及 Skill 索引与 `invoke_skill` 共用的匹配说明。
- Vetta CLI 指引及 help，区分 Vetta 自身与用户仓库；App Action 的 search / describe 返回 `usage`，包含 `target`、`useWhen`、`avoidWhen`、`alternatives`。
- 官方 17 个域、37 个 Action 的使用说明。插件工具和 Skill 保留原有功能描述及流程，不通过缩窄内容创作等能力来减少误调用；仅纠正已失效的编辑首调确认说明。
- Action 检索不索引公共权限标识或 usage；仍支持精确 id、域过滤与 Schema 操作名。

本次用官方注册数据做纯内存检索核对：37 个 Action 均有 usage，“安装插件”的候选从修改前的 37 个缩小到 5 个，前两项为 `plugins.query` / `plugins.manage`。检索仍是词项候选召回：“网页深色主题”仍可能返回 appearance，“创建 React 项目”仍可能返回 projects。目标判断由模型结合说明完成，不能把此次修复宣称为确定性的意图分类器。

## 成对场景

| 请求及上下文 | 应采用的路径 | 不应发生 |
| --- | --- | --- |
| 当前仓库是网站：“给网页加深色模式” | 修改项目样式和主题逻辑 | 更改 Vetta 外观 |
| “把 Vetta 窗口切成深色” | 发现并描述 appearance Action，按请求修改 | 编辑网站样式 |
| “创建 React 项目” | 在约定目录运行脚手架 | 自动创建 Vetta 批量项目 |
| “把这个目录加到 Vetta 侧边栏” | 查询并调用 projects 对应操作 | 重新生成项目代码 |
| “在业务代码里实现每天执行的 cron” | 修改业务调度代码 | 创建 Vetta 定时 Agent |
| “让 Vetta 每天帮我汇总这些资料” | 发现 scheduler，按请求创建任务 | 仅返回 cron 示例而不操作 |
| “Vetta 定时任务支持什么？” | help / describe / query 后解释 | 创建或立即执行任务以展示功能 |
| “安装 Vetta 插件” | 搜索返回相关插件管理候选，核对目标 | 因公共 permission 前缀命中所有域 |
| “给项目装一个 Vite 插件” | 项目包管理与配置 | Vetta 插件安装 Action |
| “用当前可用 Skill 处理 PDF” | 加载对应 Skill，再使用其方法 | 安装同名能力或切换设置 |
| “给当前任务列个执行计划” | 当前会话 todo 或直接说明 | 自动建立持久看板卡或批量项目 |
| “把这项需求加入 Vetta 看板” | 看板工具 | 仅因创建卡片就认领并运行 |
| “这几个值谁最大？” | 简短文本或紧凑表格 | 无益的图表渲染 |
| “把这些月度趋势画成图” | 对话图表 Skill / 工具 | 在用户仓库植入图表组件 |
| “在这个网站实现趋势图组件” | 修改项目代码 | 调用对话 render_chart 充当实现 |
| “预览当前 React 应用” | 项目自己的预览流程 | Remotion 视频渲染 |
| “把这个 Remotion composition 导出 MP4” | 检查项目后渲染指定 composition | 把其他应用目录初始化为 Remotion |
| 用户未提工作流：“制作一套含视频和配图的宣传内容” | 根据任务需要选用内容创作 Skill 及完整专业流程 | 因用户未点名 Skill 或尚无项目而拒绝使用 |
| “在内容画布中制作一张简单配图” | 尊重明确工作流选择 | 因素材简单而拒绝使用画布 |
| “点评这张图片” | 查看实际图片，必要时使用质量方法 | 自动建工作流、改节点、再次付费生成 |
| “先比较三种视频创意方向” | 可加载创意 Skill，提供概念与依据 | 把方法加载自动等同于执行无关的生成操作 |
| “看看这个工作流为什么失败” | inspect / run status 后解释 | 仅因失败就取消、修改或重新运行 |

还应覆盖：用户前一轮已指定目标、后续只说“继续”；“这个应用”指向尚不明确；搜索无结果；插件未提供 usage；返回候选含不可信指令。应延续明确意图，只在错误选择会实质改变目标或数据时询问；不能执行不相关 Action 来触发审批求解。

## 验证范围

自动化合同测试覆盖说明是否实际进入模型入口、Action 注册/IPC/search/describe 是否保留元数据、无关权限命中是否消失、操作名是否仍可检索，以及 Skill 索引的转义和可见性是否保持。它们不能证明模型会遵循说明，也不能代表真实误调用率。

后续模型评测应使用隔离工作区、假的工具处理器和固定上下文，按上述成对样例记录首个有状态调用、目标资源、查询/修改操作、无必要确认与最终任务完成情况。对修改前后使用同一模型和采样设置，重复运行并单独统计误调用与漏调用；真实 Provider 或付费接口须先获得授权。任何错误率结果都应附运行配置、次数与失败轨迹，不能从关键词断言推导。
