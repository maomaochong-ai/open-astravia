# ADR-0159：模型选择器改为三栏面板

## 状态

已接受。

## 背景

模型选择器原先是「搜索框 + 按服务商分组的一条长列表」：几十个模型还能滚，上百个就
只能靠搜索，而搜索要求用户先记得模型名。参照实现在 0.5.73 把它改成了三栏
（服务商｜模型｜思考强度）并加了收藏。

本项目的模型数量来自用户自己配置的服务商，重度用户往往接三五个服务商、
每个几十个模型——正是单列长列表最难受的区间。同时「思考强度」原本塞在列表上方的一个
子菜单里，选完模型还要再点一次子菜单才能调档位，两步操作在两个不同的浮层里。

## 决策

### 1. 三栏结构

- 第一栏：服务商列表（**收藏**作为第一格，不是独立区域——收藏跨服务商，放进服务商栏
  才能与「当前看哪个服务商」共用一个选中位）；
- 第二栏：该服务商的模型列表，或搜索时全量命中（行尾标注来源服务商）；
- 第三栏：思考强度，**没有档位时整栏不渲染**（不占宽度、不留空列）。

搜索跨服务商平铺：用户此刻要的是「哪个模型叫这个名字」，而不是「这个服务商有没有它」。

### 2. 容器从 DropdownMenu 改为 Popover

内容已经是一个复合面板：服务商按钮列、可滚动的模型列表、思考档位列、搜索框、每行一个
星标按钮。放在 `DropdownMenuContent`（`role="menu"`）里有两个问题：

- ARIA 上不合法——菜单只能包含 `menuitem`；
- Radix 的方向键导航会把焦点困在「菜单项」之间，而面板里真正的交互是 Tab 在按钮之间走。

Popover 的语义是「带交互的附属面板」，正好对应它，且同样支持 Esc 与点击外部关闭。

顺带给 `PopoverContent` 补了 `portalContainer`（与 `DropdownMenuContent` 已有的同名
参数一致）：面板放在抽屉/对话框里时要挂到那些容器上，否则会渲染到 body、脱离父级滚动
边界。

### 3. 选择后的关闭行为

- 没有思考档位：选中即关闭（完成了一件完整的事）；
- 有思考档位：保持打开，让用户接着在右栏选强度。这是参照实现已有的行为，本次沿用。

### 4. 收藏只存本机

键 `astravia-model-favorites`，只存模型 key。收藏是「我这台机器常用的模型」，
跨设备同步反而会让别人的目录影响自己的菜单。存储不可用时退化为会话内有效。

### 5. 长列表虚拟滚动

超过 60 行才窗口化，行高固定（28px），用滚动位移直接算可见区间，不逐行测量。
几十行时窗口化的收益抵不上它带来的焦点与滚动锚点问题。

## 备选方案

- **保留单列，只加收藏与分组折叠**：成本最低，但没有解决「换服务商等于滚动」这件事，
  而这是模型多时最常做的动作。
- **保留 DropdownMenu，把三栏塞进菜单项**：ARIA 不合法，且星标按钮与搜索框都不是菜单项，
  键盘导航会失效。
- **弹出独立对话框**：模型选择是高频轻量操作，弹窗会打断输入流的上下文。

## 后果

- 正面：找模型从「滚动 + 读」变成「点 + 读」；思考档位与模型在同一面板，少一层浮层；
  常用模型不必每次现找。面板宽度从 16rem 放到 34rem，三栏才排得开。
- 代价：面板更宽，窄窗口下会退化为「两栏 + 收缩」，需要 `max-w` 兜底（已用
  `min(34rem, 100vw - 2rem)`）；`PopoverContent` 多了一个参数要维护。
- 已知限制：面板的视觉（三栏在 320px 窄屏下的排布）**未实机验证**——本机 dev 壳没有
  开远程调试端口，无法截图核对；纯逻辑与组件行为有 22 条用例覆盖。
