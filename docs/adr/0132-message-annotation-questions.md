# ADR-0132：消息旁注问答独立于主会话

## 状态

已接受。

## 背景

用户阅读消息时需要临时解释和探索，并可能稍后回看；常规 fork 会创建并打开另一个会话，成本过高。仅在界面折叠问答仍会让旁支内容进入主会话的模型上下文。

## 决策

1. Desktop 在普通会话上组合旁注能力。选中文字的右键菜单、消息更多菜单负责发起；保存过的消息在悬停或键盘焦点时显示批注标记。消息更多菜单和批注面板提供当前会话批注的集中搜索，不在会话顶部增加入口。非模态面板关闭不会取消正在进行的回答。
2. 旁注通过主进程独立调用会话当前模型，不启用工具、不创建 Runtime Session、不写主历史或发送队列。历史按角色标注为引用资料，不回放主 Agent 的执行指令。追问保留旁注自身的问答。
3. 首次提问冻结截至来源消息的文字上下文；合并的助手气泡包含其工具循环直到下一条用户消息。若此前已有压缩，使用最近压缩摘要及后续记录，避免重新展开已压缩历史。图片只保留缺省说明，不读取图片或工作区文件。主会话后续更新、切换分支不改变已保存快照。
4. 每个会话使用 `<sessionPath>.annotations.json`，文档版本为 1。路径由 Runtime 根据 runtimeId 解析，Renderer 不能传入存储路径。主进程校验 IPC 和存储结构，原子串行写入保证同一会话多个旁注不相互覆盖。来源、引用和上下文一经创建不可改变。
5. 发起前保存问题，结束、失败或取消时保存回答；中间流式状态由主进程持有并定向投影，不随面板卸载取消。重启后未完成记录显示为中断，可重新回答；重试替换失败轮次而不重复追加问题。删除主会话同时清理旁注。
6. 原消息不在当前分支时仍可从批注列表阅读快照。旁注不会出现在普通会话列表，也不会自动加入主会话上下文。

## 备选方案

- 隐藏普通 fork：需要对会话列表、运行状态和会话切换附加例外规则；不采用。
- 在主历史里追加折叠消息：展示折叠不等于上下文隔离；不采用。
- 只存 Renderer 临时状态：关闭、虚拟列表卸载或重启后无法找回；不采用。

## 兼容与验证

旧会话和 Runtime 协议不迁移；缺少旁注文件等同于没有旁注。新增 Desktop IPC 和可选的消息选区菜单 children 保持既有调用兼容。业务状态位于 Desktop connector；输入、历史列表和问答布局叶子在 theme-ui，复用已有 Popover、DropdownMenu 和 Markdown 能力。

验证涵盖提问、追问、关闭重开、选区菜单、搜索、主草稿保持、上下文截止、并发写入、取消、重试、损坏存储、IPC 校验与订阅清理。真实 Provider 和用户运行中的 Desktop 不作为自动化测试环境。
