# ADR-0157：与参照实现 0.5.72–0.5.81 的全量对齐登记

## 状态

已接受，并由本记录替代此前「按主题取舍」版本。**判定基线是全量对齐**：本项目的定位
是基于参照实现的二次开发，因此参照实现在 0.5.72→0.5.81 之间落地的每一个行为变更
都属于对齐范围；只有**依赖参照实现独有品牌资产**（本机代理 Magpie、像素白鼬应用图标、
Splash 引导面板）的条目需要产品决策，因为采纳它们等于采用对方的品牌与产品身份。

## 背景

本项目从参照实现的代码线演进而来，两条线在 0.5.72 之后独立推进。此前一轮把
0.5.72→0.5.81 的改动按领域归并后「挑几条做、其余说明不做」——那个判断与本项目
二次开发的定位不符：凡参照实现改过的行为，用户在两边的预期应当一致，不能因为
「本项目结构不同」就搁置。

本记录改为逐条登记：参照实现这九个版本共 248 个非合并提交，其中
**213 条产生可观察行为**（另 35 条为版本号推进、发布说明与测试），全部进入下方
登记表，一条不漏。

## 决策

### 1. 登记与状态词汇

| 状态 | 含义 |
| --- | --- |
| 已对齐 | 本项目达到同一可观察行为；实现方式可以更彻底（例如会话历史解析本项目另加了异步与线程分流） |
| 待对齐 | 尚未做。**这是默认状态**，未逐项确认的条目必须先补证据再改代码，不得按提交标题猜测实现 |
| 需产品决策 | 条目本身是参照实现的品牌资产，采纳与否是产品身份决策，不是技术对齐 |

所有条目从「待对齐」起步，每完成一条就地改为「已对齐（批次）」并注明验证方式；
不预先把未核实的东西写成已完成。

能力 + 1 条 logo）、像素应用图标与 Dock 图标 7 条、Splash 引导面板 1 条（`hl6i` 外阴影）。

复核后有两个修正：

- **`hl6i`（Splash 外阴影）不是品牌问题**，它已随上游最终态（共享面板皮肤）一致，改为「已对齐」，
  不再进 B14；
- **Dock 默认图标（`izqa`）与 `e7nz` 的默认图标部分可用本仓自有素材完成**，
  不必等像素白鼬素材，可以提前做。

因此真正需要品牌素材的只有 12 条：像素图标 7 条 + Magpie 5 条。

它们共同的特点是**采纳即采用对方的品牌身份**，与功能对齐无关——当时默认不采纳，等产品确认。
本轮产品方已确认**采纳**，决策与实施拆解见 [ADR-0172](0172-adopt-reference-brand-identity.md)；

## 后果

- 正面：0.5.72→0.5.81 的每个行为变更都有唯一归属与批次，不再依赖记忆挑拣；
  二次开发定位下「结构不同所以不做」不再是理由，形态差异按对齐处理。
- 代价：B2、B3 两条需要新的公共合同（顶栏动作贡献点、模型菜单结构），必须各自
  另立 ADR 并接受插件 SDK 兼容性检查；B5 的密码登录要动 ssh-transport。
- 已知限制：参照实现同期 35 条版本号/发布说明/测试提交不入表；其中 12 条是同一
  功能的中间迭代（顶栏、模型菜单各一批），已分别归并进 B2、B3 的范围描述。
