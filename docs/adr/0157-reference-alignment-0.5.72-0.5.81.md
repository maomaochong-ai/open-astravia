# ADR-0157：与参照实现 0.5.72–0.5.81 的全量对齐登记

## 状态

已接受，并由本记录替代此前「按主题取舍」版本。**判定基线是全量对齐**：本项目的定位
是基于参照实现的二次开发，因此参照实现在 0.5.72→0.5.81 之间落地的每一个行为变更
都属于对齐范围；只有**依赖参照实现独有品牌资产**（本机代理 Magpie、像素白鼬应用图标、
Splash 引导面板）的条目需要产品决策，因为采纳它们等于采用对方的品牌与产品身份。

## 背景

本项目从参照实现的代码线演进而来，两条线在 0.5.72 之后独立推进。此前一轮把
0.5.72→0.5.81 的改动按领域归并后「挑几条做、其余说明不做」——那个判断与本项目
二次开发的定位不符：凡参照实现改过的行为，用户在两边的预期应当一致，不能因为
「本项目结构不同」就搁置。

本记录改为逐条登记：参照实现这九个版本共 248 个非合并提交，其中
**213 条产生可观察行为**（另 35 条为版本号推进、发布说明与测试），全部进入下方
登记表，一条不漏。

## 决策

### 1. 登记与状态词汇

| 状态 | 含义 |
| --- | --- |
| 已对齐 | 本项目达到同一可观察行为；实现方式可以更彻底（例如会话历史解析本项目另加了异步与线程分流） |
| 待对齐 | 尚未做。**这是默认状态**，未逐项确认的条目必须先补证据再改代码，不得按提交标题猜测实现 |
| 需产品决策 | 条目本身是参照实现的品牌资产，采纳与否是产品身份决策，不是技术对齐 |

所有条目从「待对齐」起步，每完成一条就地改为「已对齐（批次）」并注明验证方式；
不预先把未核实的东西写成已完成。

### 2. 分批顺序

按「改动面小 → 大、无新合同 → 有新合同」推进，每批独立可验证、可回滚：

| 批次 | 范围 | 条数 | 前置条件 |
| --- | --- | --- | --- |
| B1 | 纯样式与文案修正（换行、底色层次、间距、简称） | 约 40 | 无 |
| B2 | 会话页顶栏（按钮组 + 顶栏动作贡献点 + 窄窗收纳） | 12 | 需新组件 API 与插件贡献点，属公共合同，单独 ADR |
| B3 | 模型选择菜单（三栏、收藏、虚拟滚动、去 motion） | 12 | 需重排输入栏菜单结构 |
| B4 | 侧栏「管理会话」面板（含 >80 条虚拟列表） | 5 | 能力缺口，新增面板 |
| B5 | 设置与外观（界面大小滑块、默认模型选择器、SSH 表单拆分与密码登录） | 14 | 密码登录需 ssh-transport 支持 |
| B6 | 能力页、项目页、插件与 MCP（sse 传输、`.mcp.json` 并入、顶栏动作、从外部应用打开） | 约 30 | 需协议与 SDK 变更 |
| B7 | 更新器对话框与运行时性能（图片解码、prompt cache 指纹） | 约 12 | 需样本与症状比对 |

### 3. 第一批（B1）

移植方式说明：这一批是从上游对应提交的 diff 里取改动块，在本仓同名文件的同一位置
做等值替换，不是按标题重写。过程中有两处必须人工修正：

1. 上游同时给 `theme-ui` 的 exports 补了「管理会话视图」条目，而本仓还没有这个
   组件——机械套用会留下指向不存在文件的导出，已回退，随 B4 一起做；
2. 上游 README 里写的是它自己的包名，套用后会把对方的包名带进本仓文档，已改回本仓
   包名。

### 5. 待对齐但依赖 B3 的 chat 条目

模型菜单相关的 12 条（三栏、收藏、虚拟滚动、去 motion、玻璃材质、思考强度栏等）
都以三栏结构为前提，本仓仍是单列表结构，因此整组随 B3 一起做；单独套用其中任何一条
都会在没有对应结构的位置改动，属于假对齐。

| 条目 | 落地 |
| --- | --- |
| 命令面板底部动作条改用方形按钮组 | `CommandPanelView` 的动作条改为 `<ButtonGroup blur={false} shape="square">`，不再是一排各自成形的独立小按钮 |

散按钮位置（自动化详情面板等），按后续批次处理。

### 9. 需产品决策的 11 条

Magpie 本机代理（4 条）、像素白鼬应用图标与 Dock 图标（4 条）、Splash 引导面板（3 条）。
它们的共同点是**采纳即采用对方的品牌身份**，与功能对齐无关。默认不采纳，等产品确认。
