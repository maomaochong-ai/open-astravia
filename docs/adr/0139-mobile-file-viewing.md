# ADR-0139：手机查看电脑上的文件

## 状态

已接受（在 ADR-0128 的协议 v2 上增量扩展，启用握手里预留的 `fileRead` 能力位）

## 背景

手机已经能镜像电脑上的会话，但 Agent 产出的文件看不到：回复里的 `[报告](./report.html)` 指向电脑上的路径，点了没有反应；也没有办法浏览会话的工作目录。

有几件事让「把路径交给手机」行不通：

- 相对路径要按会话自己的运行目录解析。「对话」里每个会话的运行目录是 `~/.vetta/conversation/<sessionId>/`，手机并不知道它。ADR-0128 刻意用会话文件路径的哈希作会话 id，不向手机暴露路径。
- 桌面点链接时的解析规则（`file://`、Windows 路径、SSH 项目把远端绝对路径换回项目 URI）已经有一份实现，手机再写一遍迟早走样，Android 还得写第三遍。
- 链接不一定落在会话目录里，Agent 常把产物写到 `~/Desktop`。
- 单个加密帧的明文约 1 MB，中继跑在免费额度上。

## 决策

### 寻址：路径字符串，由电脑解析

新增 `file.list`、`file.stat`、`file.read` 三个请求，都挂在会话上（请求带 `sessionId`），都用一个**路径字符串**指代文件，由电脑按会话运行目录解析，与桌面点链接走同一套规则。手机从不拼绝对路径：

- 点链接时，手机把链接原文原样交给 `file.stat`。
- 电脑返回的每个路径都是**规范形式**：会话运行目录之内给相对路径（根目录是空串），用户主目录之下给 `~/…`，其余给绝对路径。手机拿它继续 `file.read` 或 `file.list`。

这样会话的运行目录不会出现在协议里；桌面重启后路径仍然有效，手机可以按「会话 + 路径 + 修改时间 + 大小」缓存。只有既不在会话目录也不在主目录下的文件会以绝对路径出现，这类路径本来就已经出现在 Agent 的回复里。

没有采用电脑签发的不透明引用 id：它要在电脑上维护一张有上限的映射表，电脑重启后全部失效，而路径字符串已经足够。

### 读取边界（远程可读范围）

与桌面自身的两档边界同源：

- `file.list` 只在会话运行目录之内。
- `file.stat` / `file.read` 放宽到桌面预览的范围：已放行的目录，或用户主目录下任意位置。
- SSH 项目的会话沿用桌面对远程路径的边界：只在项目的远程白名单内。`~` 与项目外的绝对路径一律拒绝。

在此之上，手机还受一份**敏感位置黑名单**约束，桌面本机不受此限：`~/.ssh`、`~/.gnupg`、云服务凭据目录、系统钥匙串，以及 `~/.vetta` 下除会话工作区、上传目录等产物目录之外的全部内容（凭据、配置、插件数据）。本地路径同时按解析符号链接后的真实路径再判一次，防止会话目录里的符号链接指向黑名单。

不设「允许手机查看文件」的开关：已配对的手机本就能让 Agent 读任意文件，开关不缩小实际风险面；真正的防线是黑名单与逐台撤销配对。

### 传输

- `file.read` 按范围分段，每段最多 700 KB，第一段之后手机带上第一段返回的修改时间，文件在读取途中被改写时电脑返回 `file_changed`，手机从头再读。
- 单个文件上限 10 MB，与桌面预览一致，局域网和中继相同，超过返回 `too_large`。
- 图片由电脑先缩到长边 2048 像素、转成 JPEG 再计入大小，所以大照片也能看。
- 电脑对最近读取的几份内容做短时缓存，分段读取时不必每段都重新读文件、重新缩图（SSH 项目尤其需要）。

### 错误码与兼容

新增错误码 `forbidden`（超出可读范围或命中黑名单）、`too_large`、`file_changed`。只有文件请求会返回它们。

电脑在 `device.status`（每次手机连上都会推送）里带 `fileRead: true`，握手的 `hello` 也声明同名能力位。手机只能以 `device.status` 为准：它是握手的发起方，收到的 `hello_ack` 不含对端能力。旧版电脑遇到不认识的请求会断开连接，所以手机只在 `device.status` 声明了 `fileRead` 时才发这三个请求，否则把入口置灰并提示升级电脑端。

## 后果

- 手机端不需要知道会话的运行目录，Android 以后接入时也不必移植链接解析规则。
- 同一个文件在电脑上能预览、在手机上不一定能：黑名单只约束手机。
- HTML 页面引用的相对资源（同目录的 CSS、图片）这一期不会加载；需要时可让 WebView 通过自定义 scheme 按需回电脑取，不改变本决策的寻址方式。
- 不做文件变化的实时推送；手机在一轮结束后自行刷新，电脑不为手机挂文件监听。
- `fileWrite` 仍不声明。
