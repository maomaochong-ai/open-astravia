# ADR-0124：文件列表显示策略与插件图标主题分离

## 状态

Accepted

## 背景

Desktop 主进程读取目录时曾无条件丢弃所有以 `.` 开头的条目。这个决定同时混合了文件系统读取、用户显示偏好和平台垃圾文件过滤，导致 `.env`、`.github` 等正常项目文件无法从活动面板访问，Renderer 也没有机会让用户切换行为。

插件文件装饰只有 `icon`、`badge` 和 `tooltip`，且由同一个高优先级 provider 整体胜出。若直接在这条路径上继续增加文件类型图标，用户选择的图标主题会与 Git、诊断等动态状态互相覆盖；若开放任意 className/CSS，又会破坏主题一致性、可访问性和虚拟列表布局。

## 决策

1. 主进程的直接目录读取返回真实目录条目，不再按点前缀或平台文件名做展示过滤。内部会话 UUID 目录等既有安全边界保持不变。
2. 文件列表显示策略由 Renderer 持有，并以带 `schemaVersion` 的本机配置持久化；配置使用 Toolkit 的统一迁移入口。默认显示点文件，仅排除 `.DS_Store`、`Thumbs.db` 与 `desktop.ini`，用户可切换隐藏点文件并编辑工作区相对 glob。
3. 过滤同时作用于渲染、键盘导航、选择和 `reveal`，且只接受当前工作区内路径；被隐藏的已选项会从选择中移除。
4. 动态状态装饰与文件图标主题是两个独立解析面。装饰提供徽标、提示、语义色、淡化、删除线和父目录聚合；图标主题提供文件名、扩展名、文件夹名、展开态及色彩模式关联。主题图标与状态装饰可以同时生效。
5. 图标主题由用户显式选择。主题所属插件停用或卸载时回退到内置图标，但保留选择值，以便插件恢复后自动恢复主题。
6. 插件通过 `onDidChangeDecorations` 通知状态失效；事件可携带未展开后代的元数据，使父目录无需先读取或展开即可聚合状态。它不触发文件系统刷新。
7. 插件输入在宿主首次边界进行结构校验。装饰只能使用宿主定义的语义色，图标只能来自声明式定义；不开放任意文件行 CSS、字体、布局、排序或交互区覆盖。
8. 新合同以 Plugin API 2.7.0 暴露；旧 `icon` / `badge` / `tooltip` provider 继续兼容。

## 备选方案

| 方案 | 未采纳原因 |
| --- | --- |
| 主进程增加 `showHidden` 参数并继续过滤 | 显示偏好会进入 IPC 和文件系统服务，且每次切换都要重新读取目录；排除规则仍会散落在两层 |
| 所有文件永远显示，不提供设置 | 无法满足希望隐藏点文件、依赖目录或生成文件的用户，也无法替代原有平台垃圾文件过滤 |
| 继续用 decoration provider 提供完整图标主题 | 状态与类型图标只能由一个 provider 胜出，选择主题会丢失 Git/诊断状态，优先级语义也会变得不可解释 |
| 允许插件给文件名传入 className 或 CSS | 任意样式会越过主题与可访问性边界，并可能改变虚拟行尺寸；宿主无法稳定校验或组合多个插件 |
| 状态变化统一调用 `refresh()` | 为纯视觉状态重新读取文件系统，成本高且无法表达未展开后代的父目录聚合 |

## 后果

- 直接目录读取的调用者会看到此前被隐藏的点条目和平台文件；文件列表在 Renderer 按用户偏好过滤。依赖“主进程天然隐藏”的新调用者必须自行选择合适的展示策略。
- 默认行为从隐藏所有点文件改为显示点文件，这是有意的用户可见变化；原行为可通过关闭「显示隐藏文件」恢复。
- 文件图标主题与状态装饰可独立演进，但插件需要维护快速、无副作用的同步 provider，并在状态变化时发送失效事件。
- 用户配置已建立版本边界；后续字段或语义变化必须增加显式迁移，不能静默重解释旧值。
