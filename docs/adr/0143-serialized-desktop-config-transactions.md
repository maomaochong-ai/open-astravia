# ADR-0143：Desktop Config 使用单进程串行事务更新

## 状态

已接受（补充 ADR-0140）

## 背景

`desktop-config.json` 同时承载项目、通用设置、快捷键、知识库和手机遥控等多个领域。过去各领域先读取完整快照、修改一个字段、再整份写回；两个异步操作交错时，后写入的旧快照会覆盖先完成的更新。Windows 上原子写入的 `rename` 还可能因杀毒软件、索引器或另一次写入短暂占用目标文件而返回 `EPERM`，同步重试会阻塞 Electron 主进程。

仅在远程配对模块增加重试不能消除这些结构性问题，因为其他配置调用方仍能制造同样的竞争，配置迁移回写也曾是读取路径中的隐藏写入。

## 决策

1. `desktop-config-store` 是本进程内读取、迁移和更新 `desktop-config.json` 的唯一 I/O 边界。异步操作进入同一个 FIFO 队列；一次失败不得阻断后续操作。
2. 写调用方只使用 `updateDesktopConfig(updater)`。updater 在队列内接收最新的规范化配置并返回下一份配置；不再暴露接受完整旧快照的 `writeDesktopConfig`。updater 不得再次读取或写入 Desktop Config，也不应在持有队列时执行无关 I/O。
3. 写入前重新读取原始文档并保留本版本不认识的顶层字段；已知字段以 updater 结果为准，显式 `undefined` 保持删除语义。未来版本的通知子字段继续按 ADR-0140 保留，`sshHosts` 继续以 `ssh-hosts.json` 为独立事实源。
4. 异步读取也进入同一队列，因此会看到此前已提交的更新；读取触发的 schema 迁移在队列内异步落盘。`readConfigSync` 仅用于启动和必须同步回答的路径，只解析当前磁盘快照，不再回写主配置。
5. Desktop Config 使用异步原子写入。Windows 可恢复的 `EPERM`、`EACCES` 和 `EBUSY` 采用有上限的异步退避重试，避免阻塞主事件循环；同步原子写 API 保留较短重试供其他独立文件使用。

## 备选方案

- 只修改远程配对：diff 较小，但设置、项目、快捷键和迁移仍可互相覆盖或触发同类 `EPERM`。
- 保留整文件写 API，在每个调用方手工加锁：锁与事实源会分散到多个领域，新调用方容易绕过，且无法统一保护迁移回写。
- 引入跨进程文件锁：能处理两个 Desktop 进程共享同一配置，但增加锁恢复、崩溃清理和跨平台语义。本仓库已要求不要同时运行共享 `~/.vetta` 的 `dev:home` 与正式版，因此本次不扩大到跨进程协调。

## 后果

- 同一 Electron 主进程中的配置操作按最新状态串行提交，不同领域的并发更新不会再通过旧快照互相覆盖。
- 文件被 Windows 短暂占用时，主进程仍可处理事件；超过有限重试窗口后错误会正常返回，队列随后仍可继续工作。
- 调用方需要以字段更新函数表达意图；测试替身也必须执行 updater，而不是只记录一份完整配置参数。
- 配置格式和 schema 版本没有变化，无需数据迁移；旧配置仍按 ADR-0140 的迁移链读取。
- 该队列是进程内保证，不是跨进程锁。若未来允许多个 Desktop 进程共享同一配置目录，需要另行决策跨进程协调或拆分事实源。
