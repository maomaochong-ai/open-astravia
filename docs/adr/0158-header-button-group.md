# ADR-0158：顶栏按钮组与顶栏动作贡献点

## 状态

已接受，分两步实施：**第一步（本记录同期落地）** 是通用按钮组与 `SessionTopItem`
两个 UI 原语，以及会话页顶栏改用它们；**第二步** 是插件顶栏动作从命令式改为声明式
贡献点，属插件合同变更，单独评审。

## 背景

会话页右上角现在是一排各自实现的操作：活动面板开关、终端、导出、窗口置顶、插件注入
的按钮……每个按钮自己定尺寸、自己的 hover、自己的图标尺寸。这条线上有四个具体问题：

1. **视觉不成组**。同一条水平线上的按钮高度、间距、分隔线各不相同，窗口变窄时先被
   挤变形的是它们。
2. **没有收纳**。按钮数量随功能增长，窄窗口下直接溢出或被裁掉，用户找不到操作。
3. **插件无法参与**。插件只能往固定位置塞按钮，无法声明「我要一个顶栏动作」，
   于是插件作者各自实现外观，宿主也无法统一收纳。
4. **每个按钮重复实现弹层**。下拉与气泡的使用方式在每处都写一遍，样式与对齐不统一。

参照实现在这批迭代里把这四件事一起解决了：一个 `ButtonGroup` 原语、一个
`SessionTopItem`（按钮 / 下拉 / 气泡三合一）、以及声明式的顶栏动作贡献点。

## 决策

### 1. 两个 UI 原语，放在 `@astravia/ui`

- **`ButtonGroup`**：半透明胶囊，`shape: "pill" | "square"`，`blur` 可关。组成员之间用
  `before` 伪元素画 1px 分隔线，**不占布局宽度**；选中项与它的右邻项都不画线，避免
  线与选中底色连成一片。
- **`ButtonGroupItem`**：图标 / 文字 / 角标（数字、红点、任意节点）/ `active`。
  纯图标必须有 `title` 或 `aria-label`。
- **`SessionTopItem`**：在 `ButtonGroupItem` 之上三选一——普通按钮、`menuItems`（下拉）、
  `popoverContent`（气泡）。单独使用时自己包一层胶囊，放进 `ButtonGroup` 里就是组内的
  一格，由 `useInButtonGroup()` 判断，调用方不需要选两套 API。

放在 `packages/ui` 而不是 `theme-ui`：它们不依赖主题令牌以外的东西，也不属于某个
业务域；`theme-ui` 的业务视图可以直接复用。

### 2. 收纳规则：宿主决定，不交给每个按钮

窄窗口下把放不下的动作收进「更多」菜单。规则：

- 顺序固定，先按「常用度」排：面板开关 → 终端 → 导出 → 其余；
- 溢出判定用容器实测宽度 + 每组按钮宽度的累计，**不按固定数量**（不同动作宽度不同）；
- 收进菜单的项保留图标、文字、角标与选中态，点开即执行；
- 菜单里不出现已被收纳的重复项。

### 3. 第二步：插件顶栏动作改声明式（本次不实施）

现在插件用命令式接口注册按钮，宿主无法统一外观与收纳。改为声明式：

```ts
ctx.ui.registerHeaderAction({
	id: "my-action",
	label: "我的动作",
	icon: "solar--star-linear",
	badge: () => count,          // 可选，返回数字或 boolean
	onSelect: async () => { … },
});
```

宿主拿到声明后自己渲染成 `SessionTopItem`，从而天然获得外观一致、收纳与可访问性。
**本次不实施**，理由：这是插件 SDK 的公共合同变更，需要版本推进、清单权限声明与
兼容层（旧命令式接口在过渡期内必须继续可用）。按仓库规则另立记录并单独评审。

## 备选方案

- **只做样式统一（不改结构）**：把现有按钮的尺寸/间距统一即可，成本最低，但问题 2、
  3 完全没解决——窗口一窄还是溢出，插件还是各写一套。
- **用现有 `Toolbar`/`Button` 组合**：这些是表单语境的原语，没有「组内分隔线」「角标」
  「收纳」的语义，硬套会在每个调用点再写一遍。
- **收纳交给 CSS（flex-wrap 或 scroll）**：换行会破坏单行顶栏的高度，横向滚动在顶栏上
  没有可见提示（同一轮修输入栏时已经踩过这个坑）。

## 后果

- 正面：顶栏视觉成组；窄窗口有收纳而不是溢出；插件（第二步之后）自动获得一致的
  外观与收纳；下拉/气泡的样式与对齐只存在一处实现。
- 代价：新增两个公共组件，`packages/ui` 的导出面变大；顶栏从「逐个按钮摆放」变成
  「声明一组动作 + 由宿主决定收纳」，改动的调用点比单纯调样式多。
- 已知限制：第一步只覆盖会话页顶栏。项目详情页、命令面板底部动作条等其它「按钮成组」
  的位置按后续批次逐个迁移，不在本次一次改完。
