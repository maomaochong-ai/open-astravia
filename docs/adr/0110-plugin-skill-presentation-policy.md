# ADR-0110：插件 Skill 的运行时身份与产品展示分离

## 状态

已接受

## 背景

插件通过 `agent.skillPaths` 把 Skill 加入 Agent 资源图。过去宿主把“已加载”直接解释成“应在所有界面展示”，因此插件的内部编排 Skill 会同时出现在能力中心、智能体能力配置和命令选择器中；用户看到的是 `vetta-ui-design` 一类稳定内部名，也无法区分它是否应作为独立产品能力配置。

Skill 的来源识别已经能够表达普通、内置和插件提供方，但来源不是展示策略。继续根据 `source` 在各页面写条件分支，会把同一规则复制到多个入口，也无法支持插件对少数公开 Skill 的单独命名与覆盖。

## 决策

1. 在公共 Skill 合同中增加可选 `presentation`，只表达展示名、展示说明与各产品入口可见性。`provenance` 继续只回答“谁提供”，运行时加载和授权语义不变。
2. 插件清单增加 `agent.skillPresentation`：插件级规则提供默认值，`skills.<name>` 对单个稳定 Skill 名覆盖。展示文案支持既有插件 NLS 占位符。
3. 当前入口统一使用五个 surface：`abilityCatalog`、`agentConfiguration`、`commandPalette`、`skillPicker`、`pluginDetail`。入口必须通过公共解析函数判断，不能自行按插件 ID 或来源猜测。
4. 插件提供的 Skill 在没有声明时默认 `hidden`；普通用户、项目、市场与内置 Skill 默认 `visible`。插件必须显式公开真正需要用户发现或单独配置的 Skill。
5. 隐藏只影响产品界面的发现与选择。隐藏 Skill 仍进入运行时资源图，插件被选中时仍可联动其底层 Skill，既有 Agent 配置中的稳定 Skill 引用继续保留并可执行。
6. `displayName` 和 `displayDescription` 不参与运行时标识、持久化引用、权限或调用路由。宿主始终用原始 `name` 作为稳定键。

## 后果

- 插件可以把内部实现保持为实现细节，同时用少量公开 Skill 构成清晰的产品能力。
- 各展示入口共享一套解析顺序，新增入口时需要显式加入 surface 并接入同一解析器。
- 没有展示声明的旧插件 Skill 会从产品选择界面消失，但不会从运行时移除。这是有意的 fail-closed 兼容策略。
- 如果未来需要让用户覆盖插件声明，应增加独立的用户覆盖层；不能改写插件清单或复用授权字段。

## 备选方案

- **按 `source === "plugin"` 在每个页面硬编码隐藏**：无法公开单个 Skill，也会形成多份规则，拒绝。
- **把可见性写进 Skill frontmatter**：同一个 Skill 包无法表达宿主插件的产品策略和本地化目录，且会混合运行时资源与产品呈现，拒绝。
- **隐藏即不加载**：会破坏插件内部调用和既有 Agent 配置，拒绝。
