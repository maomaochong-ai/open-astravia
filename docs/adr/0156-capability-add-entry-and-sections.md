# ADR-0156：输入框第一个按钮是「添加」入口，按能力类型分区

## 状态

已接受。输入栏第一个按钮的文案与面板结构据此调整；不改任何能力的存储格式、权限模型或插件契约。

## 背景

输入栏左侧第一个按钮点开后，面板里能出现的东西已经不止一类：技能（`SkillInfo`）、连接器（`ConnectorGridItem`）、本地文件与图片、以及由插件贡献的面板/应用。但这条入口的文案一直是「技能」（`inputBar.toolbar.skills`），面板里也只有两个隐式分组：连接器宫格 + 技能列表，靠 `skillsSection` / `connectorsSection` 两个标签区分，文件入口则散在工具行右侧的「添加图片 / 附加文件引用」两个独立按钮上。

三个具体后果：

1. **命名与内容不符**。用户点「技能」，看到的是「技能 + 已接入连接器」；文件入口在另一个位置。他需要先知道这条 UI 的内部实现，才知道该点哪个。
2. **加第三、第四类能力时没有位置**。插件提供的应用、对话内已引用文件都无处安放，只能继续往工具行里塞独立按钮——工具行本来已经因为按钮过多而需要横向滚动（同轮修复）。
3. **没有类型词汇**。「技能」「连接器」「插件」「应用」在界面上交替出现，但代码里没有一处把它们统一成「可被添加到本次对话的条目」这一概念，于是每加一类都要在面板里写一段特例。

参照对象（内部设计参考）把这条入口命名为「更多操作」，面板按类型分区：文件、应用、专家、技能、连接器，每区有自己的搜索与空态。本地不需要照抄分区集合（本地没有「专家」），但需要同一套结构：**一条入口 + 按类型分区 + 每区自己的空态**。

## 决策

### 1. 词汇：CapabilityEntry 与 CapabilitySection

- `CapabilityEntry`：可被添加到当前对话的一个条目，`kind ∈ files | skills | connectors | plugins | apps`，带 `id / label / icon / disabled?`。
- `CapabilitySection`：同 `kind` 的条目集合，带 `titleKey`、`searchable`、`items`。
- `CapabilityCatalog`：有序列的区段集合，由各域现有的数据源投影而来（技能来自 `SkillInfo[]`、连接器来自 `ConnectorGridItem[]`、文件来自工具行的附件动作、插件/应用来自能力注册表）。

「能力」在这里就是这几类条目的统称，不新增存储、不新增权限边界：每个区段的数据仍然由原域提供，catalog 只做投影与排序。

### 2. 入口文案：添加

按钮 title 改为「更多操作」，tooltip 写明「可添加文件、技能、连接器、插件、应用」。用「添加」而不是「能力」作主标签，因为用户的心智是「我要往这条消息里加东西」，而「能力」是这个仓库的内部术语。

### 3. 面板：固定顺序分区，空区段不渲染

区段顺序固定为 **文件 → 技能 → 连接器 → 插件 → 应用**。理由是最常用的在前（文件与技能），最不常用的在后（插件/应用），顺序稳定使同一类条目永远出现在同一位置——比按数量多少动态排序更可预期。

- 区段为空则不渲染（不出现空标题）；
- 搜索只作用于 `searchable` 的区段（技能、连接器、插件、应用），文件区段是直接动作，不参与过滤；
- 键盘导航保持现状：一维索引只覆盖可插入的技能列表；文件动作与连接器是点击目标，不进入索引（与改造前的连接器宫格一致）。

### 4. 不改的东西

- 不改技能/连接器/插件的注册、发现与安装路径；
- 不改面板的展开形态（仍是输入卡片的形态切换，不是浮层）；
- 不改「添加图片 / 附加文件引用」两个动作的能力，只是把它们纳入 `files` 区段统一呈现。

## 备选方案

- **保留「技能」文案，只把连接器改名**：成本最低，但第三类（文件）仍然在外面，问题 2 与 3 不解决。
- **做成二级菜单（点一级出类型，点二级出条目）**：与现有键盘导航与过滤交互冲突（过滤词需要跨类型生效），且多一次点击。
- **按使用频率动态排序区段**：位置不稳定，同一类型第二次打开可能换位置，违反可预期性。

## 后果

- 正面：加新类型能力时有明确位置与词汇；入口文案与实际内容一致；文件入口回到「添加」语义下，工具行少两个按钮。
- 代价：面板纵向内容变多，需要分区标题与更紧凑的行高；`useCommandPanelModel` 要为每类提供空态文案（新增若干 i18n 键）。
- 已知限制：`apps` 区段当前只在插件声明了应用入口时出现，本地尚无独立「应用」数据源；区段按空则不渲染，因此不会显示空标题。
