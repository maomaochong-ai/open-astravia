# image budget 改判定：未看过的图永不驱逐，OOM 硬保护改由本地部署方提示词兜底

[[image budget]]（`applyImageBudget`）原本每次 LLM 调用前在整条消息历史里只留最新 N 张图（默认 2）、其余换文本占位符，目的是给显存受限的本地/开源 VL 模型的视觉 token 封顶、防 OOM。但它**纯按数量砍、不区分模型是否看过这张图**：当 agent 一轮里批量 `read` 多张图（如逐页读 PDF），即将发起的这次调用本是模型第一次看它们，却已被砍到只剩 N 张——模型对其余图收到占位符，从没真正看过却以为读过，出现「读了=没读」与对占位符的幻觉归因（误判为「文件不存在」）。本质是系统允许模型在一次调用里请求超过预算的图，再用「静默丢弃」兜底。

## 决定

把 [[image budget]] 的驱逐判定从「留最新 N 张」改为引入 [[未看过的图]] 概念：

- 以消息历史里**最后一条 assistant 消息**为界，在它之后的 toolResult/user 图片即将被模型**第一次**看到，判为「未看过」→ **无条件保留**，不受 N 约束。
- 在它之前的图模型已至少看过一次，判为「看过」→ 才进入预算，保留最新 N 张、其余换占位符。

判定是消息数组结构的纯函数、无状态、不 mutate 原始历史。配套把 N（`maxRecentImages`）在 desktop 设置页做成可调滑块（默认 2、最小 1、最大映射到 `<=0` 即禁用预算保留全部）；N 的语义收敛为「对**看过**的旧图保留多少」。

## 关键取舍

**刻意移除算法层的 OOM 硬保护。** 旧机制把批量读的图强砍到 N 防 OOM，代价是静默遗忘；新判定「未看过全保留」意味着一轮批量 read 6 张会让 6 张同时进上下文——云端模型无显存墙不受影响，但**显存受限的本地模型会 OOM**。我们接受这个分工：本地部署方在跑受限模型时用提示词软引导 agent「一张一张 read、读完先写要点再读下一张」来控制并发未看过图的数量，这是 OOM 的唯一闸门。理由是本地部署方对自己的硬件情况确定可知，能用提示词控制读图节奏；而云端用户占多数且最受「读了=没读」之害。把「防 OOM」的责任从「系统静默丢图」转移到「本地部署方显式控制读图节奏」，换来云端默认正确、语义清晰（未加载就明说未加载，不再假装读到了）。

**为何不在 read 入口硬拦截。** 曾考虑让 read 工具在超过 N 张时对超出部分返回「图片未加载，请先释放再重读」的显式文字，从源头挡住 OOM 且不静默丢图。否决：它给所有部署（含云端）强加分批读的复杂度与多轮往返开销，而 OOM 只是本地子集的问题；用提示词把这层复杂度留给真正需要的本地部署方更对称。若将来本地场景需要确定性硬拦截，可作为门控特性正向加回，不影响本 ADR 的判定改动。

## 后续若改变主意

- 若本地 OOM 靠提示词不可控，按上面口径给本地模式加 read 入口硬拦截（门控），而非回退到「静默砍未看过的图」；
- 「看过」的更强语义（要求已有引用该图的文字总结才允许驱逐）检测难做准，暂不引入，留给模型自行决定是否文字化。
