# ADR-0178：设计画廊按能力页设计语言重做（v2 原型）

## 状态

已接受，待实施。范围是 `packages/plugins/presets/astravia-ui-design` 的设计画廊
（`src/gallery/**`，约 2500 行），不改插件对外合同与画布引擎。

## 背景

现有画廊是「Hero + 我的项目卡 + 风格库」三段式：页头有底色与底线、Hero 占一整块、
页面内部滚动、风格卡与项目卡尺寸不同、风格详情是右侧窄栏、分区之间靠分割线。对照
参照实现与能力页的设计语言，这些形态偏「生硬、信息密度低、与宿主其余页面不协调」。

用户在原型阶段（`.tmp/design-gallery-v2/prototype.html` + `README.md`，13 个状态截图）
已经逐条给过反馈并定稿方向，本 ADR 把定稿方向转成可执行的决策，不再重新讨论「要不要做」。

## 决策

### 1. 页头：去底色与底线，标题改渐变

页头去掉底色与底部分隔线；大标题用「前景 → 主色」渐变、加粗、-0.03em 字距；动作是幽灵
按钮；标题区后面铺一层极淡主色光晕做过渡。**只留「设计」两个字与右侧动作**——项目数、
风格数、搜索态提示、副标题、描述全部删除（对应原型的「大标题下不要副标题」反馈）。

### 2. 流式布局：页面不再内部滚动

现有 `astravia-design-gallery-scroll` 是内部滚动容器，窗口一窄就裁切。改为流式：

- 画布宽 `min(1200px, 100%)`，内容左右内边距 56、页头内边距 `28 56 0`；
- 内边距用 `clamp()` 随窗口收缩；网格 `auto-fill` 自动减列；
- 说明栏（设计说明横条）放画布上方、与画布同宽，窄于 900px 退成一列；
- 页面不内部滚动，画布高度随内容长，任何状态都能从页头看到页脚。

代价：页头不再固定在滚动容器外，需要评估「搜索/新建/导入/刷新」按钮在长页面里的可达性
（现有 `setWorkspaceViewHeader` 把工具栏交给宿主页头，这个机制保留）。

### 3. Hero 删除，风格卡与项目卡同网格

- **Hero 整块删除**，副标题压成一行（如「8 个设计项目 · 10 套内置风格」）。
- 项目卡与风格卡放进**同一个三列网格**（`repeat(3, minmax(0,1fr))`，gap 16），
  同样的 16:10 预览 + 两行信息。风格卡的预览用该风格自己的令牌画一条界面骨架
  （侧栏 / 标题 / 内容块 / 主按钮 / 三色板），不再用截图或占位图。

### 4. 轮播参考能力页的 `AbilitiesBanner`

顶部轮播（高 200、圆角 18、双列 `1fr 1fr`）直接借用能力页 `AbilitiesBanner` 的语法：

- 图标星座（第 0 个居中偏左最大、其余按 `SLOT_LAYOUT` 错落）、每张幻灯片一个色相渐变
  （`SLIDE_HUES`，参考 255/210/232/40/12）、推荐文案 + 主色按钮 + 短横轮播点；
- 5 秒一轮、悬停 / 失焦 / 滚出视口暂停（复用 `IntersectionObserver` + `focus/blur` +
  `visibilitychange` 的停帧逻辑）。

不复制 `AbilitiesBanner` 代码，而是在画廊里实现同一套视觉语法——它是宿主组件，插件不能
直接 import；参照它的 `slideGradient` / `SLOT_LAYOUT` / `SLIDE_HUES` 结构。

### 5. 风格详情弹窗：上下布局

从右侧窄栏改为上下布局：通栏预览在上（用该风格的令牌渲染），下面是「配色色块 → 事实标签
→ 摘要 → 资源清单」；配色只给色块不给色号；「在浏览器打开 Demo」移到页脚左侧，与
取消 / 使用分开。

### 6. 少分割线 + 文案精简

分区之间、卡内分隔线全部去掉，改用间距与底色差；「风格库」「点一套风格看详情」等多余
字眼删除。

### 7. 未定项（实施时决定，不进本 ADR 结论）

- 轮播「推荐文章」取哪一条：暂按风格库顺序取前 5 套，人工推荐位留到以后；
- 风格卡三色板是否保留：暂保留（对区分同为浅色的几套有用）；
- 「查看全部」触发行数：与 `use-gallery-columns` 的量测绑定，不写死 6。

## 备选方案

- **只调样式、保留 Hero 与内部滚动**：改动最小，但不解决「生硬、信息密度低、窄窗口裁切」
  三个核心反馈，等于把原型阶段否掉的方向又捡回来。
- **把画廊改成宿主能力页的复制品**：视觉一致但画廊有「我的项目 / 风格库 / 导入导出 /
  归档」这些能力页没有的语义，硬套会丢功能。

## 后果

- 正面：画廊与能力页同一套设计语言（柔和页头、星座轮播、流式布局、少分割线），
  窄窗口不再裁切，风格卡与项目卡信息密度一致。
- 代价：重做约 2500 行画廊组件（`GalleryView` / `GalleryHero` / `DesignSystemGrid` /
  `GalleryCard` / `DesignSystemDetailDialog` 等）；删除 Hero 意味着「逛逛风格库」的
  滚动锚点入口要重新给（轮播或页头承担）。
- 兼容性：不改插件对外合同（`tab-ids`、画布引擎、导出分享包格式），只改画廊 UI 层。

## 验证

- 组件测试：页头无底色/底线、标题渐变类名存在；轮播在无图标时回落占位、悬停暂停、
  轮播点数量正确；风格卡与项目卡同尺寸同网格；风格详情上下布局（配色色块、资源清单、
  Demo 按钮在页脚）；空态与骨架态。
- 交互测试：卡片点击进画布、右键菜单导出/在文件管理器中显示/归档、导入/新建对话框、
  整页拖放只认分享包、归档二次确认——这些现有行为的用例继续全绿。
- 视觉：`prototype.html` 逐屏对照（仅在用户明确要求时跑 `verify:ui:*`）。

## 实施批次

1. 页头 + 流式布局骨架（删内部滚动，画布/内边距/网格改 `clamp` + `auto-fill`）；
2. 轮播（参考 `AbilitiesBanner` 的星座 + 色相渐变 + 停帧）；
3. Hero 删除 + 风格卡/项目卡同网格；
4. 风格详情弹窗上下布局；
5. 分割线清理 + 文案精简；
6. 组件/交互测试补齐 + code-review + diagnosing-bugs。
