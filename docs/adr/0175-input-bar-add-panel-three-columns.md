# ADR-0175：输入框「添加」面板改为三栏浮层，并引入收藏

## 状态

待审核：本文只记录决策与验收口径，**代码未改**。审核通过后按「实施轮廓」落地，届时
取代 [ADR-0156](./0156-capability-add-entry-and-sections.md) 的 §1 词汇与 §3 面板结构。
入口文案、五类顺序、以及「分类投影、不新增存储与权限」这三条从 ADR-0156 继续有效。

原型（仅用于评估，放在未跟踪的 `.tmp/` 下，不作为产物）：

- `.tmp/command-panel-prototype/prototype-v2.html` —— 七个状态可切换
- `.tmp/command-panel-prototype/screens/v2-*.png` —— 对应截图
- `.tmp/command-panel-prototype/README.md` —— 与上游的映射、落点与取舍

## 背景

ADR-0156 把这条入口定为「一条入口 + 按类型分区」，五类（文件 → 技能 → 连接器 →
插件 → 应用）在**同一个滚动容器**里靠 10px 区段标题区分，键盘是一维索引且只覆盖
可插入的技能。当时每类的条目都是个位数到几十条，这个结构够用。

现在的量级不同了：技能来自插件市场，重装几个插件就是几百上千条；连接器与插件本身也
在增长。三个后果：

1. **分类没有稳定位置**。类别边界是一条区段标题，它随前面内容的长短上下移动。想找
   「插件」必须先滚过连接器宫格与几十条技能，每次打开都要重新找。
2. **没有「常用的那几个」**。用户每次真正插入的是同一两个技能，却要从头找一遍；
   现有的排序（调用次数 → 类别 → 最近使用 → 名称）只能让它们排得靠前，不能把它们
   从上千条里择出来。
3. **列表行背了太多信息**。行里同时放图标、名称、来源徽章、右侧描述，行高 32px，
   一屏只出 5–6 行；描述与徽章在「按名字找东西」这个动作里都是噪音。

同时 ADR-0159 已经为本仓建立了另一套语汇：模型选择器是**三栏浮层**（图标栏 ｜ 搜索 +
虚拟列表 ｜ 右栏），毛玻璃、收藏、上下渐隐、行悬停才出现的附加入口。同一个输入卡片上
挂两个面板，用户会同时看到两套观感。

### 词汇冲突（必须在本轮解决）

ADR-0156 §1 造了 `CapabilityEntry` / `CapabilitySection` / `CapabilityCatalog`。
但本仓 `Capability` 已经被**授权契约**（`docs/capabilities/`、`@astravia-org/capability-sdk`）
占用，见 [CONTEXT.md](../../CONTEXT.md) 的「Capability（授权契约）」词条：它回答的是「某个
subject 能否调用某个宿主能力出口」。而这个面板列的是**可以往这条消息里加的东西**——
文件动作、技能、连接器、插件、应用——既不都是 [[Ability（能力）]]（连接器与文件动作
都不是可分发能力单元），更完全不涉及授权。继续用 `Capability*` 命名，会让两组含义在
同一个 grep 里混起来。

## 决策

### 1. 词汇：AddPanel，条目叫 Entry

| 术语 | 含义 | 取代 |
| --- | --- | --- |
| `AddPanelCategory` | 面板的五个分类，`files \| skills \| connectors \| plugins \| apps` | `CapabilityKind` |
| `AddPanelEntry` | 可被加到当前消息的一个条目 | `CapabilityEntry` |
| `AddPanelCatalog` | 由各域数据源投影出的「分类 → 分组 → 条目」结构 | `CapabilityCatalog` / `CapabilitySection` |
| `AddPanelFavorites` | 跨分类的常用项集合 | — |

「添加面板」是界面上的正式中文叫法，与入口文案「添加」一致。**不使用「能力面板」**：
`能力` 在本仓指 [[Ability（能力）]]，而连接器、文件动作都不是它。

### 2. 结构：三栏，分类在左

```
┌────┬────────────────────────┬──────────────┐
│收藏│  搜索框                 │  详情         │
│────│────────────────────────│  名称 / 来源  │
│文件│  分组头（无计数）        │  描述         │
│技能│  行：名称 + 悬停星标/详情 │  状态         │
│连接│  ...                   │  主次动作     │
│插件│                        │              │
│应用├────────────────────────┤              │
│    │  ↑↓ 选择 Tab 分类 ⏎ 插入 │              │
└────┴────────────────────────┴──────────────┘
```

- 第一栏 44px：**收藏在第一格**，分隔线后按 `files → skills → connectors → plugins → apps`
  自上而下排列，与 ADR-0156 的区段顺序一致（顺序不变，只是从纵向堆叠变成固定轨道）。
  每格只有图标，名字走原生 `title`，不占列表宽度。
- 第二栏：搜索框（跨全部分类）+ 虚拟化列表。未搜索时只显示当前分类，分类内部仍按
  来源/状态分组（技能按 内置/我的/插件/场景，连接器与插件按 已连接/未连接、
  已启用/已停用），分组头**不带计数**。
- 第三栏 232px：详情 + 动作。**没有选中项时整栏不渲染**（不留空白列、不占宽度），
  与 ADR-0159「没有档位时整栏不渲染」同一条规则。

### 3. 形态：独立浮层，不再是「长高的卡片」

保留现有实现事实：面板本来就是 `absolute` 定位、不参与布局（展开不会把消息列表顶上去）。
本次改的是**视觉归属**：

| | 现在 | 改为 |
| --- | --- | --- |
| 与卡片关系 | 底边压在卡片上描边上，同圆角、同描边，看起来是一块面长高 | 独立浮层，与卡片留 8px 间隙，四角圆角 14px，自带描边与投影 |
| 背景 | 与卡片同色实底 `--input-bar-bg` | `background/40` + `backdrop-blur(40px) saturate(150%)`（与模型选择器同一组取值） |
| 高度 | `min(320px, 40vh)` | `min(340px, 52vh)` |
| 关闭 | 点外部 / Esc | 不变 |

理由：卡片形态切换要求接缝处描边、圆角、底色完全连续，一旦要毛玻璃就没有可连续的
「同一块面」——玻璃必须透出背后的会话内容，而卡片是不透明的。模型选择器已经验证了
浮层这套观感在会话页成立（ADR-0159），两处统一。

### 4. 行：只放名字

行高 28px，内容 = 条目名（`truncate`）+ 悬停/选中时才出现的两个图标（星标、详情）。
描述、来源、状态全部移到第三栏。

分类切换后靠 rail 的选中态表达「现在在哪一类」，因此**列表上方不再有标题，也没有计数**。
计数在「按名字找东西」的动作里没有决策价值，反而每次切换都在跳数字。

### 5. 收藏：跨分类、只存本机

- 一栏第一格「收藏」聚合五类里的常用项，按分类分组；
- 行内星标悬停出现，点击就地加入/取消；已收藏的行星标常亮（琥珀色）；
- 存储沿用 ADR-0159 §4 的口径：键 `astravia-add-panel-favorites`，只存 `category::id`，
  只存本机、不跨设备同步；存储不可用时退化为会话内有效；
- 空态：星形图标 + 「还没有收藏」+ 一句怎么收藏。不放「去逛逛」这类引流按钮。

### 6. 搜索：跨分类，结果按分类分组

用户此刻要的是「哪个东西叫这个名字」，不是「这一类里有没有」。搜索命中按 rail 顺序
分组，分组头只写分类名（无计数）；选中搜索结果后，清空搜索并把 rail 切到该条目所属
分类，避免「选完之后列表里找不到刚选的东西」。

### 7. 键盘：分类进键盘模型

| 键 | 行为 |
| --- | --- |
| `↑` `↓` | 在当前可见列表内移动（含收藏与搜索结果，分组头跳过） |
| `Tab` | 循环切分类（收藏 → 文件 → 技能 → 连接器 → 插件 → 应用 → 收藏） |
| `Enter` | 插入技能 / 执行文件动作 / 连接-配置连接器 / 启停插件 |
| `Esc` | 关闭面板 |

`↑↓` 的索引从「全面板一维」改为「当前列表内一维」——正因为分类不再共享一个滚动容器，
一维全局面板索引没有意义了。

### 8. 虚拟化阈值统一为 40 行

与模型选择器共用同一个列表组件与阈值（行高同为 28px）。ADR-0159 §5 写的是 60 行，
本次统一到 40：两处行高相同，阈值不同只会让读者以为有原因。改动只影响模型选择器
开始窗口化的条数，交互不变。

### 9. 窄窗口退化

按容器宽度（`@container`，输入卡片已经是容器）而不是视口：

- ≥ 720px：三栏；
- 520–720px：隐藏详情栏，只留 rail + 列表（详情信息通过行内详情图标弹出）；
- < 520px：rail 收为顶部横向分段控件，列表全宽。

## 备选方案

- **保留单列，把区段标题做成吸顶**：成本最低，但类别仍然随内容滚动，头上最多浮一条
  标题，长列表里没有「固定位置」；收藏依然无处安放。
- **分类做成顶部横向 tab**：省掉 44px 轨道，但 tab 条会挤占列表宽度，且同一个卡片上
  会同时出现两种分类导航（模型选择器是 rail）。
- **每类各自一个浮层**：切换等于关一个开一个，多一次点击，且无法跨分类搜索。
- **保留卡片形态切换，只加 8px 留白**：留白会让接缝变成一条缝，描边、圆角、底色的
  连续假设全破；要么回到「同一块面」不能有留白，要么就必须断开成浮层。
- **继续用 `Capability*` 命名**：与授权契约同名，是本次最容易避免的长期成本。

## 后果

- 正面：分类位置固定（点一下就到，不再滚）；常用项收敛到收藏；行数从 5–6 提到 9–10；
  条目上千时只渲染可视行；与模型选择器共用浮层语汇，输入卡片上的两个面板不再像两家产品。
- 代价：三栏需要最小宽度，窄窗口要退化（三档）；详情栏是新增的注意力区，只为「快速
  插入一个技能」的用户它是噪音（缓解：它不抢焦点、动作固定在底部、无选中时不渲染）；
  面板高度从 320 提到 340；新增收藏存储与一批 i18n 键。
- 数据模型变更：`capability-sections.ts` 从「区段顺序 + 计数投影」改为「分类 → 分组 →
  条目」，并承担搜索结果的跨分类分组。`sectionAppliesFilter` 的语义从「这段是否参与
  过滤」变成「这个分类是否参与过滤」（文件分类仍是直接动作，不参与）。
- 不改变：技能/连接器/插件的发现、安装、权限与存储路径；插件信任模型；输入卡片其余布局。
- 与 ADR-0156 的关系：其 §1 词汇与 §3「单列分区 + 一维全局面板索引」被本文取代，
  其余（入口文案为「添加」、五类顺序固定、catalog 只做投影）继续有效。

## 实施轮廓

按依赖顺序，每一档都能单独验证：

1. **数据层**：`capability-sections.ts` → `add-panel-catalog.ts`，输出 `AddPanelCatalog`
   （分类 → 分组 → 条目）；补 `AddPanelEntry` 的 `category / group / key / icon`。
2. **面板骨架**：`CommandPanelView` 改为「浮层 + 三栏」，三栏各自独立滚动，第三栏按
   有无选中决定是否渲染；`useCommandPanelModel` 的 `activeIndex` 改为
   `{ category, index }`，`Tab` 绑定进现有 `useShortcutScope`。
3. **行与列表**：新行组件（名字 + 悬停星标/详情），列表窗口化复用模型选择器的实现；
   分组头去计数。
4. **收藏**：`useAddPanelFavorites`（本机存储、会话内降级），rail 首格与行内星标同源。
5. **详情栏**：按分类给动作（插入 / 执行 / 连接-配置 / 启停），文案与键补齐。
6. **窄窗口**：`@container` 三档退化。

## 验证

- 组件/交互（必需）：分类切换、`Tab` 循环、`↑↓`/`Enter`/`Esc`、搜索跨分类分组与选中后
  归位、收藏增删与空态、无选中时详情栏不渲染、文件分类不参与搜索。
- 用户常见流程（必需，从输入栏入口进入）：依次「打开面板 → 切到插件 → 收藏一项 →
  打开收藏并插入 → 搜索关键词跨分类选中并插入」，断言最终输入框里的提示词与面板状态。
- 批量条目：构造 > 40 行数据，断言只渲染可视窗口行数。
- 视觉（实机核对，非默认 `verify:ui:*`）：8px 间隙、玻璃与投影、三档退化排版。
- 发布说明：本变更属可见行为变化，需在当版 `.github/release-notes/v<version>.md` 的
  「改进」下写一条（分类固定在左侧、新增收藏、列表更紧凑）。
