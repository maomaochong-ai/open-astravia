# ADR-0148：Desktop 首屏使用细粒度 UI 公共入口

## 状态

Accepted

## 背景

开发版显示启动骨架后，`renderApp` 的静态依赖图仍需逐模块转换、请求和求值。
M1、16 GiB 设备的隔离测量中，这一步冷态约 5–6 秒；完成前请求约 1,247 个同源资源、27 MiB。
`theme-ui` 的领域聚合导出、远程主题共享模块和全局弹窗把尚未使用的视图及 Three.js 等依赖带入首屏。
生产构建的打包优化掩盖了这部分开发成本。

## 决策

- `theme-ui` 和基础 `ui` 为首屏消费的组件与工具增加显式公共子路径。原聚合入口保留；新入口直接指向同一个源模块，组件身份、Context、样式副作用和 API 保持一致。
- Desktop 首屏依赖闭包改用这些子路径；共享组件内部取 `cn` 时使用已有的 `ui/utils`。不从其他包深度导入 `src`。
- Vite 按 workspace 包的 `exports` 解析 UI 包，删除绕开导出表的目录别名，保留源文件热更新。
- 仅选择非默认主题时加载远程主题运行时。已保存的非默认主题仍完成恢复后再展示页面，失败仍回退默认主题。
- 全局审批事件接收保留在首屏，先进入已有队列；全局视图在首个实际路由或路由错误页完成绘制后加载；同一信号再上报主进程内容就绪，避免后台初始化与页面代码加载竞争。卸载期间不启动迟到的视图；视图加载后消费同一队列。
- 活动面板保留页签元信息、工作区注册和后台状态订阅；内置页签的内容组件按实际挂载异步加载，使用原有 Portal 和驻留策略保留浮动、停靠及页签切换的状态。
- 高频路由的空闲预取仅在实际页面模块加载、组件提交并绘制后启动；网络等待期间的主线程空闲不能作为首屏完成信号。默认对话目录尚未返回时，空聊天路由继续等待重定向，避免提前加载马上会卸载的聊天页。
- 开发入口根据 hash 与同一份持久会话定位解析器，并行预取目标聊天/新会话页代码，避免外壳加载后才开始第二条模块瀑布；不提前挂载页面、不创建或恢复会话，显式其他路由不额外预取。这项推测预取失败不会阻塞正常路由重试。
- 开发服务器使用 Vite 自带的首屏入口预热，与 Electron 启动并行。生产构建保持原来的打包流程。

## 备选方案

| 方案 | 取舍 |
| --- | --- |
| 只延迟远程主题加载器 | 只能减少一条聚合导入路径，无法消除其余首屏依赖 |
| 把所有 UI workspace 源码当成第三方依赖预打包 | 会改变源码编辑、缓存失效和 Fast Refresh 行为；继续使用 Vite 原生源码模块 |
| 隐藏骨架或提前报告内容完成 | 不减少实际等待，不采用 |
| 全部改为跨包源码深度导入 | 绕开包合同，不采用 |

## 后果

- 公共子路径数量增加；维护时必须保持导出表、实际源码与消费者一致。原入口无迁移要求，也不涉及持久数据迁移。
- 非首屏视图首次加载有异步边界，不能把事件订阅一起推迟。审批队列的连续操作、主题切换与失败回退由组件测试覆盖。
- Vite 公共入口解析和首屏静态依赖由合同测试保护；真实性能与后续交互仍需使用隔离 Electron 测量。
- 计时区分页面首次内容绘制与输入可用；不同设备、缓存和并发负载不承诺统一的两秒上限。

## 验证（2026-10-08）

Apple M1 / 16 GiB，隔离开发实例、默认主题，未启动插件开发服务器。
重复测量保留 Vite 转换缓存，关闭浏览器 HTTP 缓存，窗口置于前台；时间从页面导航开始，
DOM 出现后再等待绘制，输入点以可见的可编辑输入框为准。

| 阶段 | 第一次 | 第二次 | 第三次 |
| --- | --- | --- | --- |
| 启动骨架可见 | 0.124 s | 0.171 s | 0.090 s |
| 应用外壳可见 | 1.005 s | 1.018 s | 0.891 s |
| 输入框可用 | 1.412 s | 1.411 s | 1.290 s |

三次输入就绪前均完成 962 个资源请求，无页面异常。另一次重启 Vite/Electron 的完整开发实例中，
从主窗口启动计时点到骨架绘制为 0.413 s，到实际路由内容绘制为 2.663 s；不含命令启动前的
workspace 构建和插件打包时间。冷启动尚未达到两秒，因此不将重复加载结果当成冷启动承诺。
原实现隔离冷态的外壳模块导入为 5.03–6.10 s，重复加载为 2.48–2.55 s；这只是原实现的一个
阶段，不能直接等同于其输入就绪总时间。重载结果与首次实例启动使用不同起点，亦不混算。
