# ADR-0093：云市场与 GitHub 多源独立启用

- 状态：已接受
- 日期：2026-08-30

## 背景

Desktop 曾以云功能开关决定是否注册内置 GitHub 市场，导致云版刷新时看不到 GitHub 仓库新增能力。
开发期额外开关只能缓解联调问题，不能表达两类来源独立、开源版支持多个来源的产品要求。
现有目录模型已区分来源身份，安装冲突也有显式处理流程，不需要通过互斥目录来避免冲突。

## 决策

1. 云开关只控制云服务的构建与请求。GitHub 多源功能在所有模式可用，但商业版默认不包含 GitHub 仓库。
   两种版本均仅由 `VETTA_OPEN_MARKETPLACE_REPOSITORY` 显式声明内置来源，未配置或空白时不注册；
   运行时、构建和发布脚本都不兜底仓库地址，也不清空商业版的显式配置。
2. 复用 `MarketplaceSourceStore` / `OpenMarketplaceManager`，不建立通用 Provider 框架或第二套安装路径。
   默认源坐标来自环境变量；默认配置协调提取为纯策略，文件存储继续拥有持久化。
3. 来源升级保留用户来源身份和开关。同仓库已有自定义来源时保留它，并以可选
   `registeredDefaultRepositories` 字段记录默认仓库已协调，避免删除后复活。旧 `version: 1` 文件仍可读取。
4. Renderer 的 GitHub 目录状态由独立 Hook 拥有，统一处理读取、修改、请求顺序和后台通知。
   云失败与单个 GitHub 来源失败分别呈现；未启用云服务不能算作成功的市场请求。
5. 同一来源 worker 的并发刷新共享同步任务；修改名称和开关不重建 worker，坐标改变才切换缓存身份。
   UI 提供单源刷新、自动更新及缓存/失败状态。保留现有目录 ID 和显式安装冲突语义，不自动跨源覆盖。

## 备选方案

- 仅删除云分支：不能解决默认仓库与用户已有来源重复、升级开关丢失、目录旧响应覆盖等问题。
- 保留开发期开关：发行版行为仍互斥，增加环境差异与排查成本。
- 在代码中默认内置官方仓库：混淆“功能可用”和“发行配置”，导致未配置的商业版也注册 GitHub 来源。
- 新建统一 Provider 引擎：目前只有既有云 API 和 GitHub 管理器两个明确边界，新增引擎不减少职责或重复。

## 后果与验证

商业版未配置时只有云市场；开源版要随包提供官方源，须在构建环境或 CI Variables 配置地址。
移除环境配置不删除已保存来源或改变其开关，旧版本曾自动创建的来源可在界面停用。
默认注册元数据不影响市场 manifest 或已安装内容；
旧客户端可能删除该可选字段，降级后的来源删除记忆不作保证。

自动化测试覆盖云/非云与开发/生产配置、旧文件升级、同仓库去重及开关保留、多源故障隔离、缓存回退、
单源操作接线、旧响应与后台通知顺序、并发同步和安装来源合同。测试使用临时目录与外部边界替身。

能力分型和安装轨道仍遵守 ADR-0049；本决策不更改 MCP 协议、权限或上游 MCP 源码。
