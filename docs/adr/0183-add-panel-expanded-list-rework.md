# ADR-0183：添加面板展开列表重构（分类对齐、更多按钮、面板分离）

## 状态

已接受，待实施。范围是聊天输入框「添加」按钮展开面板的交互与视觉，不动条目数据来源
（能力页同一套组装结果，见 ADR-0177）。

## 背景

「添加」面板经过几轮迭代后，导航与视觉出现几处与用户直觉不一致的地方：

1. 左栏分类用**上下箭头**逐格滚动，台式机与无触控板用户只能靠它，但「上下箭头」与
   分类切换的语义割裂——用户期望点分类本身，而不是先滚轨道再点；
2. 输入行上方工具条用**左右箭头**逐格滚动，同理割裂；
3. 分类集合（files/skills/connectors/plugins/apps）与能力页的类型（skill/mcp/plugin/bundle）
   不一致，「附件」单独成类又与输入框内已有的附件按钮重复；
4. 面板与输入卡片是「长高」形态（底边压过卡片描边），视觉上不是一个独立的圆角浮层，
   与模型选择器的毛玻璃浮层语言不一致。

## 决策

### 1. 左栏分类对齐能力页类型，压缩上下文并入「指令」（对应 a、c）

- 分类从 `files/skills/connectors/plugins/apps` 收敛为能力页类型
  `skill / mcp / plugin / bundle`，图标与文案复用能力页的 `ABILITY_TYPE_ICON` /
  `ABILITY_TYPE_LABEL_KEY`，两处不再各写一套名字；
- 「附件 / 文件」不再是分类：输入框内已有附件按钮，面板里再放一类是冗余；
- 「压缩上下文」等会话操作并入「指令」分类（`operations` 改名 `commands`），与技能分类
  同一条轨道；
- 收藏、全部保持不动。

### 2. 上下箭头改为「更多分类」按钮（对应 a）

- 左栏不再常显上下箭头；轨道放不下全部分类时才在轨道末端自动出现一个「更多分类」
  三点按钮，点击弹出圆角列表选择被收纳的分类；
- 放得下时不显示任何箭头——分类固定位置、直接可点，这是导航的全部意义。

### 3. 工具条左右箭头改为「更多动作」按钮（对应 b）

- 工具条不再常显左右箭头；动作放不下时行尾出现一个「更多动作」按钮，点击展开圆角
  列表选择被收纳的动作；
- 与左栏「更多分类」同一套三点图标与弹层视觉。

### 4. 斜杠命令正常触发（对应 d）

- 斜杠命令 `/` 触发面板，不因面板打开态或编辑器焦点出现「按两次斜杠才出现」；
  触发去抖只针对连续输入，不吞掉首次 `/`。

### 5. 面板与输入卡片分离为独立圆角浮层（对应 e）

- 面板改为**独立圆角容器**（四角圆角 + 完整描边），不再「长高」压过卡片上描边；
- 底色与输入卡片同 token，加毛玻璃（`backdrop-blur` + 半透明前景色），与模型选择器
  同一套材质语言；
- 两栏式（分类轨道 + 列表/预览）保持不变；圆角边框线四边完整，不缺失。

## 备选方案

- **保留上下/左右箭头，只改样式**：不解决「箭头与切换语义割裂」，用户仍要滚轨道。
- **面板改为三栏对齐模型选择器**：模型选择器三栏是「服务商/模型/思考强度」的层级，
  添加面板是「分类/条目」两层，硬套三栏多出一列无意义；两栏更窄、窄窗口更从容。

## 后果

- 正面：分类与能力页一致、导航与浮层语言统一，斜杠触发不再卡顿。
- 代价：分类轨道、工具条、面板容器三处渲染结构重构，需同步改测试。
- 兼容性：不改条目数据来源与插入语义，纯渲染与交互层改动。

## 验证

- 分类对齐：面板分类键与能力页类型一致（skill/mcp/plugin/bundle），无 files/apps 残留；
- 更多分类 / 更多动作：溢出时出现、点击弹层可选、不溢出时不显示；
- 斜杠触发：`/` 首次即打开面板（回归用例）；
- 面板分离：圆角容器四角圆角 + 完整描边，不与输入卡片「长高」相连（组件测试）。
