# ADR-0183：添加面板展开列表重构（分类对齐、更多按钮、面板分离）

## 状态

已接受，已实施。范围是聊天输入框「添加」按钮展开面板的交互与视觉与条目归类，数据来源
仍是能力页同一套组装结果（见 ADR-0177）。

补充决策见「追加决策：归类与计数」一节——首版实现漏了组合包（bundle）与市场连接器
（mcp）的归类，且分组头没有条目数量。

## 背景

「添加」面板经过几轮迭代后，导航与视觉出现几处与用户直觉不一致的地方：

1. 左栏分类用**上下箭头**逐格滚动，台式机与无触控板用户只能靠它，但「上下箭头」与
   分类切换的语义割裂——用户期望点分类本身，而不是先滚轨道再点；
2. 输入行上方工具条用**左右箭头**逐格滚动，同理割裂；
3. 分类集合（files/skills/connectors/plugins/apps）与能力页的类型（skill/mcp/plugin/bundle）
   不一致，「附件」单独成类又与输入框内已有的附件按钮重复；
4. 面板与输入卡片是「长高」形态（底边压过卡片描边），视觉上不是一个独立的圆角浮层，
   与模型选择器的毛玻璃浮层语言不一致。

## 决策

### 1. 左栏分类对齐能力页类型，压缩上下文并入「指令」（对应 a、c）

- 分类从 `files/skills/connectors/plugins/apps` 收敛为能力页类型
  `skill / mcp / plugin / bundle`，图标与文案复用能力页的 `ABILITY_TYPE_ICON` /
  `ABILITY_TYPE_LABEL_KEY`，两处不再各写一套名字；
- 「附件 / 文件」不再是分类：输入框内已有附件按钮，面板里再放一类是冗余；
- 「压缩上下文」等会话操作并入「指令」分类（`operations` 改名 `commands`），与技能分类
  同一条轨道；
- 收藏、全部保持不动。

### 2. 上下箭头改为「更多分类」按钮（对应 a）

- 左栏不再常显上下箭头；轨道放不下全部分类时才在轨道末端自动出现一个「更多分类」
  三点按钮，点击弹出圆角列表选择被收纳的分类；
- 放得下时不显示任何箭头——分类固定位置、直接可点，这是导航的全部意义。

### 3. 工具条左右箭头改为「更多动作」按钮（对应 b）

- 工具条不再常显左右箭头；动作放不下时行尾出现一个「更多动作」按钮，点击展开圆角
  列表选择被收纳的动作；
- 与左栏「更多分类」同一套三点图标与弹层视觉。

### 4. 斜杠命令正常触发（对应 d）

- 斜杠命令 `/` 触发面板，不因面板打开态或编辑器焦点出现「按两次斜杠才出现」；
  触发去抖只针对连续输入，不吞掉首次 `/`。

### 5. 面板与输入卡片分离为独立圆角浮层（对应 e）

- 面板改为**独立圆角容器**（四角圆角 + 完整描边），不再「长高」压过卡片上描边；
- 底色与输入卡片同 token，加毛玻璃（`backdrop-blur` + 半透明前景色），与模型选择器
  同一套材质语言；
- 两栏式（分类轨道 + 列表/预览）保持不变；圆角边框线四边完整，不缺失。

## 备选方案

- **保留上下/左右箭头，只改样式**：不解决「箭头与切换语义割裂」，用户仍要滚轨道。
- **面板改为三栏对齐模型选择器**：模型选择器三栏是「服务商/模型/思考强度」的层级，
  添加面板是「分类/条目」两层，硬套三栏多出一列无意义；两栏更窄、窄窗口更从容。

## 后果

- 正面：分类与能力页一致、导航与浮层语言统一，斜杠触发不再卡顿。
- 代价：分类轨道、工具条、面板容器三处渲染结构重构，需同步改测试。
- 兼容性：不改条目数据来源与插入语义，纯渲染与交互层改动。

## 验证

- 分类对齐：面板分类键与能力页类型一致（skill/mcp/plugin/bundle），无 files/apps 残留；
- 更多分类 / 更多动作：溢出时出现、点击弹层可选、不溢出时不显示；
- 斜杠触发：`/` 首次即打开面板（回归用例）；
- 面板分离：圆角容器四角圆角 + 完整描边，不与输入卡片「长高」相连（组件测试）。

## 追加决策：归类与计数

首版落地后用户反馈三处归类/信息缺失，根因都在「条目 → 分类/来源」的投影规则上，与数据来源无关：

1. **套装分类恒为空**：`categoryOf` 只处理了 skill/mcp/plugin，`bundle` 落到 `undefined`，
   整类条目被丢弃。改为直接返回 `item.type`，分类与能力页类型一一对应。
2. **市场安装的连接器消失**：MCP 分支额外要求「非 github-marketplace 来源」，与能力页
   「已安装即列出」相悖。改为统一以 `item.installed || item.isBuiltin` 判断可见性，
   来源只影响分组（`market`），不再影响是否出现。
3. **通用 Agent 技能混进「我的」**：插件贡献、`~/.agents/skills`、项目 `.agents/skills`
   三类来源此前共用 `mine`。新增 `agents` 分组，与 `mine` 分开；是否扫描这些目录仍由
   「设置 → 扩展功能 → 适配通用 Agent Skill」在**主进程**决定，面板只如实呈现。
4. **分组头没有数量**：`AddPanelRow` 的 header 变体带 `count`，浏览态每个分组头都显示该组
   条数，搜索态显示整类条数；分组顺序固定为「内置 → 市场 → 插件 → 通用 Agent → 已连接 →
   已安装 → 项目 → 我的 → 未知」，不随条目名变化。
5. **来源视图（内置/市场）分组标题**：该视图里来源已是筛选条件，命中的条目并回分类分组，
   标题改用分类名，避免出现多个同名「市场」分组。
6. **内置技能按 `source === "builtin"` 归组**：随 App 分发的技能只有这一种标记，此前只认
   `isBuiltin`，于是它们全部落到「我的」，与用户自己装的技能混在一起。
7. **面板只列「能力页也会列出」的能力**：`mcp.json` 里残留的预置连接器（既非市场安装、
   也非手动添加）在能力页两个分区都不展示，面板却凭「配置里有」把它列了出来。现在面板与
   能力页同一判据（`isAbilityListedInDiscover` / `isAbilityListedInPersonal`），并额外放行
   「清单登记为市场安装」的技能——那类技能要等市场快照同步才会出现在能力页，面板不必一起等。
8. **内置能力与其它条目一样可插入**：曾经的「内置只展示、不插入」是错的——上游内置技能
   （安装技能、创建技能等）点一下就会插进对话框。内置能力虽随 App 分发，但用户要引用它是
   明确动作（`/技能` 令牌），不允许点击只会让人以为「这个不能用」。`insertable` 这层判定
   随之整体删除（已无任何不可插入的条目）。
9. **关掉「适配通用 Agent Skill」后通用技能真的消失**：技能加载器早就按开关跳过
   `~/.agents/skills`，但资源包投影（`ResourceProjector`）无条件扫描祖先目录的
   `.agents/skills`，把它们以「项目技能」身份重新塞回来。开关现在同时下发到投影层
   （`createResourcePackageRuntime({ includeAgentSkills })`）。

## 追加决策：行的一等公民是「能不能插进消息」

**上游的做法（open-vetta）**：命令面板只列两种东西——技能与连接器。数据源是
`useSkillList({ surface: "commandPalette" })`，逐条按 `isSkillVisibleOnSurface(skill, "commandPalette")`
过滤；插件贡献的技能同样在这个列表里（默认隐藏，插件显式声明可见才出现）。列表里每一行
都是「能被引用进这条消息的东西」：点技能插入 `/技能` 令牌，点连接器挂上下文。上游**没有**
「插件行」这种只读条目——插件不是被插入的对象，它贡献的技能才是。

**本仓库的偏差**：面板为了与能力页对齐，额外列了「插件」「套装」两类。这两类的点击落在
同一个 `switch` 的 `default` 分支里，一律只开预览，于是出现「点插件什么都不进对话框」的
割裂感；同时插件贡献的技能被 `source !== "plugin"` 整批排除，连本可以插入的那部分也消失了。

决策：

1. **技能一律按界面表面可见性收录**，不再按来源排除插件贡献的技能。判据与上游同口径：
   `isSkillVisibleOnSurface(skill, "commandPalette")`。
2. **插件行的点击语义 = 插入「插件引用令牌」`@plugin:slug`**，不是挑包内某个技能顶上来，
   也不是插一段纯文本。

   最初实现成「插入它显示名最小的那个可见技能」，这是错的：插件通常带多个技能，替用户挑
   一个会使其余技能在消息里失去入口，职责边界也乱了——**技能是技能，插件是插件**：插件是
   能力包（工具 + 若干技能），把插件放进消息是「用这个包干活」，不是「用包里的某个技能」。

   第二版退成了纯文本（`使用「<插件名>」插件的能力完成：`），输入框里没有胶囊形态，与技能、
   连接器不一致，用户看不出「这是一个引用」。现在补齐为**真正的行内令牌**：文本形态
   `@plugin:slug`，与 `@skill:` / `@mcp:` 同构；编辑器里渲染为同一款胶囊，气泡里由
   `usePluginTokenMeta` 回查标题与图标。包内每个技能另有独立可插入行，互不影响。
3. **来源事实优先于标记**：明明从市场装的条目，不该因为能力条目上残留 `builtin` 标记
   （插件 `source` 被归一成 `system`、或技能带内置图标）就归到「内置」。分组先判来源、
   再判标记。
4. **套装行保持预览**：套装是一组能力的集合，不是可插入对象；它的成员技能本来就有各自
   的可插入行。套装行仍参与导航（预览页说明包内成员在哪一类）。
5. **连接器行**：挂 `@mcp:` 上下文，不变。

### 验证（本轮）

- `useAddPanelAbilityEntries.test.tsx`：插件贡献的可见技能进「插件」分组并可插入；插件无可见
  技能时该行 `insertable=false`。
- `useCommandPanelModel.test.tsx`：点插件行插入插件引用而非旗下技能。

### 验证

- `add-panel-catalog.test.ts`：分组头计数、固定分组顺序、来源视图按分类成组；
- `useAddPanelAbilityEntries.test.tsx`：市场连接器进 MCP 且归入 `market`、Agent 技能独立成组、
  市场技能图标与中文标题；
- `CommandPanelView.test.tsx`：浏览态出分组头、搜索态改出分类头；
- 实机（开关关闭）：技能视图「内置 2 / 市场 46」，套装「市场 2」，MCP「市场 1」，
  市场视图按分类分「技能 46 / 插件 9 / MCP 1 / 套装 2」，`.agents/skills` 里的 16 个技能不再出现；
  内置行 `aria-disabled=true`、点击不插入、方向键跳过（实测点击后输入框仍为空）。
