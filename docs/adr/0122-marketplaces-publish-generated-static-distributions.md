# ADR-0122：能力市场采用生成的静态分发仓库

- 状态：已接受
- 日期：2026-09-19

## 背景

源码与可安装索引共同演进，迫使文档和普通开发提交也提高 marketplaceVersion。
构建后再创建目录 PR 又使源码版本、制品上传与审核相互依赖。

## 决策

采用 Helm chart-releaser 的静态包仓库模式：普通源码 PR 审核代码及能力版本，
合入市场配置声明的源码分支表示批准发布。已有线上市场使用独立的 `marketplace-source`
承载新源码，冻结 `main` 作为 schema v2 兼容来源。CI 构建未发布插件版本、校验已发布 Desktop 兼容性、
上传不可变 .vettapkg，再向 gh-pages 发布生成的 schema v3 目录与资源。
不新增发布计划协议，不向源码分支回写生成索引，不创建第二个目录 PR。

源码配置 marketplace.source.json 不包含 marketplaceVersion 或 releases；
发布工具从能力声明、包内容与历史分发索引生成它们。源码修改不重发同版本运行内容。
Skill/MCP 等沿用现有安装合同，只有提高能力版本才替换分发中的运行文件。

Desktop 沿用 GitHub 来源协议读取 gh-pages 的精简归档，插件包按需下载。
该归档仍包含展示资源及非插件安装内容；本次未引入按文件的 CDN 拉取协议。
旧 schema v1/v2 入口和用户来源配置不自动迁移，`main` 在受支持旧版仍使用期间保持有效；
确认新分发有效后，新版 Desktop 显式切换到 `gh-pages`。

构建任务只读，写入任务不执行插件构建脚本。已发布制品禁止覆盖；任务失败重跑
必须校验已有字节。仅在制品检查通过后更新分发分支，源码或分发基线前进则拒绝旧任务。

## 备选方案

- Zed 式逐版本目录 PR：适合集中审核外部作者更新，自有多能力仓库会多一次登记。
- Release Please 式独立发布 PR：提供单独发布审批，但当前普通版本变更 PR 已能承担审批。
- 自建注册服务：增加身份、存储和 API 运维，当前 GitHub 静态分发足够。

## 影响与验证

维护者需保护配置声明的源码分支并要求检查和审核，合并版本变化即允许 CI 发布。
需要 GitHub Release 和 gh-pages 写权限，但无需机器人创建 PR 权限。
客户端 schema、权限校验、最高兼容版本选择与安装器保持原样。
工具测试覆盖首次发布、同版本不重发、升级保留历史、路径拒绝、上传中断续跑和摘要冲突；
Desktop 隔离测试直接读取生成目录并安装本地构建的包。
