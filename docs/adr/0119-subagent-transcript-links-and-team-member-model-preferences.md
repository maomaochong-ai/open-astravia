# ADR-0119：子代理消息入口与团队成员模型偏好

## 状态

已接受

## 背景

子代理的运行状态保存在父会话，却缺少能稳定对应父消息中派发工具调用的字段。普通子代理因此只能在活动面板查看摘要，无法从派发位置进入自己的消息记录。子会话已经有独立的会话文件和只读查看器。

团队成员拥有独立运行时，但模型选择只存在于团队会话。团队定义可能由插件提供并在同步时整体重铺；将用户选择直接写入 `TeamMember` 会被插件更新覆盖。已有团队和会话默认应继续跟随会话模型。

## 决策

1. 子代理快照增加可选的 `originToolCallId`，从 `spawn_agent` 与 `dispatch_workflows` 的真实工具调用传入，随父会话的子代理状态持久化和观察事件传递。旧记录缺少该字段仍可恢复，只保留原有活动面板入口。
2. 父消息列表按当前运行时会话与 `originToolCallId` 把子代理状态卡放在派发工具调用下方。子会话文件就绪后，卡片打开既有只读会话查看器；查看器提供返回父对话入口。排队或尚未建立文件时显示状态，文件建立后开放入口。子会话不重新加入普通侧栏会话列表。
3. 成员模型偏好是用户拥有的独立文件，按团队 ID、成员 ID 与绑定的 Agent Profile ID 保存。插件团队定义仍由插件维护。成员换绑不同 Agent 后，旧偏好不再生效。
4. 偏好缺省时沿用本轮显式会话选择或团队会话模型；固定模型存在时优先于会话选择。选择在成员轮次入队时确定，只影响后续轮次。固定模型不在当前模型目录时，设置页保留原选择并提示重新选择或恢复跟随；运行时不会静默改用其他模型。

## 备选方案

- 从工具结果文本解析子代理 ID：文本不是稳定协议，排队、恢复与多工作流派发容易失联。
- 为子代理创建普通会话入口：会重现子会话进入侧栏及被当作主会话恢复的问题。
- 在 `TeamMember` 中存模型：插件同步会覆盖用户偏好，且改变团队定义的所有权边界。
- 模型失效时自动回退会话模型：会悄悄改变用户给成员指定的成本和能力预期。

## 后果

子代理快照协议增量兼容旧数据。成员模型偏好文件新增独立持久化合同；删除或换绑成员后不再应用旧记录，后续可清理无效条目。设置页和运行时共同使用偏好，但团队定义格式不变。
