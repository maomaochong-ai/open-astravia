# ADR-0128：手机接入的双通道、端到端加密与会话镜像

## 状态

已接受（修订 ADR-0078 中"双方均主动连接中继"与"明文帧"两项决定）；手机端实现部分已由 ADR-0129 修订：Expo 客户端移出仓库，iOS 改为 Swift 原生。之后 Kotlin Android 客户端恢复维护并升级到 v2 加密中继；局域网优先切换仍仅由 iOS 实现。

## 背景

ADR-0078 让手机经 Cloudflare 中继遥控桌面，但落地后有四个问题：

1. 桌面端只会主动拨到云端中继，本机不监听任何端口，在同一 Wi-Fi 下也必须绕道公网，延迟高且离线不可用。
2. 协议帧是明文。中继原样转发，技术上能读到全部对话；局域网上同网段的人也能抓到配对密钥与内容。
3. 一台电脑只能绑一部手机，重新扫码会顶掉旧配对，无法单独撤销某一部丢失的手机。
4. 手机只能看到"对话"目录里、由它自己发起的轮次；电脑上正在跑的任务、其他项目的会话、电脑弹出的提问都看不到。且远程层打开会话时写死沙箱模式，会把电脑上正以完全访问模式运行的会话悄悄切成沙箱。

同时用户明确要求：**没有手机连接时，桌面端不能为移动端付出任何代价**。

## 决策

### 双通道，同一协议

桌面端在有已配对手机时于局域网开一个 WebSocket 端口（默认 43117，占用则顺延），路径 `/v2/lan/<pairingId>`；同时按设备保持一条到中继房间 `/v2/relay/<pairingId>/desktop` 的常驻链路。手机局域网优先（约 1.5 秒预算并发探测），失败走中继，在中继上定期探测并静默切回。两条链路共用一份按设备的事件日志（`RemoteEventJournal`），事件序号跨通道连续，手机重连只补缺失的尾部；日志按条数与时长封顶，超出后发 `session.resync` 让手机整体重拉。

### 协议 v2：端到端加密

`@vetta/remote-control` 升到 v2。双方各持一把长期 X25519 身份密钥，每次连接再生成临时密钥，用三重 DH（临时/临时、身份/对端临时、临时/对端身份）经 HKDF 派生方向密钥，业务帧全部封进 XChaCha20-Poly1305 的 `sealed` 信封。明文只剩 `hello`、`hello_ack`、`pairing_pending`、`peer_status`；中继读 `hello` 校验角色，并把双方公钥抄进对端的 `hello_ack`，此后只转发 `sealed` 帧，收到其他明文帧即断开。密码学只用已审计的 `@noble/*`，Node、Electron 与 React Native 共用同一份实现。

### 每部手机独立配对

桌面端维护设备列表。每次"生成二维码"创建一条配对记录：配对 id、手机长期密钥（只有哈希落盘，明文留在凭据库直到被领取）、中继房间的桌面密钥。二维码只对第一部出示密钥的手机有效：桌面钉住它的身份公钥，之后任何其他身份都被拒绝；10 分钟未领取自动作废。手动输入 IP 的配对走 `/v2/lan/pair`，两端由双方身份公钥各自算出同一个 6 位验证码，桌面端放行后经加密链路用 `device.paired` 事件把长期凭据交给手机。任何手机接入都弹系统通知。

中继房间由桌面注册，注册时用子协议 `vetta.peer.<sha256(手机密钥)>` 把手机凭据哈希交给中继，中继从不持有手机密钥；重新注册即可轮换。

### 会话镜像

手机看到的就是桌面看到的：会话镜像按会话文件路径去重复用运行时里已活的实例（打开时不指定执行模式），列出"对话"目录与全部已打开项目的会话，跟随运行时的 running 变化订阅电脑上发起的轮次，并把用户消息、流式增量、工具阶段、提问与回答同步到手机。会话在协议里用会话文件路径的哈希作不透明 id，不泄露路径。提问代理增加按 requestId 结算的外部槽位，先答先得，手机能接住电脑上任何正在等待的提问。

### 零负担

未配对：远程模块不开端口、不连中继、不订阅运行时。已配对无手机在线：只保留局域网监听与空闲的中继链路（指数退避重连；中继侧靠 `ping`/`pong` 自动应答维持休眠，不产生费用）。镜像只在至少一部手机在线时挂载，最后一台断开（5 秒宽限，避免换通道时抖动）即卸载。流式增量在桌面端按约 80 毫秒合并再发。

### 客户端

Swift 客户端（`apps/mobile/client-apple`）是完整双通道参考实现。Kotlin Android 客户端（`apps/mobile/client-android`）实现同一份 v2 配对、加密帧与中继合同，可以连接新桌面；当前只走中继，不进行局域网优先探测与静默切换。

## 备选方案

- **局域网也走云端中继**：最省事，但必须联网、延迟高、离线不可用，与"局域网"名不副实。
- **本机跑一份中继**：要把 Wrangler 运行时打进安装包，过重。
- **局域网用自签 TLS 代替应用层加密**：只解决局域网，中继照样看明文，且 React Native 不便做证书指纹校验。
- **一对一配对**：换手机或多设备体验差，丢失手机无法单独作废。
- **手机专属会话（维持现状）**：做不出"电脑正在做的事"这个产品定位，且模式被改写的缺陷仍在。

## 后果

- 协议 v1 客户端全部失效；Android 用户需要安装支持 v2 的 Kotlin 客户端。Android 当前依赖中继，关闭「允许在外网访问」后无法连接。
- 桌面端多了一个局域网监听端口，首次开启时 macOS 会询问是否允许传入连接；文案已在设置页说明。
- 相比 v1，密钥材料多了一处凭据库依赖：凭据库不可用的系统无法配对。
- 中继保持在 Cloudflare 免费额度内的前提是心跳走自动应答、流式合并发送；若日后加入大流量能力（如屏幕），需重新评估。
- 后续二期：手机确认策略、推送通知、远程桌面（WebRTC，需开发构建）、SSH 终端、生物识别确认，均建立在本决策的链路与配对模型之上。
