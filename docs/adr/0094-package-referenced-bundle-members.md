# ADR-0094：Bundle 包引用与独立上架分离

- 状态：已接受
- 日期：2026-08-30

## 背景

GitHub 市场的 bundle 原先只能引用顶层已上架条目。发布一个组合就必须同时展示所有成员，
把独立管理和独立推广绑定在一起。只在 Renderer 删除成员会丢失详情、安装参数、更新检测和来源身份。
用户希望通过 marketplace 顶层是否注册来决定独立展示，而不为此引入 Plugin 或额外的隐藏开关。

## 决策

1. GitHub manifest 增加 `schemaVersion: 2`，成员仍以 `type` / `slug` 定位，允许附带
   `source.path` 指向同一市场根下的现有包。v1 继续可读，但不允许包路径成员；无路径成员仍须在顶层注册。
2. 未注册成员的 `ability.json` 是目录元信息事实源，包含名称、版本、配置版本、分类及翻译；
   类型与 slug 必须匹配引用，版本必须匹配制品。独立上架时沿用顶层元信息和既有包展示合并规则。
   不在成员引用里复制元信息，不在包元信息里内联 `config` 或 `source`。
3. 主进程 catalog loader 先解析全部显式成员，再使用原有各类型包校验和展示加载器统一校验。
   刷新激活、缓存重载、安装都复用此路径。缺包、身份/路径冲突、越界、超限或无效配置导致整源失败，
   不激活部分结果，沿用现有缓存回退。磁盘目录不被自动扫描为能力。
4. 目录同时保留完整的可安装能力集合和顶层 slug 集合；后者派生 DTO 的 `listed`，不作为作者开关或持久化新事实源。
   Renderer 保留所有能力供详情、成员解析、安装及「我的」使用，只在「发现」查询和市场 banner 中过滤未上架成员。
   缺少 `listed` 的旧 DTO 默认可见，云市场不改变。
5. 同一来源的同一 slug 只能有一种类型和一个规范化路径；多个 bundle 可共享同一成员。
   上架状态不参与身份，`github:sourceId:type:slug`、安装台账、禁用状态和现有物理安装轨道保持不变。
   bundle 仍无独立安装状态、不嵌套、不强制安装成员，也不拥有成员凭据或权限。

## 对 ADR-0049 的修订

仅对 GitHub 开放市场，取消“未独立上架的成员只能打入 Plugin”的限制。成员包路径是对现有制品的引用，
不是内联制品，不需要第二套打包格式或安装器。松散组合用 bundle，随 Plugin 生命周期绑定且对用户不可见的
内部资源仍用 Plugin 内聚。云市场的服务端格式及私有 MCP 既有约定不在本次修改范围。

## 备选方案

- 仅前端按 bundle 关系隐藏：无法表达同时上架 bundle 与成员，且仍强制维护顶层成员条目。
- 给每个条目增加 `hidden`：与顶层注册形成两个展示事实源，不能满足不注册就不独立显示的作者模型。
- 在 bundle 中内联完整包或执行安装脚本：引入新安装和安全模型，违反复用标准包的边界。
- 不升级 schema：旧解析器会丢弃未知成员字段，可能错误解释清单；显式版本可拒绝不支持的合同。

## 兼容与验证

新客户端读 v1 和 v2，缓存 state 格式不变；旧客户端拒绝 v2 源，存在旧缓存时继续使用。
应先发布支持本功能的客户端，再切换仓库格式；目标 Desktop 版本为 `0.5.49`，同版本号的旧开发构建也需更新代码。
降级后不保证能读取已经激活的 v2 缓存，但不会卸载本地能力。只改上架位置不提升成员的产物/配置版本，
仍须提升 marketplaceVersion。

单元测试覆盖协议兼容、共享/独立引用、元信息与本地化、路径与大小限制及各类型校验；
临时归档集成测试覆盖同步、真实 Skill 安装升级、禁用状态保留、MCP 准备、缓存重载与失败回退；
真实 Hook 与组件测试覆盖发现/banner 过滤、成员详情导航、安装勾选、应用语言和已安装管理。
