# ADR-0184：更新检查、添加面板分类、图标与运行时版本收尾

## 状态

已接受，已实施。五处问题均已落地并通过类型检查与定向测试；其中「Windows 状态栏图标」
根因是启动器 exe（Go 编译）未嵌入图标，已在打包阶段补上图标写入，需在 Windows 构建上
验证。

## 背景

0.5.97 发布后，用户在 macOS 开发壳与 Windows 构建上又发现五处残留问题，分散在五个域。
这些问题不是同一模块，但都指向「上一轮重构没清干净的尾巴」或「跨平台差异没对齐」。

## 领域模型与问题归类

### 域 A：更新检查（设置 → 通用 → 应用）

| 编号 | 问题 | 根因方向 |
| --- | --- | --- |
| A1 | 更新完成后下方残留 md 更新内容面板 | `GeneralSettingsView` 仍渲染 `UpdateCheckerDetail`（版本号 + 下载/重启按钮 + releaseNote 预览）。这个卡片在「检查更新」打开对话框后是冗余的——对话框里已有完整的更新内容与进度 |
| A2 | 下方重复出现「下载中」按钮 | `UpdateCheckerAction`（顶部）与 `UpdateCheckerDetail`（下方）在 downloading 阶段同时显示下载状态，两处重复 |
| A3 | 下载进度显示 0% | 需确认 progress 事件从主进程到渲染层的链路；0.5.97 已补 `UpdateCheckerAction` 的 progress 透传，但仍需验证下载中是否实时刷新 |

### 域 B：对话顶栏活动面板按钮

| 编号 | 问题 | 根因方向 |
| --- | --- | --- |
| B1 | 活动面板按钮点击后未居中、右侧偏移 | `ChatHeaderPanelAction` 用 `sidebar-minimalistic-linear` + `-scale-x-100` 水平翻转。该图标的字形在 viewBox 内左偏（侧边栏在左），翻转后视觉重心右偏，flex 居中只居中元素盒、居中不了字形 |

### 域 C：添加按钮名称与展开面板分类

| 编号 | 问题 | 根因方向 |
| --- | --- | --- |
| C1 | 添加按钮 hover 名称是「技能」，应显示「添加文件 / 调用指令」等明确名称 | 按钮 title 用的是 `toolbar.add`（「添加」），tooltip 是「可添加文件、技能、连接器、插件、应用」，与旧分类耦合，语义不清 |
| C2 | 展开第一栏分类要按能力页筛选按钮分类，当前分类推翻 | 当前是 skill/mcp/plugin/bundle + 指令，要改为能力页的「技能 / 插件 / MCP / 套装」+「内置 / 全部 / 市场 / 操作」8 种；「连接器」「应用」两个旧叫法删除（统一为 MCP / 套装） |

### 域 D：Windows 状态栏图标

| 编号 | 问题 | 根因方向 |
| --- | --- | --- |
| D1 | Windows 状态栏（任务栏）显示 Electron 默认图标（用户视为「React 图标」） | 窗口/托盘图标都指向 `build/icon.ico`（有效，含 256/48/32/16 四尺寸）。需确认打包后 `resources/build/icon.ico` 是否正确落位，或 `nativeImage` 加载是否在 Windows 上异常 |

### 域 E：Node.js 运行时版本

| 编号 | 问题 | 根因方向 |
| --- | --- | --- |
| E1 | 托管 Node 运行时 22.22.2 需更新到最新 | `apps/desktop/src/main/runtimes/manifest.json` 的 `node.version` 与各平台 `filename`/`dir` 是单一事实源，`fetch-vendor-runtimes.mjs` 从它读版本下载 |

## 决策

### 1. 域 A：设置页只留一行更新入口，删除下方详情卡片

- 删除 `GeneralSettingsView` 里 `updatesDetail`（`UpdateCheckerDetail`）的渲染——更新内容与进度由「检查更新」打开的对话框统一承载；
- 设置页「应用」行只保留 `UpdateCheckerAction`：版本介绍按钮 + 检查更新按钮（下载中在该按钮上显示实时百分比）；
- `UpdateCheckerDetail` 组件本身保留在 theme-ui（供其他宿主复用），只是不再在设置页挂载；
- A3 进度：确认 progress 事件链路，必要时补一条「下载中百分比随时间前进」的断言。

- **后续反转（v0.5.99）**：删除详情卡片后，更新完成时的「重启」入口只存在于随下载进度
  变化的对话框里，用户一关对话框就找不到重启入口。于是把 `UpdateCheckerDetail` 卡片恢复了
  回来，作为下载与重启的唯一常驻入口（见 v0.5.99 发布说明）。

### 2. 域 B：活动面板按钮不再翻转字形，改用对称图标

- `-scale-x-100` 翻转是「字形左偏」的放大镜，翻转后重心右偏。改用本身对称或表示「右侧面板」的图标（若图标库没有合适的，则去掉翻转、用正图标 + 微调），保证字形视觉居中；
- 保留 `flex size-4 items-center justify-center` 包裹，只换图标来源。

### 3. 域 C：分类对齐能力页筛选，按钮名称明确

- 分类键与顺序（平级 8 格）：`skill`（技能）、`plugin`（插件）、`mcp`（MCP）、`bundle`（套装）、`builtin`（内置）、`all`（全部）、`market`（市场）、`operations`（操作）；
- 图标与文案复用能力页 `ABILITY_TYPE_ICON` / 来源文案，删除「连接器」「应用」两个旧叫法；
- 「文件/附件」不再单独成类（输入框内已有附件按钮），「操作」即原「指令」分类（压缩上下文等会话操作）；
- 添加按钮 title 改为「添加文件或调用指令」（中英文适配），tooltip 同步去掉旧分类列表。

### 4. 域 D：Windows 图标先定位后修，不改运行时逻辑的猜

- 先核对打包产物 `resources/build/icon.ico` 是否存在、`BrowserWindow`/`Tray` 的 icon 加载是否为空；确认是「路径没落位」还是「加载异常」，再定点修，不以猜测直接改；
- 图标资源（`build/icon.ico`）本身有效，不重新生成。

### 5. 域 E：Node 运行时升级到 22 线最新 patch

- `node.version` 22.22.2 → 22.23.5（Node 22 LTS 线最新，2026-11-11 发布），各平台 `filename`/`dir` 同步；
- 同版本线升级，兼容性风险最低；升级到 24/26 LTS 属跨版本变更，不在本次范围（若后续需要单独评估）。

## 备选方案

- **A1 保留 `UpdateCheckerDetail` 但只去掉 md 预览**：仍有一份下载/重启按钮与顶部重复，治标不治本。
- **C2 分类按类型/来源两个维度分成两组下拉**：更贴近能力页筛选的层级，但用户明确要「平级 8 格」，且添加面板是窄栏，两级下拉交互更重。
- **E1 升级到 Node 24/26 LTS**：更「新」，但跨大版本可能引入 breaking change，需单独回归。

## 后果

- 正面：更新入口收敛、分类与能力页一致、图标跨平台正确、运行时跟进最新 patch。
- 代价：域 C 分类结构重构需同步改目录模型与测试；域 D 需 Windows 包验证。
- 兼容性：分类键变更影响收藏/高亮持久化（按 `${category}:${id}` 记），老收藏键会失效，需在迁移里容忍未知分类键。

## 验证

- 域 A：设置页「应用」行只有两个按钮；下载中按钮显示前进的百分比（组件测试）；无 `updater-detail` 节点。
- 域 B：活动面板按钮字形居中（组件测试断言 icon 节点不再带 `-scale-x-100`）。
- 域 C：分类键为 8 种且顺序正确；「连接器」「应用」不再出现；添加按钮 title 明确（中英文）。
- 域 E：manifest 版本与 filename/dir 一致（已有 runtime-archive-installer 测试覆盖）。
- 本次**不提交不推送**，先跑通类型检查与定向测试。
