# ADR-0137：手机端引用技能，协议新增 `skill.list`

## 状态

已接受（在 ADR-0128 的协议 v2 上增量扩展，不改变已有请求、事件的形状）

## 背景

iPhone 客户端要在输入框里引用技能：点附件按钮里的「技能」，从列表里挑一个，发送时带上。

- 桌面输入框引用技能只是在文字里写 `@skill:名字`（场景写 `@scene:名字`，名字带空白时加引号），模型按名字查技能。`session.prompt` 本来就原样转发文字，发送这一侧不需要改协议。
- 协议里没有列技能的方法。桌面的技能列表按 cwd 扫描，带出项目自己的技能；新会话页在发送前还没有会话，只有选中的项目。
- 桌面选择器的可见性规则与「使用次数优先」的排序写在渲染进程里，主进程用不了。

## 决策

- **协议新增 `skill.list { cwd? }` → `{ skills }`**，不需要 `sessionId`。每条 `RemoteSkillOption` 只有 `name`、可选的 `alias`（与 `name` 相同时省略）、`description`（截到 400 字符）、`type`（`skill` / `scene`）和 `source`，图标、插件 id、展示策略都不下发。
- **`cwd` 只接受 `project.list` 里的项目**，其他值（包括「对话」根目录）一律按全局列出，手机不能让电脑去扫描任意路径。
- **过滤和排序在电脑上做**，规则与桌面输入框的技能选择器相同（`skillPicker` 可见性，按使用次数、来源、最近使用和名字排序），最多 500 条。排序代码移到 `apps/desktop/src/shared/skill-ranking.ts`，主进程与界面共用。
- 手机把选中的技能拼成开头的 `@skill:` / `@scene:` 记号，再走 `session.prompt`；消息气泡把这些记号解析成胶囊显示。
- TypeScript 包、JSON Schema、`VettaKit` 同时更新，联调夹具同步支持。

## 备选方案

- **按 `sessionId` 查**：可以复用会话的 cwd，但新会话页没有会话，只能进了会话才能用技能。
- **只列全局技能**：最简单，但项目自己的技能在手机上用不了。
- **把原始列表下发，由手机过滤排序**：要把可见性规则和排序各实现一遍，还得下发使用统计，规则一改两端就不一致。
- **手机只在文字里插入记号，不做胶囊**：会露出原始记号，删掉一半就成了无效引用。

## 后果

- 旧的手机端不发送新请求，照常可用；旧的桌面端以 `invalid_frame` 拒绝未知方法，新手机端据此提示更新桌面端。
- 列表反映的是请求那一刻的技能与使用统计，手机按项目在内存里缓存，每次打开时刷新。
- Android 客户端暂未接入，可以直接复用这个方法。
