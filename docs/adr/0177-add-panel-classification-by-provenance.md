# ADR-0177：添加面板的分类由数据来源决定，未映射来源有兜底

## 状态

已实施（2026-11-15）。补齐 [ADR-0175](./0175-input-bar-add-panel-two-columns-with-preview.md)
留下的分类缺口：新增来源（能力市场新上架的技能、新装的连接器、以后才能读到的插件与应用）
落到哪里、以及读不到时会不会消失。

## 背景

ADR-0175 把面板定为「固定五类 + 收藏 + 操作」，但只规定了**布局**，没有规定**归属**。
实现时按各自域现有的字段各自映射，于是出现了三种不确定性：

1. **技能按 `SkillInfo.source` 字符串分桶**，映射表里没有的来源（新安装渠道、新 provider
   类型）当时 fallback 到「我的」——把别人发布的技能说成用户自己的。
2. **连接器只认内置预置**：`isConfigured` 里要求 `matchBuiltinMcpPreset(name, config)`
   必须命中，于是用户自己手写进 `mcp.json` 的 server、以及以后由能力市场装进来的 MCP，
   在面板里**根本不出现**。「装了但看不到」比「装失败」更难排查。
3. **插件与应用没有数据源**：分类常驻但永远空。这本身可以接受（空态是明确的），但当时
   没有写下「等数据源接入后按什么规则归类」，等于把同一个问题推给下一次。

这三条的共同点是：**分类是产品契约，不是渲染细节**。写成「按来源字符串 if-else」之后，
每加一个来源就要改面板代码，而漏改的表现是条目静默消失或错位。

## 决策

### 1. 分类只由「数据来源」决定，不由条目类型推断

每一类条目的归属来自**它所在领域的权威字段**，面板只做投影：

| 分类 | 归属依据 | 说明 |
| --- | --- | --- |
| 文件 | 工具行注入的三个动作 | 固定三项，不随安装变化 |
| 技能 | `SkillInfo.source` → 分组 | 见 §2 |
| 连接器 | `mcp.json` 里的 server key | 见 §3 |
| 插件 | 已安装插件清单（当前未接入） | 见 §4 |
| 应用 | 插件声明的应用入口（当前未接入） | 见 §4 |

**不按条目名字、图标或安装路径猜类别**：同一个技能可能由插件提供，也可能由用户手写，
名字没有语义；只能问它来自哪个域。

### 2. 技能：归属来自「谁装的」，不是「文件落在哪」

扫描器（`skill-loader`）只能报告**文件落在哪个目录**——它给几乎所有技能都是 `path`。
「从市场装的」「用户自己放的」「插件贡献的」这些信息只存在于**清单**（`skills-manifest.json`
/ 插件 manifest / 内置 `skills-manifest.json`）与插件路径贡献里。因此主进程组装 `SkillInfo`
时必须按这个优先级取来源：

1. 文件在内置技能目录内 → `builtin`；
2. 文件落在某个插件的 `agent.skillPaths` 下（且该插件授予了 `agent.skills.control`）→ `plugin`；
3. 否则取技能清单里登记的 `source`（`market` / `custom`）；
4. 都没有才用扫描器给的目录类型（`path` / `agents-user` / …）。

先把扫描器类型当来源，会让**市场安装的技能全部算成「我的」**——这正是实机上「分类识别不全」
的主因，与 ADR 表述的「按来源归类」在字面一致、在语义上错位。列表过滤（`shouldListSkill`）
也必须用同一份来源判定，否则市场技能的停用状态会失效。

同一个错误在面板侧还有一处：`provenance.kind === "native"` 时曾把「非 project 的 scope
一律折叠成『我的』」，即使主进程已经把 scope 写成 `market` 也照样落进「我的」。
现在 native 分支统一走 `SKILL_GROUPS` 映射表，新增 scope（未来的安装渠道）加一行即可。

实机结果（开发环境，104 条技能）：内置 2 · 插件 1 · 我的 95 · 市场 6。

**内置技能的数量由内置清单决定，不由面板决定**：`packages/skill-presets/skills-manifest.json`
列出 3 个，其中 `publish-ability` 标记 `requiresCloud: true`，在未开启云端的构建里被
`filterForBuild` 整体过滤——这是刻意的 lite 行为，不是分类丢条。面板因此显示 2 条内置技能。

### 2.2 面板与能力页共用同一份组装结果（2026-11-15 收敛）

前面的规则仍然是「面板自己按来源分桶」，实机暴露出两个必须收敛的问题：

1. **面板会列出能力页没有的东西**：连接器直接读 `mcp.json`，于是用户手写的
   `cloudflare-api-2` 这种重复 server 也出现在面板里，而能力页按能力条目去重后只有两个。
2. **图标与显示名不一致**：面板自己解析图标，内置 Skill 走不到 `builtinSkillIconUrl`
   的兼容映射，市场条目也拿不到预置名，出现「能力页有图、面板没图」。

因此面板不再自己组装，改为调用**能力页同一套 `build*Abilities()`**：

- 数据：`abilities.getLedger()` / `skills.getMarketManifest()` / `skills.list()` /
  `plugins.listAll()` / `mcp.get()`（只读本地安装态，不拉市场快照）；
- 条目：`buildSkillAbilities` / `buildMcpAbilities` / `buildPluginAbilities` /
  `buildBundleAbilities`，取 `installed && enabled`；
- 分类由 `type` 决定（skill/mcp/plugin/bundle），**分组由能力页的判据决定**：
  `isBuiltin` → 内置（含 skill-presets、通用 Agent Skill、**系统插件**）、
  `isCustom` / 清单 custom → 我的、市场安装 → 市场、插件贡献 → 插件；
- 名称与图标直接取能力条目（`title` / `icon`），面板不再解析。

结果（开发环境）：技能 `内置 2 · 我的 89 · 市场 6`；连接器 2 条（`Cloudflare 文档` /
`Cloudflare API`，不再是三个原始 key）；插件 `内置 11 · 已安装 3`，图标齐。

同一个条目的分组标题也改为按 **groupId** 解析：同一分类里可以同时有「内置」与「已安装」，
按分类取标题会把内置组错标成「已安装」。

### 2.3 「全部」格与预览页的清理（2026-11-15）

- **新增「全部」格**：紧挨「收藏」，跨分类列出能力页有的所有条目（文件 / 技能 / 连接器 /
  插件 / 应用各带分类头）。它成为面板的默认视图——用户不必先猜东西属于哪一类。
  图标用原来的星芒（`magic-stick`），「技能」改用 `code`，避免两格撞形状。
- **删除预览页的说明句**：「点击这一行即可插入；输入框里会留下一个提示词标签…」这类解释
  在多处重复出现，占着一行高度却没有新信息；插入行为由行本身承担，不需要再解释一遍。

### 2.4 与能力页的「同一份清单」补齐三处（2026-11-15 第三轮）

1. **连接器只列用户自己的 server**。台账 `origin = github-marketplace` 的、或命中内置
   预置的连接器属于能力页「公开」分区，个人分区里没有。面板此前把它们也列出来，于是出现
   「能力页没有 `Cloudflare 文档 / Cloudflare API`，面板却列了两条」——名字不是编造的，
   但**来源分区错了**，用户看到的就是不一致。现在按这两条显式过滤。
2. **图标判定复用能力页规则**。`AbilityIcon` 分三态（图片 URL / `solar:xxx` 名称 / 空），
   面板此前用「像 scheme 就是图片」的宽判定，把 `solar:xxx` 塞进 `<img>`，加载失败后落到
   灰色占位符——实机整列灰块就是这么来的。现在 `splitIcon` 直接调
   `isRenderableImageIcon`，`AddPanelIcon` 再分三态渲染；无图标的**技能**用
   `SkillDefaultIcon`（与能力页相同），不是分类图标。
3. **形态回到「输入卡片长高」**。面板与卡片是同一个圆角容器：底色用卡片同一个 token
   `--input-bar-bg`（跟随主题，不写死色值）、上圆角 20px、底边压过卡片上描边 1px、
   展开时卡片上描边让位。此前的「留 8px 间隙 + 毛玻璃浮层」在深色主题下与卡片形成两块
   不同亮度的面，看起来像另一块面板，而不是输入框自己抬高了。

### 2.5 接缝对齐与移除快捷键行（2026-11-15 第四轮）

- **接缝错位**：面板锚点已从「卡片内容盒」换成「外层容器」，但定位用的还是
  `-inset-x-px`（早期锚在内容盒时要补的 1px）。多出来的这 1px 让面板左右各比卡片宽
  一像素，接缝处的两条竖线错开半格。改为 `inset-x-0`（左右外边界与卡片完全重合）+
  `bottom-[calc(100%-1px)]`（底边压住卡片上描边那一行），实测面板与卡片均为
  `left=421 / right=1093`。
- **删除底部快捷键提示行**：它是「面板」语汇里的东西，而现在是输入卡片自己长高；
  一行 kbd 提示既与对话框不搭，也挤占列表高度。键位本身仍然可用（`↑↓` / `Enter` /
  `Tab` / `Esc` 由 `onPanelKeyDown` 处理），只是不再常驻说明。
- 工具行右侧加 16px 渐隐：横向滚动时被裁掉的胶囊是渐隐而不是硬切一半。

### 2.6 工具行对齐、分隔线与展开性能（2026-11-15 第五轮）

- **箭头与条目图标同尺寸**：工具行的左右切换按钮从 32px 收到 **24×24 / 圆角 4px**，
  与条目行里的图标盒完全一致（实测左缘同为 478、尺寸同为 24）。此前左缘对齐但尺寸大
  8px，视觉重心偏右，看起来就是没对齐。
- **补回工具行上方的分隔线**：快捷键行删除后，列表与工具行之间少了分层。现在工具行带
  `border-t border-border/30`，且它位于**内容列**内，因此横线正好从左栏竖线右缘开始
  （实测竖线右缘 466、横线起点 466），两者形成 T 形交点；透明度与竖线统一为 `/30`。
- **展开更快**：
  1. 动画从 `clip-path` 揭幕换成 **opacity 淡入 90ms**（裁剪整块上百行的面板每帧都不便宜，
     而用户只感知「是不是立刻出来」）；
  2. 首帧只渲染 12 行，动画结束再补齐（`revealed` + `limit`，用定时器而不是
     `onAnimationComplete`——`AnimatePresence initial={false}` 让首次展开不播动画，
     那个回调根本不会触发）；
  3. 条目数据加**模块级缓存 + 5 秒内不重读**：这份数据要串五个 IPC，过去每次开合都重来
     一遍，是「点了慢半拍」的主因。

实测（开发环境，CDP 计时）：首帧从约 430ms 降到 150–200ms（受机器负载影响有波动），
首帧行数 10、补齐后 108。

### 2.7 分隔线位置、安装技能图标与悬空竖线（2026-11-15 第六轮）

1. **分隔线移到工具行下方**。在工具行上沿画线会把列表最后一项与工具行切开，看起来像列表
   被截断；挪到下沿才表达「面板到此为止」。线仍在内容列内，因此起点正好是左栏竖线右缘
   （实测竖线 466 / 横线 466）。
2. **市场安装的技能补上图标**。这类技能包只在同目录 `ability.json` 里声明 `icon`，
   而 `loadSkillPackagePresentationIcon` 原先只读 SKILL.md frontmatter 的 namespaced
   presentation——于是 `skills.list()` 里 `icon` 为空，面板与 `/` 菜单只能显示默认图，
   能力页因为读市场行反而有图标。现在读不到 frontmatter 时回退 `ability.json`（只认包内
   相对路径）。实机 6 个市场技能图标已正确显示。
3. **默认态不再有悬空竖线**。工具栏在加号后无条件画一条分割线，而附件按钮在面板收起时
   整组隐藏——只剩「添加」一个按钮时，那条线就是加号右侧一根孤线。现在只有面板展开
   （附件按钮真的渲染）时才画。

### 2.1 来源字符串有映射就归位，没有就归「其他」

- 映射表 `SKILL_GROUPS`：`builtin → 内置`、`user / agentsUser / path / custom → 我的`、
  `project / agentsProject → 项目`、`plugin → 插件`、`market → 市场`。
- **未映射的来源归「其他」**，不再 fallback 到「我的」。分类可能不够漂亮，但不会把别人
  发布的技能说成用户自己的。
- 新增来源的扩展方式：在 `SKILL_GROUPS` 加一行。**不加也不会丢条目**——会出现在「其他」里，
  下次打开仍在同一位置。
- 分组顺序 = 条目在清单里首次出现的顺序（`useSkillList` 已按「调用次数 → 类别 → 最近
  使用 → 名称」排好），面板不重排，避免同一条目在两次打开之间换组。

### 3. 连接器：能读到配置就出现，预置只影响外观

- `mcp.json` 里**未禁用**的 server 全部出现在「连接器」分类；
- 内置预置（`matchBuiltinMcpPreset`）只用于更好看的名称与图标；**没命中预置时用 server
  key 作标签、图标退回分类图标**，不因此隐藏；
- 命中预置时仍要求必填密钥齐全（预置自己声明的约束）；没有预置则没有「必填密钥」概念；
- 不查 OAuth 授权状态（会引入异步跳变），未授权时由对话链路报错。

这条改掉了「装了自定义 MCP 却在面板看不到」的静默失败。投影抽成纯函数
`projectConnectorItems(servers, translate)`，分类契约因此可以被单测直接锁住。

### 4. 插件：已安装且未禁用；应用等读取接口

**插件已接入**（`useAddPanelPlugins` → `window.astravia.plugins.listAll()`）：
在面板里出现的条件是「已安装 + 未禁用」，按名称排序；名称与描述是 manifest 里的
`%key%` 目录键时按插件自己的 catalog 解析（直接显示原文会出现裸 `%name%`，实测如此）。
点插件行不插入文本（它没有插入语义），而是打开预览说明它是什么、它提供的技能在哪一类。

**应用**仍没有读取接口，分类常驻、内容为空态。接入时按以下规则：

- **应用**：归属由**提供它的插件**给出（`capability` 注册表里的 app 条目），不是独立目录；
  插件被停用时它的应用一并从面板消失，与插件的生死绑定（同 ADR-0040 的「插件内聚」判据）。
- 未发布 / 下线的应用仍然列出，但标明状态，位置不跳。

### 5. 新增分类的门槛

加第六类（例如「知识库」「MCP 资源」）需要同时满足：

1. 有独立于现有五类的**数据来源**（不是某一类的子集）；
2. 用户会「往这条消息里加」它（面板的动作语义是插入，不是管理）；
3. 有一个稳定的键可以记收藏。

否则并入现有分类的分组，不新增轨道格——轨道格是固定位置，加一格就挤掉其它格的可达性。

## 备选方案

- **按数量动态决定分类可见性**：同一类在两次打开之间换位置，违反 ADR-0156/0175 的固定顺序。
- **未知来源并入最近的一类**（例如「插件」）：猜错的代价是把别人的技能算成插件贡献，
  而「其他」只是不够具体。
- **连接器继续只认内置预置**：这正是本 ADR 要修的静默失败；预置是展示层便利，不该当准入门槛。
- **等数据源齐了再统一定义插件/应用归属**：分类契约会再次散落在实现里，本次定下规则成本几乎为零。

## 后果

- 正面：新上架的技能、新装的 MCP、新启用的插件会**自动出现且位置正确**；不会静默消失；
  分类契约可测（`add-panel-catalog.test.ts` 覆盖未知来源与 provenance，`useConnectorGrid.test.ts`
  覆盖无预置 server，`useAddPanelPlugins.test.ts` 覆盖启用过滤与 `%key%` 名称解析）。
- 代价：多一个「其他」分组（只有出现未知来源时才有条目，空分组不渲染）；自定义 MCP 的
  展示名就是它的 key，比预置名朴素——要更好看需要补预置，那是内容问题不是代码问题。
- 已知限制：应用仍是空态（等 app 条目读取接口）；面板不展示 MCP / 插件的启用开关，
  那是设置页与能力广场的职责；插件行点击只打开预览，不提供启停入口。

## 验证

- `add-panel-catalog.test.ts`：未知来源归「其他」、`market` / `plugin` 各自归位、
  分组不因数量重排。
- `useConnectorGrid.test.ts`：无预置的 server 出现且标签为 key、禁用的不出现、
  命中预置时仍用预置名。
- `useAddPanelPlugins.test.ts`：停用的插件不出现、按名称排序、`%key%` 名称按 catalog 解析。
- 面板层（`CommandPanelView.test.tsx`）：固定五类 + 收藏 + 操作共七格，空分类显示分类空态。

实机核对：插件分类已列出本机 8 个启用插件（`从外部应用打开` / `飞书` / `构建 Apple App` /
`脚本` / `浏览器操作` / `媒体查看器` …），名称不再是 `%name%`。
