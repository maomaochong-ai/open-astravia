# ADR-0174：输入栏工具栏里泄漏的注释文本与宽度分配

## 状态

已接受并实施。修复会话页 / 新会话页输入卡片的两处可见缺陷，与 ADR-0165 的会话界面
范围相邻，但不改变其决策。

## 背景

输入卡片出现三个症状，用户截图里同时可见：

1. 工具栏里凭空多出一段二百字的说明文字（就是本文件下面那段「权限模式…」的注释本身），
   被渲染成窄列、把正文压住；
2. 模型名「DeepSeek-V4.1-Flash」被语音与发送按钮盖住；
3. 卡片被撑得过高（空态 150–342px），工具栏控件浮在卡片中部而不是底部。

实机测量（开发版，`1280×799` 与 `760×780`）：

| 元素 | 修复前 | 修复后 |
| --- | --- | --- |
| `toolbar-leading` | 578×96（另有 201×288） | 35×28 |
| `toolbar` | 108–300 | 51 |
| `input-card` | 150–342 | 93 |
| 模型触发器右边界 / 发送按钮左边界 | 1188 / 1104（溢出 84px） | 425+88 / 513（不重叠） |

## 决策

### 1. 根因是 JSX children 位置的块注释

`InputBarLeadingActions` 里一段解释「权限模式为什么在模型菜单底栏」的注释写成了
`/* … */`，而不是 `{/* … */}`。**在 JSX children 位置，裸的块注释不是注释，是字面文本**，
于是这二百字连同换行被当成一个文本节点塞进工具栏：

- 它自己把工具栏撑到 96–300px 高、卡片跟着变高，控件因此居中看起来「浮在中间」；
- 它占满左侧工具组，把模型选择器挤到只剩十几像素，模型名于是压到语音/发送按钮上；
- 它的内容恰好是一段中文说明，看起来非常像「草稿泄漏进了工具栏」，极易误判。

改为 JSX 注释，并在注释里写明这个坑。这类错误类型检查与 lint 都不报（语法完全合法），
只能靠实机看。

### 2. 顺带把尾部包裹层改成 flex 容器

即使没有泄漏文本，模型选择器外面两层包裹是 `min-w-0 shrink` 的**块级**元素：作为 flex 项
它们可以被压到 0 宽，但块级盒子不会因此裁掉或收缩子元素，里面的 `button` 仍按内容宽度
绘制并向右溢出（实测包裹 0 宽、按钮 145 宽，压住语音与发送按钮）。

改成 `flex min-w-0 shrink` 后，被挤压时触发器会真的收缩并显示省略号，而不是原地溢出。
左侧工具组保持「可收缩 + 横向滚动」（不额外加 `grow`——实测 `flex-1 basis-0` 会反过来把
模型名压成 14px 的省略号）。

## 备选方案

- **只修注释、不动包裹层**：泄漏消失后大部分场景看起来正常，但窄窗口 + 长模型名仍会溢出，
  属于「下次再有人加长模型名就复发」的隐患。
- **给工具栏加 `overflow-hidden`**：把溢出变成静默裁切，模型名被硬切且无提示。
- **给触发器加 `max-w-full`**：包裹层宽 0 时触发器会被算成 0，模型名彻底消失。

## 后果

- 正面：输入卡片回到单行高度，工具栏控件贴在卡片底部；模型名与语音/发送按钮不再互相遮挡；
  宽度分配变成「左侧工具组先让位、必要时横向滚动」。
- 代价：窗口极窄时模型名会省略（保留模型区、牺牲左侧工具的可见性），这是有意的优先级。
- 兼容性：纯布局与注释修正，无公共合同变化。

## 验证

- 实机（开发版，`verify:ui` 附着）：
  - 修复前 `toolbar-leading` 内含草稿样文本节点，`toolbar` 高 300；修复后文本节点为空、
    `toolbar` 高 51、`card` 高 93。
  - 宽度矩阵 `1280 / 1000 / 820 / 760`：模型触发器右边界始终小于发送按钮左边界，
    且不超出卡片右边界（修复前 1280 宽度即溢出）。
- `bun scripts/quality/run-vitest.mjs --run --config apps/desktop/vitest.config.ts <input-bar 目录>`：
  26 个文件 / 91 条用例通过。
- `bun run check:quick -- <改动文件>`：lint 与架构守卫通过。
- 限制：jsdom 不计算布局，也不能表达「注释被当文本渲染」，这条回归无法用单元测试锁住；
  改为上面的实机测量矩阵，并在发布说明里写清用户可见变化。
