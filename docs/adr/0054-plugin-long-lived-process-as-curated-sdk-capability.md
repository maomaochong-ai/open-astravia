# 插件长驻进程做成通用策展 SDK 能力，而非系统插件专供后门

「Vetta UI Design」需要为每个打开的 .vetd 起一个 vite dev server（ADR-0053），但现有 `ctx.command.run` 是一次性 execFile（~120s 上限），跑不了长驻进程。我们决定在插件 SDK 上新增**通用**的长驻进程能力（拟 `ctx.command.spawn`：启动/停止/退出事件/端口分配，返回 Disposable 随插件卸载统一清理），与 `command.run` 同一治理模式——清单 `commands` 声明二进制名 + 新权限 + 用户可在设置关闭——而不是宿主内部只对本插件开口的专供 API。

理由：SDK 的既有哲学是「策展能力出口 + 权限门控」，系统插件与普通插件刻意共用同一套 SDK 与清单（ADR-0024）；专供后门破坏这一致性，且下一个需要本地长驻服务的插件（本地预览服务器、语言服务等）出现时还得重做。代价是要设计公开 API 面（进程生命周期、端口管理、崩溃重启语义），作为独立宿主工作项先行。
