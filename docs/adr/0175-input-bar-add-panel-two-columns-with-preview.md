# ADR-0175：输入框「添加」面板改为两栏浮层，引入收藏与整页预览

## 状态

已实施（2026-11-15，同日修订一次）。取代 [ADR-0156](./0156-capability-add-entry-and-sections.md)
的 §1 词汇与 §3 面板结构；入口文案、分类顺序、以及「分类投影、不新增存储与权限」这三条
从 ADR-0156 继续有效。

**修订记录（2026-11-15，实机验收后）。** 初版是三栏（轨道 ｜ 列表 ｜ 详情栏）。实机验证发现
右栏这套设计有四个问题，因此改为两栏 + 整页预览：

| 初版问题（实机观察） | 修订 |
| --- | --- |
| 右栏只有 232px，长描述被截成两三行；名称与来源在列表与右栏各出现一次 | 详情改为**整页预览**（占满中栏、带返回），描述完整可读、可选中复制 |
| 右栏底部那颗「插入到输入框」与「点行即插入」重复，且是面板里唯一一颗实心主色按钮，在玻璃表面上非常扎眼 | **删除**。插入只有一条路径：点列表里那一行 |
| 行内「详情」按钮点开只是换右栏内容，用户看不出点与不点的区别 | 「详情」按钮打开整页预览，是明确的视图切换 |
| 分类轨道固定五格，其中插件 / 应用两格永远为空 | 轨道**只渲染真有条目的分类**（由目录内容推导）；插件与应用暂时不出现 |

其余修订：行高 28 → 32（有图标后 28 太挤）；分类图标必须彼此可辨（原 `code-scan` /
`widget` / `widget-2` 在 16px 下都是四宫格）；行首图标缺失时用分类图标兜底。

**第二次修订（同日，第二轮实机验收）。** 第一版两栏的四个残留问题：

| 问题 | 修订 |
| --- | --- |
| 轨道只渲染「有条目」的分类，结果所有技能都堆在「技能」一格，连接器/插件/应用根本看不到 | 恢复**固定五类 + 收藏**：分类位置恒定，空的分类留在轨道上、内容区显示该分类的空态 |
| 行与行之间没有间距，圆角贴在一起像一条长块 | 行容器 32px + 行间 2px、圆角 8px；行首图标放进 24px 圆角底（6px） |
| 「选中的第一行」与「划过的行」分不清，而且默认就有选中项 | **默认没有选中项**（下标 -1）：这个列表不是「当前值」，默认选中会被读成「已经选好了」；选中只由键盘产生 |
| 列表自己来回跳 | 去掉窗口化（见下），并让滚动只作用于列表容器自身 |

另外两处观感修正：面板与输入卡片的间距 8 → 12px；轨道与内容之间、预览页之间不再画分隔线
（靠间距与明度分层），线条少了也就没有「线在交点处断开」这回事。

**第三次修订（同日，第三轮实机验收）。** 六处调整：

1. **压缩上下文不再是固定头部**，而是左栏「操作」格下的一行：它本来就是一个可选动作，
   与其它条目同构（图标 + 名称 + 右侧说明）。左栏因此多一格「操作」，与五类同档对齐。
2. **行改用小圆角**（6px；图标底 4px），并保持 2px 行间距。
3. **快捷键行与工具行不再套外层圆角底**：它们是一个整体面板里的两行，加一层圆角背景反而
   像两个独立控件；现在只有文字/按钮本身。
4. **快捷键曾经按了没反应**，根因是焦点常在编辑器里、编辑器在 capture 阶段就
   `preventDefault`，全局快捷键栈见到 `defaultPrevented` 直接放弃。现在面板在 document
   capture 阶段自行接管 ↑↓ / Enter / Tab / Esc / ←（面板开着时这几个键的语义就是「在面板里
   选东西」），并显式无视 `defaultPrevented`。
5. **点左栏后列表「回跳」**：换分类时沿用上一类的 scrollTop。现在列表按分类重置（用 key
   重建），换分类一定从顶部开始。
6. **左栏图标之间不再画水平分割线**，改用间距。能力广场入口留在左栏，作为**第一格**
   （轨道底部会被末尾分类挤压、与最后一格重叠，顶部永远是空位）。

**第五次修订（工具行与快捷键位置）。**

- **快捷键提示移到最底部一行**，工具行在它上方：先看得见「能点哪些工具」，再看得见
  「键盘怎么用」。
- **轨道加分隔与上下切换**：左栏与内容区之间补一条 `border-border/30` 的细分隔线（原来
  完全无线，两块内容靠得很近时看不出是两栏）；轨道两端各加一个上下切换按钮，规则同工具行
  （只在那个方向还有内容时出现），解决无触控板时无法滚动分类的问题。
- **快捷键行上方加细分隔线**（`border-border/25`）：它与工具行是两种信息（操作 vs 提示），
  没有分隔就糊成一块。
- **工具行与条目图标左对齐**：切换按钮放在行尾（放行首会把整排胶囊推右、破坏对齐），
  左内边距调到实测 10px，使胶囊左缘与列表行内图标左缘同为 477px。
- **切换箭头常显、逐格步进、换成双箭头**：只在溢出时出现等于让无触控板的用户不知道
  这里能翻。现在两端常驻（到顶/到底只降到 40% 不透明度，位置尺寸不变），点一下走一格
  （左栏 36px、工具行 34px），图标统一换成 `double-alt-arrow-*`，与相邻格同尺寸同配色，
  **不额外弱化**。
- **竖线与横线的交点**：把工具行与快捷键行从「与两栏并列的同级」移进内容列，左栏边框因此
  一直画到面板底部，快捷键行那条横线正好从竖线右缘开始——形成 T 形交点，不再出现缺口。
- **工具行加左右切换按钮**：一排插件/内置动作经常比面板宽，触控板能两指横扫，
  但台式机与不带触控板的笔记本只能靠拖滚动条——而这里为了观感把滚动条藏了。现在两端各
  一个箭头按钮，只在对应方向还有内容时出现，点一下滚半屏。

**第四次修订（同日，间隙问题）。** 面板此前挂在输入卡片的内容盒上，`bottom: 100% + 8px`
是相对**内容盒**算的，于是它贴在卡片顶边上、把卡片上方那一排快捷动作盖住，看起来「没有间隙、
压住对话框」。三处一起改：

1. 面板从 `MessageInput.Content` 里移到输入区**外层容器**（`InputBarView` 的 stack 层，
   与快捷动作条同级），锚点变成整个输入区上沿；
2. 间隙 8 → **8px（相对新的锚点，即整个输入区上沿）**，并把卡片的 `topConnected` 关掉——
   那张「顶边透明、与面板接成一整块」的样式是旧长高形态的残留。最初的 16px 实机看偏松，
   收到 8px：够看出是两层面，又不至于像断开；
3. 高度不再写死 `min(360px, 56vh)`，而是按**实际可用空间**收口
   `max(180, min(320, 卡片上沿 - 16 - 16))`：窗口矮或卡片靠上时面板自己变矮并内部滚动，
   不会一路长到盖住上方的页面内容。

## 背景

ADR-0156 把这条入口定为「一条入口 + 按类型分区」，五类（文件 → 技能 → 连接器 →
插件 → 应用）在**同一个滚动容器**里靠 10px 区段标题区分，键盘是一维索引且只覆盖
可插入的技能。当时每类的条目都是个位数到几十条，这个结构够用。

现在的量级不同了：技能来自插件市场，重装几个插件就是几百上千条；连接器与插件本身也
在增长。三个后果：

1. **分类没有稳定位置**。类别边界是一条区段标题，它随前面内容的长短上下移动。想找
   「插件」必须先滚过连接器宫格与几十条技能，每次打开都要重新找。
2. **没有「常用的那几个」**。用户每次真正插入的是同一两个技能，却要从头找一遍；
   现有的排序（调用次数 → 类别 → 最近使用 → 名称）只能让它们排得靠前，不能把它们
   从上千条里择出来。
3. **列表行背了太多信息**。行里同时放图标、名称、来源徽章、右侧描述，行高 32px，
   一屏只出 5–6 行；描述与徽章在「按名字找东西」这个动作里都是噪音。

同时 ADR-0159 已经为本仓建立了另一套语汇：模型选择器是**三栏浮层**（图标栏 ｜ 搜索 +
虚拟列表 ｜ 右栏），毛玻璃、收藏、上下渐隐、行悬停才出现的附加入口。同一个输入卡片上
挂两个面板，用户会同时看到两套观感。

### 词汇冲突（必须在本轮解决）

ADR-0156 §1 造了 `CapabilityEntry` / `CapabilitySection` / `CapabilityCatalog`。
但本仓 `Capability` 已经被**授权契约**（`docs/capabilities/`、`@astravia-org/capability-sdk`）
占用，见 [CONTEXT.md](../../CONTEXT.md) 的「Capability（授权契约）」词条：它回答的是「某个
subject 能否调用某个宿主能力出口」。而这个面板列的是**可以往这条消息里加的东西**——
文件动作、技能、连接器、插件、应用——既不都是 [[Ability（能力）]]（连接器与文件动作
都不是可分发能力单元），更完全不涉及授权。继续用 `Capability*` 命名，会让两组含义在
同一个 grep 里混起来。

## 决策

### 1. 词汇：AddPanel，条目叫 Entry，且不得占用 Capability

| 术语 | 含义 | 取代 |
| --- | --- | --- |
| `AddPanelCategory` | 面板的五个分类，`files \| skills \| connectors \| plugins \| apps` | `CapabilityKind` |
| `AddPanelEntry` | 可被加到当前消息的一个条目 | `CapabilityEntry` |
| `AddPanelCatalog` | 由各域数据源投影出的「分类 → 分组 → 条目」结构 | `CapabilityCatalog` / `CapabilitySection` |
| `AddPanelFavorites` | 跨分类的常用项集合 | — |

「添加面板」是界面上的正式中文叫法，与入口文案「添加」一致。

**命名隔离是硬约束，不是命名偏好**。本仓已经有两个同族但完全不同的概念，各自的中文与
英文都被占满，第三层概念不能再借它们的词：

| 已有概念 | 归属 | 含义 | 本面板能借用的词 |
| --- | --- | --- | --- |
| [[Capability（授权契约）]] | `@astravia-org/capability-sdk`、`packages/capability-*` | 「某个 subject 能否调用某个宿主能力出口」——Grant、access session、audit | **一个都不能用**。`Capability*` 类型名、`capability` 目录名、`capabilities` 表名都已被占 |
| [[Ability（能力）]] | 服务端 `abilities` 表、desktop 能力广场 | 可分发扩展单元（skill / mcp / plugin / bundle），有 slug、可安装 | 中文「能力」只能用来说广场里的条目（如「能力广场」「在能力广场中查看」），**不能**指整个面板 |
| 添加面板（本 ADR） | `AddPanel*` | 往当前消息里加东西的五类条目 | 全部新增，前缀 `AddPanel` |

因此：

- 中文正式名「添加面板」，**禁止**叫「能力面板」；
- 连接器与文件动作**不叫**「能力」——它们不可分发、不可安装，也没有 slug；
- 代码里所有新增标识符用 `AddPanel*`；`capability-sections.ts` 与
  `CapabilityKind/CapabilityEntry/CapabilitySection/CapabilityCatalog` 在本次一并改名，
  改完后 `apps/desktop/src/renderer` 下**不应再出现** `CapabilityEntry` 一类名字
  （授权契约自己的代码在 main 进程与 `packages/capability-*` 里，不受影响）。
- 落地时用一条 grep 级守卫固定它：`scripts/quality/` 中禁止 renderer 的
  conversation 域出现 `Capability[A-Z]` 标识符，避免下次有人顺手借词。

术语定义同时记进 [CONTEXT.md](../../CONTEXT.md) 的「添加面板（add panel）」词条，
与「Ability（能力）」「Capability（授权契约）」相邻，读者一眼能看到三者的边界。

### 2. 结构：两栏，内容区在列表与预览之间切换

```
列表态                                预览态
┌────┬────────────────────────┐      ┌────┬────────────────────────┐
│收藏│  搜索框                 │      │收藏│ ← 返回                  │
│────│────────────────────────│      │────│ 图标 名称 / 来源·分组     │
│文件│  分组头（无计数）        │      │文件│ 完整描述（可选中复制）    │
│技能│  行：图标 名称  ⓘ ★     │      │技能│ 来源 / 插入方式 / 状态    │
│连接│  ...                   │      │连接│ 一句后果说明             │
│    ├────────────────────────┤      │    ├────────────────────────┤
│    │  ↑↓ ⏎ ⓘ esc            │      │    │  esc / ← 返回            │
└────┴────────────────────────┘      └────┴────────────────────────┘
```

- **默认分类是「技能」**。技能清单是异步来的，打开那一瞬间可能只有文件动作有内容；
  这时先停在第一个可见分类，等技能到位再切回技能——但「自动挑的」这个状态不能清，
  一清就永远停在「文件」。用户手动点过分类后不再纠正，并记住他这次的分类（模块级变量，
  不落盘），重开面板还停在那里。
- 左栏 44px：**收藏在第一格**，其后**固定五类**（文件 → 技能 → 连接器 → 插件 → 应用），
  顺序沿用 ADR-0156。某一类暂时拿不到条目（插件、应用当前就是）时仍然占位，内容区显示
  「插件里还没有内容」这类**分类空态**。分类位置必须恒定——`只显示有内容的分类` 会让同一类
  在两次打开之间换位置，用户每次都要重新找。每格只有图标，名字走原生 `title`。
- 右栏（内容区）：搜索框 + 列表（虚拟化），或预览页。**没有第三栏**。
- 列表态的行是插入目标（点击 = 插入 / 执行文件动作 / 连接连接器）；行尾「详情」打开
  预览。预览页**没有动作按钮**——它只回答「它是什么」。

### 2.1 为什么不用第三栏

三栏是这个仓库既有的语汇（模型选择器，ADR-0159），当初直接沿用。但两者的右栏性质不同：
模型选择器的右栏是**思考档位**，本身就是一个要选的值，必须同时可见；添加面板的右栏是
**只读信息**，而「要做什么」只有一件事（插入）。把只读信息常驻成第三栏，代价是列表少
约三分之一宽度、描述被截断、还要在右栏重复一遍列表里已有的名称与来源。

### 3. 形态：独立浮层，不再是「长高的卡片」

保留现有实现事实：面板本来就是 `absolute` 定位、不参与布局（展开不会把消息列表顶上去）。
本次改的是**视觉归属**：

| | 现在 | 改为 |
| --- | --- | --- |
| 与卡片关系 | 底边压在卡片上描边上，同圆角、同描边，看起来是一块面长高 | 独立浮层，与卡片留 8px 间隙，四角圆角 14px，自带描边与投影 |
| 背景 | 与卡片同色实底 `--input-bar-bg` | `bg-background/40` + `backdrop-blur-2xl backdrop-saturate-150`（与模型选择器同一组取值） |
| 高度 | `min(320px, 40vh)` | `min(360px, 56vh)` |
| 关闭 | 点外部 / Esc | 不变 |

理由：卡片形态切换要求接缝处描边、圆角、底色完全连续，一旦要毛玻璃就没有可连续的
「同一块面」——玻璃必须透出背后的会话内容，而卡片是不透明的。模型选择器已经验证了
浮层这套观感在会话页成立（ADR-0159），两处统一。

### 4. 行：图标 + 名字 + 两个行尾入口

行高 32px，内容 = 分类图标（有真实图标则用真实的）+ 条目名（`truncate`）+ 行尾两个图标。
**顺序固定为「详情在左、收藏在最右」**：收藏是行尾的持久状态（已收藏时星标常亮），放最右
才不随悬停的出现/消失而位移；详情是临时入口，靠内。

三处具体约束：

1. **图标不能缺，而且要分清「class」与「图片」**。技能图标来自市场，常常是相对路径的
   png；第一版只在连接器上区分了图片，技能的 png 被当成 iconify class 塞进 `<span>`，
   整列技能因此在实机上是空白（不是没图标，是图标渲染不出来）。现在在投影时用
   `splitIcon` 把图标拆成 `icon`（class）与 `iconUrl`（图片），条目自己没有图标或图片
   加载失败时退回分类图标（`AddPanelEntry.fallbackIcon`）。
2. **分类图标必须彼此可辨**。16px 下 `code-scan` / `widget` / `widget-2` 都是四宫格，
   一排看过去像三个相同的格子；现在分别是 回形针 / 魔棒 / 插头。
3. **选中与悬停必须一眼分得开，且不能依赖主题主色**。实机第一版用了
   `bg-primary/15` 做选中底——在默认深色主题下是淡靛蓝，看起来像一层灰；在黑白主题下
   `--primary` 是近白 `rgb(228,228,228)`，`primary/20` 与 hover 的中性底亮度几乎相同，
   完全看不出哪一行是键盘选中。现在两者都用同一族中性底、只差档位，再加左侧主色指示条
   与名字加粗：选中 `bg-foreground/12`、悬停 `bg-foreground/6`、指示条 2px、选中行
   `font-medium`。分组头比行小一号、比行淡一档，与行之间留 6px 上间距。

分类切换后靠 rail 的选中态表达「现在在哪一类」，因此**列表上方不再有标题，也没有计数**。

搜索行内部用 flex 一行排布（图标 / 输入框 / 清除键，`align-items: center`），
不用绝对定位 + `top: 50%`：容器带内边距时那个 50% 是含内边距的盒高，图标会比文字低几像素。

### 4.1 悬停不改高亮，也不触发滚动

高亮（`activeKey`）**只由键盘移动驱动**；鼠标悬停只换底色（纯 CSS）。

原因是实机上一个真实缺陷：初版滚动副作用挂在 `activeKey` 上，而 hover 也会改它，
于是鼠标划过一行就触发一次「把高亮行滚进视口」，列表在指针底下自己往下跑，用户看到的是
「自动向下滚动、没有固定」。

现在把「这是键盘动作」显式建模成 `scrollSignal`（每次 `↑`/`↓` 递增），列表只在该值变化时
滚动。同时 hover 不进入 React 状态，省掉每次划过一行的整列重渲染。

### 5. 收藏：跨分类、只存本机

- 一栏第一格「收藏」聚合五类里的常用项，按分类分组；
- 行内星标悬停出现，点击就地加入/取消；已收藏的行星标常亮（琥珀色）；
- 存储沿用 ADR-0159 §4 的口径：键 `astravia-add-panel-favorites`，只存 `category::id`，
  只存本机、不跨设备同步；存储不可用时退化为会话内有效；
- 空态：星形图标 + 「还没有收藏」+ 一句怎么收藏。不放「去逛逛」这类引流按钮。

### 5.1 能力广场只留一个入口

初版有三处入口：rail 底部图标、页脚文字链接、右栏「在能力广场中查看」。三条指向同一
目的地的入口只会让用户猜哪个是「正确的」；两栏修订里第三栏已不存在，页脚文字链接与 rail
图标纯重复，因此**只保留 rail 底部那一个图标**（`title` 提示「能力广场」，去首页）。

条目级的「在能力广场查看」一并删除：预览页不是动作区，要插入就点列表那一行；真要找这一条
的详情读 SKILL.md，那是能力广场自己的职责，不该在输入框里再开一个跳转口。

### 6. 搜索：跨分类，结果按分类分组

用户此刻要的是「哪个东西叫这个名字」，不是「这一类里有没有」。搜索命中按 rail 顺序
分组，分组头只写分类名（无计数）；选中搜索结果后，清空搜索并把 rail 切到该条目所属
分类，避免「选完之后列表里找不到刚选的东西」。

### 7. 键盘：分类进键盘模型

| 键 | 列表态 | 预览态 |
| --- | --- | --- |
| `↑` `↓` | 从「无高亮」开始，第一次按下落到第一项；之后在可见列表内移动，并把高亮行滚进视口 | — |
| `Tab` | 循环切分类（收藏 → 出现的分类 → 收藏） | — |
| `Enter` | 插入 / 执行 / 连接当前高亮项 | — |
| `←` `Esc` | — | 返回列表 |
| `Esc`（列表态） | 关闭面板 | — |

`↑↓` 的索引从「全面板一维」改为「当前列表内一维」——分类不再共享一个滚动容器，
一维全局面板索引没有意义。

**面板打开时没有任何高亮项**，`Enter` 也不作用于任何东西；必须先按方向键。这条与模型
选择器刻意不同：模型选择器必须显示「当前选的是哪个模型」，所以它有默认选中项；添加面板
只是一批可点的东西，默认高亮会被读成「已经选好了」，而且鼠标划过换行时会像焦点在列表里
移动。悬停只换底色（纯 CSS），不进入 React 状态、不触发滚动。

### 8. 不做窗口化，列表一次渲染

条目上限是「一个会话能用的技能 + 文件动作」，实测上百行。全量渲染也就是几百个轻节点，
而窗口化需要自己维护 scrollTop、占位高度与锚点，分组头还要参与高度计算——只要有一点偏差
就表现为「列表自己来回跳」，这正是实机上报的现象之一。因此本列表**取消窗口化**：
`buildAddPanelRows` 只负责拍平与分组，渲染直接 `map`。

真正可能几千条的长列表是模型目录，仍由模型选择器那套窗口化处理（ADR-0159 §5）——两处
不再强求共用同一策略。

### 9. 窄窗口

两栏只占 44px 固定轨道 + 内容区，比三栏窄约 232px，输入卡片在常见窗口宽度下不需要退化。
只有当内容区宽度不足以完整显示一行（约 < 320px）时才有意义地压窄，此时由 `truncate`
承担，不额外引入第三档布局。真正的窄窗口问题是**面板高度**，由 `min(360px, 56vh)` 兜底。

> 分类归属（条目落到哪一类、新来源怎么处理）见
> [ADR-0177](./0177-add-panel-classification-by-provenance.md)。

## 备选方案

- **保留单列，把区段标题做成吸顶**：成本最低，但类别仍然随内容滚动，头上最多浮一条
  标题，长列表里没有「固定位置」；收藏依然无处安放。
- **分类做成顶部横向 tab**：省掉 44px 轨道，但 tab 条会挤占列表宽度，且同一个卡片上
  会同时出现两种分类导航（模型选择器是 rail）。
- **每类各自一个浮层**：切换等于关一个开一个，多一次点击，且无法跨分类搜索。
- **保留卡片形态切换，只加 8px 留白**：留白会让接缝变成一条缝，描边、圆角、底色的
  连续假设全破；要么回到「同一块面」不能有留白，要么就必须断开成浮层。
- **继续用 `Capability*` 命名**：与授权契约同名，是本次最容易避免的长期成本。
- **保留三栏，只把右栏做宽**：列表再少一截宽度，且右栏本质是只读信息，加宽只是把浪费变大。
- **把「插入」做成右栏主按钮**（初版做法）：与点行重复，还在玻璃表面上引入唯一一颗实心
  主色按钮，视觉上喧宾夺主。

## 后果

- 正面：分类位置固定（点一下就到，不再滚）；常用项收敛到收藏；行数从 5–6 提到 9–10；
  条目上千时只渲染可视行；与模型选择器共用浮层语汇，输入卡片上的两个面板不再像两家产品。
- 代价：预览是第二次点击才能看到的信息（列表行里没有描述）；面板高度从 320 提到 360；
  新增收藏存储与一批 i18n 键。
- 数据模型变更：`capability-sections.ts` 从「区段顺序 + 计数投影」改为「分类 → 分组 →
  条目」，并承担搜索结果的跨分类分组。`sectionAppliesFilter` 的语义从「这段是否参与
  过滤」变成「这个分类是否参与过滤」（文件分类仍是直接动作，不参与）。
- 不改变：技能/连接器/插件的发现、安装、权限与存储路径；插件信任模型；输入卡片其余布局。
- 与 ADR-0156 的关系：其 §1 词汇与 §3「单列分区 + 一维全局面板索引」被本文取代，
  其余（入口文案为「添加」、五类顺序固定、catalog 只做投影）继续有效。

## 实施轮廓

按依赖顺序，每一档都能单独验证：

1. **数据层**：`capability-sections.ts` → `add-panel-catalog.ts`，输出 `AddPanelCatalog`
   （分类 → 分组 → 条目）；补 `AddPanelEntry` 的 `category / group / key / icon`。
2. **面板骨架**：`CommandPanelView` 改为「浮层 + 两栏」，内容区在列表与预览之间切换；
   `useCommandPanelModel` 持有分类 / 搜索 / 高亮 / 预览，`Tab` 与 `←` 绑定进
   `useShortcutScope`；压缩上下文那一行拆到 `useCommandPanelCompaction`。
3. **行与列表**：新行组件（名字 + 悬停星标/详情），列表窗口化复用模型选择器的实现；
   分组头去计数。
4. **收藏**：`useAddPanelFavorites`（本机存储、会话内降级），rail 首格与行内星标同源。
5. **预览页**：图标 / 名称 / 来源 / 状态 / 插入方式 / 一句后果说明，加返回；**不放动作按钮**。
6. **窄窗口**：`@container` 三档退化。

## 验证

- 组件/交互（必需）：分类切换、`Tab` 循环、`↑↓`/`Enter`/`Esc`/`←`、搜索跨分类分组、
  收藏增删与空态（收藏页空态与分类空态是两句话）、**悬停不触发滚动**、预览页无插入按钮、
  文件分类不参与搜索、空分类不出现在轨道上。
- 用户常见流程（必需，从输入栏入口进入）：依次「打开面板 → 切到插件 → 收藏一项 →
  打开收藏并插入 → 搜索关键词跨分类选中并插入」，断言最终输入框里的提示词与面板状态。
- 批量条目：构造 > 40 行数据，断言只渲染可视窗口行数。
- 视觉（实机核对）：8px 间隙、玻璃与投影、hover 与选中的层次、分类图标可辨、行图标无缺失。
- 发布说明：本变更属可见行为变化，需在当版 `.github/release-notes/v<version>.md` 的
  「改进」下写一条（分类固定在左侧、新增收藏、列表更紧凑、点条目即插入）。
