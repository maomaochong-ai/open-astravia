# ADR-0160：侧栏与项目域与参照实现对齐（0.5.72–0.5.81）

## 状态

已接受。对应 ADR-0157 登记表中 `sidebar`、`project` 两域的条目，并按批次逐条回填状态。

## 背景

ADR-0157 把参照实现 0.5.72→0.5.81 的 213 条可观察行为逐条入表，状态从「待对齐」起步。
B1（样式与文案）、B2（顶栏按钮组）、B3（模型选择三栏）已完成，本批负责剩下两域里
改动面最大也最容易被搁置的一组：

- **能力缺口**：「管理会话」面板在本仓完全不存在。侧栏只能逐条右键会话，几十上百条历史
  既搜不到也删不快。这是本批唯一的「新增能力」，其余都是形态对齐。
- **结构差异**：「添加项目」在本仓是「下拉菜单 + 新建对话框 + 远程选择对话框」三件套，
  参照实现在 0.5.75 把它收成一个居中 Splash 分步流程，并新增了「从 Git 仓库导入」。
- **形态差异**：项目详情页的会话列表与指令切换贴在背景上、更新提示占据整条底栏、
  「更多」二级弹层还是旧的小圆角描边样式。

## 决策

### 1. 新增两个 Splash 原语，面板不再各写一套外壳

`packages/theme-ui/src/overlays/` 新增 `SplashPanel`、`SplashParts`（输入头部 / 标题头部 /
底栏 / 提示行 / 步骤过渡）、`SplashOptionRow`。它们与 `CommandMenuView` 共用同一套外观参数
（`bg-background/70` 遮罩、`rounded-2xl` + `border-border/80` + `shadow-2xl` 面板、
`command-menu-sheen` 高光），因为本仓的 `⌘K` 面板就是这套外观。

自己 portal 到 body：宿主可能把面板挂在侧栏这类带 `transform` 的祖先里，
`fixed` 会相对祖先定位，面板就缩在侧栏里了。

**未做**：把 `CommandMenuView` 也改成基于 `SplashPanel`。它同时是
「弹出层蒙层统一」那批的工作面，两批同时改同一个文件会互相覆盖；本次只新增原语并由两个
新面板使用，`⌘K` 面板留给那一批收口。

### 2. 「管理会话」面板

三步都在同一个 Splash 里（`list` / `menu` / `rename`），只换头部与内容：

- 列表按标题做**子串**过滤（不区分大小写），保持侧栏的置顶 / 时间序，命中区间交给行组件高亮。
  子串而不是模糊匹配：这里要的是「快速找到并删掉」，可预期比聪明更重要。
- `Control+X` 快速删除（不再逐条确认）、`Control+K` 打开更多操作、`Tab` 在标签页间循环。
  删除后选中项落到相邻一行，可以连按着删。
- 更多操作复用侧栏右键菜单的同一批 atom 与接口（置顶、重命名、在访达/资源管理器中打开、
  移动到标签、删除），不另起一套。
- 唯一保留逐条确认的分支：会话被「同一个会话」模式的自动化绑定时，删掉会让自动化暂停。
- 标签页只给「对话」档：项目内会话没有标签，且至少要有一个标签才有切换意义。
- 打开面板时对未展开的项目主动 `loadSessions(cwd)`，否则面板是空的。

**长列表**：超过 80 行才窗口化，行高固定 36px，按滚动位移直接算可见区间
（`packages/theme-ui/src/project/manage-sessions-window.ts`），与模型菜单的
`computeVirtualRange` 同一套算法、不同阈值。没有引入 `@tanstack/react-virtual`：本仓已有
自算区间的成熟做法，再引一个运行时依赖不划算；80 以下全量渲染也保住了原生滚动与焦点行为。

### 3. 「添加项目」收成一个分步 Splash，并支持从 Git 仓库导入

入口列表是第一步，新建 / Git 导入 / 远程主机各自是二级步骤；「打开项目」「导入项目」仍是
原生对话框，点了就关。原来的 `AddProjectMenuPopover`、`AddProjectMenuItem`、
`RemoteProjectPickerDialog` 及对应的 theme-ui 视图一并删除——它们被同一个 Splash 取代，
留着就是两套入口。

远程主机步骤保留本仓原有的「去登记主机」出口（`remotePicker.openSettings`）：参照实现
只写了空态说明，本仓原先可以直接跳到设置页，那是有用的动作，不对齐成更差的形态。

从 Git 导入需要主进程能力：新增 `main/ipc/project-clone.ts`（`astravia:project:clone` /
`astravia:project:clone-cancel`）与 preload 合同：

- 只放行 `https?://`、`ssh://`、`git://`、`file://`、`user@host:path` 与绝对路径；
  以 `-` 开头的直接拒掉，否则 git 会把它当选项。
- 关掉凭据交互（`GIT_TERMINAL_PROMPT=0`、`GCM_INTERACTIVE=never`）：拿不到凭据就失败，
  由面板把原因展示出来，不让 git 在后台等密码。
- 失败或取消时清掉半成品目录，并把 stderr 的最后几行作为原因返回。
- 克隆成功只是「目录就位」，登记项目仍走既有的 `openProjectPath`，校验与广播只有一条路径。

### 4. 侧栏与项目详情页的形态对齐

- 更新提示从「占一整行的条目」改成底栏右侧一个图标：仅在 `available` / `downloading` /
  `ready` 时出现，实心圆箭头加一圈淡光环；下载中换成转圈并禁止重复点击；就绪时点开更新对话框。
- 「更多」二级弹层压进侧栏（`sideOffset={-40}`）、去掉描边改成 2xl 圆角柔和投影；
  置顶区里被锁定的项（「新会话」）不再列出——它固定在侧栏顶部，列出来只是噪音。
- macOS 经典侧边栏在有 Splash 蒙层时临时换成实色：侧栏半透明是为了透出原生毛玻璃，
  而 `backdrop-filter` 模糊出来的结果也半透明，盖不住底下仍然清晰的文字。
- 项目详情页：会话列表加底色与分隔线、指令切换改胶囊、未编写指令时的空态改成带图标的虚线块。

### 5. 没有跟随参照实现的条目

**移除通知入口**（`44b44c6aa`）：参照实现删掉通知中心是因为它是商业版遗留、没有真实数据。
本仓的站内信接的是服务端 SSE（`useNotificationInit` + `notificationUnreadAtom`）并带未读计数，
删掉入口等于让一个可用功能无法触达。因此本仓保留消息中心，只跟随「更新提示改成图标」这半边。

## 备选方案

- **管理会话继续用 `Dialog`**：本仓多数辅助面板是 Dialog，但这里要的是「搜索 → 改选中 →
  继续删」的连续键盘操作，居中 Splash 与命令面板同一套手感；Dialog 的焦点陷阱会把
  方向键困在按钮之间。
- **引入 `@tanstack/react-virtual`**：省下自己算区间，但只为两个面板新增一个运行时依赖，
  且本仓模型菜单已经用自算区间跑通，同一件事出现两种做法更难维护。
- **把「从 Git 仓库导入」做成独立对话框**：与「添加项目」的其它入口并排会有两套动效与
  两套底栏提示；收进 Splash 后每一步都是「换头部 + 换内容」。
- **删除本仓的消息中心以完全对齐**：会让真实存在的站内信不可达，属于功能降级，不做。

## 后果

- 正面：侧栏与项目页的入口形态与参照实现一致；「管理会话」补上了一个明确的能力缺口；
  「添加项目」从三个跳转点收成一个可连续操作的流程，并新增 Git 导入。
- 代价：`packages/ui` 之外多了一组 Splash 原语要维护；`AddProjectMenuPopover*` 的导出被移除，
  外置插件若引用过这两个 theme-ui 视图会失败（仓库内无引用）。
- 已知限制：
  - `CommandMenuView` 尚未改用 `SplashPanel`（见 §1），⌘K 面板与 Splash 的外观暂时是两份
    相同参数、不同实现。
  - 窗口化阈值（80 行 / 36px 行高）在本机没有真实几百条会话的数据集，只由区间计算的用例覆盖；
    实机观感未做截图核对。
  - 更新图标不再提供「忽略本次更新」：图标只占一行高度，且下载仍由主进程按既有策略推进。
