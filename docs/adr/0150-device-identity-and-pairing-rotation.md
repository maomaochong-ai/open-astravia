# ADR-0150：稳定手机设备记录与配对凭据轮换

## 状态

已接受。调整 ADR-0128 中桌面端将配对记录直接作为设备记录的实现。

## 背景

每次配对都会创建新的中继房间和凭据。原实现以配对 ID 作为设备 ID，重新配对即使按身份公钥删除旧记录，也会丢失设备名称、首次加入时间和权限。手机重装后身份密钥丢失时，桌面端无法自动证明新身份属于原手机，旧记录继续存在。

设备名称、IP 和手机自行声明的随机 ID 都不能证明设备身份。手机系统提供的标识也不保证跨所有卸载、签名、用户和系统重置场景稳定，因此不引入硬件指纹或按同名合并。

## 决策

1. `RemoteControlDeviceRecord.id` 是稳定的设备记录 ID；`pairingId` 是当前唯一有效的配对 ID，负责中继房间、LAN 路径和凭据库索引。设备保留首次加入时间 `createdAt`，当前配对时间单独记录在 `pairedAt`。
2. 待领取配对单独持久化到 `pendingPairings`，不作为设备显示。手机证明持有身份私钥后，在桌面配置的一次更新中将候选配对提交为设备的当前凭据，并移除被替代的配对。相同身份公钥自动沿用设备；名称、用户命名标记和屏幕权限保留。
3. 配对统一使用现有二维码、连接码和手动地址入口，不新增设备行的重新配对按钮或定向替换 API。重装后原身份丢失时仍创建新设备；不自动将不同身份关联，用户可通过既有「解除配对」删除不再使用的旧记录。
4. 邀请创建、取消、提交和撤销串行执行，持久化更新仍使用配置存储的最新状态队列。取消、过期或提交保存失败均不能撤销原配对。手动配对先通过加密消息交付候选凭据，手机实际用候选凭据完成认证后才替换原配对。
5. `RemoteConnection` 在每轮握手成功解密首个会话帧后发出本地 `peer-authenticated` 事件，区分“公钥声明”和“持有私钥”。待领取连接使用独立事件日志，提交后才加入设备共享日志和业务连接集合；其他领取者不能接收或重放该设备的数据。没有新增线协议字段，现有手机的加密 `resume` 即可提供证明。
6. 配对替换后关闭旧 LAN、P2P 和中继连接，停止旧屏幕宿主并移除旧凭据。不向旧连接发送 `device.revoked`，避免同一手机把刚保存的新配对也当成解除配对。用户主动解除设备仍保留既有撤销通知语义。
7. 撤销与待清理凭据 ID 一起落盘。清理完成后删除 `retiredPairingIds` 中对应的任务；清理失败保留任务，在重启恢复时重试。凭据库清理不删除仍被当前设备或候选配对引用的凭据。
8. 启动恢复时合并同一身份公钥的历史记录：沿用最早设备 ID、首次加入时间和自定义名称，使用最新配对凭据；任何历史记录关闭屏幕控制时合并结果继续关闭。不同公钥、仅名称相同或仅离线的设备不自动合并或删除。上次进程留下的未完成邀请失效并清理。

## 兼容和迁移

- 旧配置没有 `pairingId` / `pairedAt` 时分别沿用 `id` / `createdAt`。没有身份公钥的旧“设备”是未领取邀请，启动时撤销。
- 手机配对 URI、凭据格式、加密和消息线协议保持 v2。iOS、Android 无需配合新增协议字段；设置页仍使用无参数的生成邀请入口。
- 运行中的通道、重放序列和屏幕宿主仍按配对生命周期管理，避免旧配对的异步回调作用于同一设备的新连接。
- 新版轮换过凭据后，旧版桌面程序不能正确理解稳定设备 ID 与配对 ID 的区别。降级后需要重新配对；不保证旧程序写回新版设备配置的兼容性。

## 备选方案

- 继续以配对 ID 作为设备 ID，仅隐藏重复行：旧凭据和连接生命周期仍然存在，名称和权限仍会丢失。
- 按设备名称、IP 或未认证的设备 ID 自动合并：无法区分同名手机或伪造声明，会错误转移权限或撤销其他设备。
- 为每台设备额外提供定向重新配对入口：增加了一套用户操作，仍需人工判断身份归属，因此不采用；身份连续时自动更新，身份丢失时沿用普通配对和解除配对流程。

## 验证

服务集成测试覆盖首次配对、同身份重新配对、不同身份保持独立、取消、过期、保存失败、竞争领取、手动凭据交付、重启、历史合并及旧凭据清理。连接合同测试覆盖认证时点、损坏加密消息和共享日志接入。组件测试覆盖设备行操作、普通二维码刷新、失败重试以及没有额外重新配对按钮；配置测试覆盖持久化校验及旧配置读取。
