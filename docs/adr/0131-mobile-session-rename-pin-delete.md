# ADR-0131：手机端重命名、置顶与删除会话，置顶移到主进程

## 状态

已接受（在 ADR-0128 的协议 v2 上增量扩展，不改变已有请求、事件的形状）

## 背景

iPhone 客户端要在聊天页的「更多」里重命名、置顶会话，在会话列表里左滑置顶或删除；置顶要和电脑侧边栏是同一份。

- 桌面的置顶只存在渲染进程的 localStorage（`vetta-sidebar-session-pins`），注释明言「只是本机 UI 偏好」。主进程里的远程镜像读不到，也改不了。
- 删除与重命名的完整步骤（Agent Team 归属校验、「对话」子目录回收、自动化解绑）只写在 `ipc/session.ts` 的处理函数里；置顶和标签的清理只由渲染进程在删除后顺手做。
- 由主进程发起的删除、重命名不会发出会话列表变化，侧边栏要等下次整体重载才看得到。

## 决策

- **置顶由主进程持有**。`~/.vetta/desktop-app/session-pins.json`（`{ schemaVersion: 1, pins: [{ path, pinnedAt }] }`）由 `session-pins-store` 单一写者维护，按会话文件路径记录，语义与原来一致：再次置顶刷新时间，时间单调递增。渲染进程改为镜像：首屏拉取、跟随 `vetta:session-pins:changed` 广播，本地改动先乐观生效再以主进程快照为准。旧版本留在 localStorage 的置顶在首次同步时交给主进程合并（同一路径取较新时间），随后删除。
- **删除、重命名抽成 `desktop-session-commands`**，侧边栏 IPC 与远程镜像共用。删除时在主进程一并清掉置顶与标签，删除和重命名都发出 `conversation-list` 变化，侧边栏据此重载。自动化解绑由调用方注入，避免 `conversations` 反向依赖 `scheduler`。
- **协议新增三个请求**，`sessionId` 均为会话的不透明键：
  - `session.rename { title }` → `{ session }`。标题去首尾空白、截到 200 字符，空标题以 `invalid_frame` 拒绝。
  - `session.pin { pinned }` → `{ session }`。
  - `session.delete` → `{ deleted: true }`。会话正在跑一轮时以 `busy` 拒绝，不替用户中止。
- **会话摘要新增可选 `pinnedAt`**（epoch ms），置顶时出现。已置顶的会话不受列表 80 条上限截断。镜像订阅置顶与会话列表的变化，电脑上的置顶、改名、删除会推送新的 `session.list`。
- TypeScript 包、JSON Schema、`VettaKit` 同时更新，联调夹具同步支持。

## 备选方案

- **置顶只存在手机上**：改动小，但与侧边栏各记各的，同一个会话在两端一个置顶一个不置顶。
- **置顶仍放在渲染进程，镜像经 IPC 向窗口询问**：窗口关闭或未就绪时手机就读不到，而远程镜像恰恰要在没有窗口时工作。
- **删除时替用户中止正在进行的一轮**：手机上一次误触就会打断电脑上正在做的事，改为拒绝并提示。

## 后果

- 旧的手机端不发送新请求，也不读 `pinnedAt`，照常可用；旧的桌面端以 `invalid_frame` 拒绝未知方法，新手机端按普通错误提示。
- 桌面自己删除、重命名会话后，除了原有的本地更新，还会收到一次列表变化并按项目重载列表，结果一致。
- 置顶从每台机器的 localStorage 改为 `~/.vetta` 下的文件：同一用户的多个窗口看到同一份；删除 `~/.vetta/desktop-app` 会连同置顶一起清空。
- Agent Team 名下的会话仍不能从手机删改，手机端会收到通用错误。
