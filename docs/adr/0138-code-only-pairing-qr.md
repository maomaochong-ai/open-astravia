# ADR-0138：配对二维码只装连接码与密码

## 状态

已接受；修改 ADR-0136 中「二维码与连接码并存、二维码装完整配对 URI」的做法。

## 背景

配对二维码原本直接编码完整配对 URI（配对 id、手机长期凭据、电脑身份公钥、电脑名、局域网地址、中继地址），约 250 个字符，二维码为 61×61 模块。设置页上它密得难看，也比 Telegram 这类「扫一下就登录」的二维码难对焦。

ADR-0136 已经让电脑把同一份配对 URI 用连接码和密码加密后放在中继信箱里，手机凭连接码和密码就能取回完全相同的 URI。二维码没有必要再重复装一遍完整内容。

## 决策

1. 连接码已放上中继（状态 `ready`）时，二维码只装 `VETTA://PAIR/<连接码>/<密码>`。全大写让它落在二维码的字母数字模式里；电脑用的不是默认中继时追加 `?relay=<中继地址>`。格式由 `@vetta/remote-control` 的 `buildInviteQr` / `parseInviteQr` 定义，并在三端测试中固定同一组向量。
2. 没有连接码时（关闭外网访问、未配置中继、中继拒收）仍显示完整配对 URI 的二维码；连接码还在放上中继时不显示二维码，避免它在手机镜头下变化。`RemotePairingInvite.qrText` 表达这三种情况。
3. 手机扫到这种二维码后走已有的连接码流程：从二维码指定的中继（缺省为内置默认中继）取信箱、本地解密，之后与扫完整二维码完全相同。
4. 精简二维码采用最高纠错（H，30%），29×29 模块，中心可以放下较大的徽标；完整 URI 仍用中等纠错（M，15%）。

## 后果

- 精简二维码依赖中继：扫码时手机要能访问中继，而完整二维码在同一 Wi-Fi 下不需要。电脑只在连接码确实放上中继后才显示精简二维码，其余情况自动退回完整二维码。
- 安全性与 ADR-0136 相同：二维码里的连接码和密码正好能打开中继上的那份密文，与偷拍完整二维码的风险相当；信箱仍是 10 分钟、10 次读取、首个领取者绑定。
- 旧版手机只认 `vetta://pair?v=2` 形式，扫精简二维码会提示无效；手机端 App 需同步升级。Android 的 intent-filter 区分大小写，因此额外登记大写的 `VETTA` / `PAIR`，系统相机扫码也能打开 Vetta。

## 备选方案

- 精简完整 URI 的字段（去掉电脑名、多余局域网地址、默认中继）：只能从 61 降到 53 模块，改善有限。
- 降低纠错等级：只能少 4 模块，还会削弱中心徽标下的容错。
- 放大二维码显示尺寸：模块数不变，只是看起来松一些，且挤占设置页布局。
