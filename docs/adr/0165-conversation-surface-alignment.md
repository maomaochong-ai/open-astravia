# ADR-0165：会话界面剩余条目对齐（模型菜单细节、消息流渐隐、@ 引用）

## 状态

已接受并实施。对应 ADR-0157 登记表里 `chat` 分组中 B3 未覆盖的部分（模型菜单行细节、
底栏与快捷键）、沉浸式顶栏里的消息流渐隐，以及 `input-bar`、`@ 面板` 两类条目。

## 背景

B3 把模型选择器从「单列长列表」改成三栏（ADR-0159），B2 把顶栏收成按钮组（ADR-0158）。
三栏落地后，行内的信息密度反而变差了：识图、倍率、默认、选中态四个标识挤在
28px 高的行里，每个都是一个小色块，用户扫一行读不出「这个模型到底怎么样」。参照实现
在 0.5.73 之后把其中三个收进一个「详情」浮层，只留名字与星标。

同一时期它还给会话页加了沉浸式顶栏与消息流上下渐隐，并让 `@` 面板可以引用目录。

## 决策

### 1. 模型行：一个详情入口代替三个标识

- 行内只留模型名（搜索态再加来源服务商）、详情入口、星标；
- **去掉选中对勾**：整行已经有 `bg-accent` 底色，再放一个对勾等于把「选中」说两遍，
  而行尾同时有详情与星标时，对勾反而是最容易被误认成「已完成」的那个；
- 详情入口 `solar--info-circle-linear`，**悬停或行聚焦时出现**（`hidden` 而非 `opacity-0`：
  星标那条已经因为不占位被用户抱怨过误点，这里同样不该留一个透明可点区）；
  浮层打开期间保持显示，否则指针移进浮层后触发器消失、浮层失去锚点；
- 浮层内容：模型名、服务商、模型 ID、识图（支持/不支持）、倍率、默认。**标签在上、值在下**，
  整块 `select-text`——用户点开详情多半就是为了复制模型 ID；
- 浮层事件全部 `stopPropagation`：它虽然 portal 到 body，React 事件仍会冒泡回所在的行，
  不拦就会被当成「选中该模型」。

`labels.infoButton` 是可选开关：**不提供时退回旧行为**（识图/倍率/默认直接排在行内）。
插件经 `plugin-ui` 复用同一视图，不能因为宿主加了详情就凭空多一个按钮、少三个标识。

### 2. 列表边缘渐隐与对齐

- 模型列表上下各 10px 渐隐（`mask-image`）。三栏里中间栏是唯一可滚的，没有渐隐时
  「最后一行只露出半截」看起来像渲染坏了；
- 打开时把当前模型 `scrollIntoView({ block: "start" })` 对齐到顶部，而不是 `nearest`：
  长列表里当前项常在视口中间，`nearest` 不动，用户仍要往上找自己的位置。

### 3. 面板材质与开合

- 面板改为 `bg-background/60` + `backdrop-blur-2xl` + `backdrop-saturate-150`，
  深色下补一圈 `border-border/60`：半透明才是毛玻璃；此前是不透明底色再叠自绘高光，
  在深色主题里那层高光几乎看不出，等于「说了玻璃但看不出玻璃」；
- 开合从 motion 弹簧改为 CSS `model-selector-in`（110ms，位移 4px + 缩放 0.985）。
  三栏面板每次弹出都带着虚拟列表，弹簧动画会在打开瞬间多叠一次布局重算。

### 4. 底栏插槽与 Cmd/Ctrl+P

- `ModelSelectorView` 新增 `footerStart` / `footerEnd`：低频入口（权限、模式）放在面板底栏，
  不占搜索框那一行；
- 新增受控 `open`：宿主的 `ModelSelector` 用 `useShortcutScope` 注册 `mod+p` 打开同一个面板。
  快捷键写在**宿主组件**而不是视图里——视图同时被插件与团队面板复用，那些地方不该抢全局键。

### 5. 服务商折叠与默认栏

- 服务商超过 7 行时左栏折叠，末尾一格显示 `+N`，点开全部。几十个服务商时左栏会把中间栏挤没；
- 当前模型已收藏时，面板默认停在收藏栏：用户收藏它就说明它比某个服务商更常用。

### 6. 消息流渐隐

`MessageFeedLayoutVirtualizer` 加 `mask-image`：顶部 14px、底部 36px 渐隐。
上半段解决「顶栏下方被硬切一刀」，下半段同时承担「输入框上沿的收口」——
输入栏自己是实底，消息流直接怼到它上面会有一条硬边。

### 7. @ 面板引用目录

- 主进程 `listFilesystemFilesRecursive` 新增 `includeDirectories`：目录单独计数、
  不占文件上限，因此打开它不会把原先能搜到的文件挤出结果；
- `@` 面板搜索时把目录也纳入命中，同名时目录排前（引用整个模块比引用它的同名文件常见）；
- 浏览态点目录仍然进入目录（原行为），行尾多一个「引用目录」入口；
  搜索态的目录没有「可进入的位置」，点它就是引用。

## 备选方案

- **保留行内三个标识，只把详情做成 tooltip**：tooltip 不能选中文字，而「复制模型 ID」
  正是详情最主要的用途。
- **把详情放进第二栏顶部（选中模型的摘要）**：只对当前模型有效，用户想比较两个模型时
  还要来回点。
- **沉浸式顶栏整块浮在消息流上**：参照实现的形态是页头变成浮层、消息流穿到它下面。
  这需要 app-shell 的页头结构变更（`main[data-header-overlay]` + 各页补偿），
  超出本次「会话域」范围，只先做了消息流自身的渐隐。后续 B8 批次已补齐页头浮层化
  （`pageHeaderImmersiveAtom` + `RootLayoutView.headerOverlay` + `MessageFeedLayoutTopInset`），
  此处保留取舍记录，实现状态以源码为准。

## 后果

- 正面：模型行可读性明显提升；详情里能直接复制 ID；面板看起来真的是玻璃；窄窗口下
  服务商栏不再把模型栏挤没；`@` 能引用整个目录。
- 代价：新增一组可选 labels（`infoButton` 等），宿主与未来的插件实现都要补文案；
  `ModelSelectorView` 多两个插槽与一个受控开关注入点；文件检索多一个可选参数，
  IPC 合同随之放宽（仅接受布尔开关，其它值按 false 处理）。
- 已知限制：
  - **沉浸式顶栏已在 B8 补齐**：页头浮层化与顶部留白均已落地，「滚到顶首条消息不被顶栏
    挡住」随之成立，ADR-0157 的状态列已同步改为「已对齐」，详见该文档 §15。
  - **SSH 项目的目录引用未做**：需要 Go helper（`ssh-helper`）补目录枚举与
    `ssh-transport` 的远端命令参数，跨三个包；本地项目已可用，远端项目仍只回文件。
  - 底栏插槽已具备，但沙箱权限仍留在输入栏：把它移进菜单需要跨会话与插件两条路径的
    权限模型改动，本次只提供插槽。
