<Takeaways>
  <li>远程连接目前是 Windows Desktop 与 Android 客户端之间的开发预览</li>
  <li>配对二维码和密钥只交给你要连接的移动设备</li>
  <li>远程输入默认关闭，需要单独确认并授予权限</li>
</Takeaways>

当前远程连接由 Desktop 生成一次性配对邀请，Android 扫描后建立连接。屏幕画面通过 WebRTC 传输，控制消息使用独立的 DataChannel；中继服务只负责连接和信令，不应被理解为保存屏幕画面或输入内容。

> 当前功能属于 developer preview。源码仓库提供 Android 项目和远程协议实现，但普通用户是否能在下载包中使用此功能，以当前 Desktop 构建和设置页实际显示为准。

## 前置条件

- Windows Desktop 版本包含 **设置 → 远程连接**。
- Android 设备安装了对应版本的 Vetta 移动端。
- Desktop 和 Android 都能访问配置的 Relay；网络策略不能阻断 WebSocket 或 WebRTC 信令。
- 连接前确认屏幕上没有不应出现在移动设备上的敏感内容。

## 创建配对

<Steps>
  <Step>
    ### 在 Desktop 创建邀请

    打开 **设置 → 远程连接**，点击创建配对。Desktop 会生成配对二维码并显示连接状态。
  </Step>
  <Step>
    ### 在 Android 扫描

    打开移动端的远程连接入口，选择扫描配对二维码，把二维码完整放入取景框。不要通过聊天、截图分享或 URL 查询参数传播配对密钥。
  </Step>
  <Step>
    ### 等待连接就绪

    Desktop 与移动端都显示在线后，再在移动端打开远程 Desktop 视图。若一端先启动，等待另一端完成握手，不要连续创建多个配对。
  </Step>
  <Step>
    ### 单独开启输入

    需要鼠标、滚轮或键盘控制时，在 Desktop 的 **控制权限** 区域显式开启远程输入。仅查看屏幕时保持关闭。
  </Step>
</Steps>

## 能做什么

| 能力 | 默认状态 | 说明 |
| --- | --- | --- |
| 查看桌面画面 | 配对后可用 | 移动端显示 Desktop 的实时画面 |
| 指针和滚轮 | 需要开启远程输入 | 输入事件经 DataChannel 发送 |
| 硬件键盘 | 需要开启远程输入 | 只发送受协议验证的键盘事件 |
| Agent 会话控制 | 取决于客户端版本 | 使用远程控制协议的会话请求/事件语义 |

远程输入的开启是宿主权限，不等于所有操作都会自动执行。Agent 仍会遵守自身的执行模式、工具权限和用户确认流程。

## 安全与生命周期

- 配对邀请包含高熵密钥；只把二维码交给目标设备。
- Relay 使用配对标识和密钥校验连接，房间在一段时间无活动后过期；重新配对会生成新的密钥。
- 不要把二维码、邀请 URI 或配对密钥写入 Issue、日志、屏幕录制或项目文件。
- 不再使用某台设备时，在 Desktop 点击撤销配对；撤销后应在移动端删除旧连接并重新扫描。
- 完全退出 Desktop 会使依赖 Desktop 的远程连接和 Agent 会话停止或断开。

## 无法连接时

1. 确认设置页显示的状态不是错误，Desktop 没有被系统休眠或退出。
2. 重新创建一次配对，不要复用过期二维码。
3. 确认 Android 扫描的是完整邀请，而不是裁剪后的图片。
4. 检查 Relay、WebSocket、防火墙和代理策略。
5. 连接成功但没有画面时，检查 WebRTC/UDP 策略；画面正常但无法操作时，检查 **控制权限** 和输入是否支持。
