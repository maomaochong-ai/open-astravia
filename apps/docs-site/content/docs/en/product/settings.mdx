## Platform and build differences

- **Remote access** and **SSH hosts** appear on Windows, macOS, and Linux.
- **App Snapshot** and **Permissions** appear only on macOS.
- **Account** requires sign-in. An open-source serv-less build has no commercial account, so this page is absent.
- The theme list depends on the build and on themes packaged with the app.
- An entry marked **BETA** can still change. Remote access is not marked that way today.

## How to change a setting

1. Change it on the settings page and save. Do not start by editing internal JSON.
2. After a model, MCP, IM, webhook, SSH, or remote-access change, run the matching connection test or a minimal task.
3. Before migrating or diagnosing, stop the related task and read [configuration paths](/reference/configuration-paths/).
4. Copy structure only. Keep tokens, cookies, OAuth state, webhook URLs, pairing QR codes, and connection codes out of projects and issue reports.

## Easy mistakes

| What you see | What it means |
| --- | --- |
| Node, Python, or Git works in a system terminal | Vetta's runtime, or the Git it detected, may still be missing |
| An API key was entered | The model still needs a real call before it counts as working |
| A plugin permission was granted | The plugin is not in a separate sandbox. It runs in the Desktop interface process |
| An automation exists | A missed time is not run later |
| An IM channel was revoked | The third-party account and every local trace are not necessarily gone |
| A phone can read sessions | It cannot necessarily see the desktop. The picture also needs away-from-home access and Allow desktop control under that phone |

<Callout title="Settings pages are not a cross-version API" type="info">
  Names, visibility, and form fields are user interface. Scripts and integrations should use the public SDK, RPC, CLI, or a configuration field that is explicitly promised. Do not depend on unpublished DOM, internal paths, or menu order.
</Callout>
