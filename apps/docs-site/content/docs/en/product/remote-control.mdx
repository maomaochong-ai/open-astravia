description: Pair an iPhone or Android phone with this computer to continue its sessions, and view and control the desktop.

<Takeaways>
  <li>Windows, macOS, and Linux all have Settings, then Remote access</li>
  <li>The phone follows this computer's sessions, end to end encrypted</li>
  <li>Give the QR code, connection code, and password only to the phone you are pairing</li>
</Takeaways>

Remote access lets a phone follow the work on this computer. It can open Chat and sessions in projects that are already open, including tasks you started on the computer, then reply, answer a question, or start a new session. The relay forwards ciphertext only. It does not store session contents.

Screen control is separate. Each paired phone has its own switch.

Phones paired with the previous protocol cannot continue. Pair them again.

## Before you start

- Vetta on the computer can open **Settings → Remote access**. All three desktop systems have this page.
- The phone runs a Vetta build that speaks to this computer. iPhone requires iOS 26 or later. Android uses the current Vetta app.
- The same Wi-Fi can connect directly. Away from that network, turn on **Allow access away from home** and make sure both sides can reach the configured relay.
- Check the screen before pairing. With remote control on, the phone can see the whole desktop.

## Pair

Opening **Settings → Remote access** prepares a QR code and shows about how many minutes remain. A code lasts about 10 minutes. It is replaced as soon as it expires, is used, or you click **Refresh**. The first phone to scan it is the only one that code will accept.

<Steps>
  <Step>
    ### Open the pairing page on the computer

    Go to **Settings → Remote access**. If secure credential storage is unavailable, the page says pairing is not possible instead of showing a code that cannot work.
  </Step>
  <Step>
    ### Use one method on the phone

    | Method | iPhone | Android | When to use it |
    | --- | --- | --- | --- |
    | Scan the QR code | Yes | Yes | The phone is next to the computer |
    | Connection code and password | Yes | Yes | You are not next to the computer. The computer shows an 8-character code and a 6-digit password. On the phone, choose **Connect with a Code** |
    | Enter the address manually | Yes | Yes | Same Wi-Fi. Enter the address shown on the computer. Both sides then show the same 6-digit code |

    A connection code needs **Allow access away from home** and a relay that supports codes. Otherwise the computer keeps the QR code and says the connection code is unavailable. Manual addresses work only on the same LAN. Guest networks often isolate devices; scan or use a connection code instead.
  </Step>
  <Step>
    ### Match the code before you allow the phone

    After a manual address, the computer shows **Phones waiting for approval**. Allow the phone only when its 6-digit code matches. Otherwise choose **Deny**.

    Every phone that connects raises a system notification on the computer. If you did not do it, remove that phone under **Remote access**.
  </Step>
  <Step>
    ### Confirm the phone is online

    **Paired phones** lists the device and how it is connected: direct (P2P), same Wi-Fi, or via cloud relay. You can leave the page. The phone remembers this computer and reconnects on its own.
  </Step>
</Steps>

The first time a phone connects over the LAN, macOS may ask whether to allow incoming connections. Allow it. iPhone also asks for local network permission the first time.

## What the phone can do

While the computer is online, the phone can:

- Open Chat and project sessions, including a task already running on the computer. Replies keep arriving, and tool calls appear as cards.
- Send a follow-up, stop the current turn, or start a new session.
- Answer a question the computer is waiting on.
- Send images and files, hold to dictate into the input (the text is not sent until you send it), and change the model and thinking level used for later replies in that session.

While the computer is offline, the phone can still read the 50 most recently cached sessions. It cannot send or start a session.

On the same Wi-Fi the phone tries a direct connection first, then the relay. An idle connection sleeps.

## View and control the desktop

While that phone is online and **Allow access away from home** is on, a computer icon sits beside its name. A green check at its corner means the phone can view and control the desktop. A red cross means it cannot. Click the icon to switch. It starts with a green check.

The phone can then open a full-screen desktop: taps, drags, scrolling, and typing go to this computer. On Android, open it from Home or Settings. On iPhone, open **Remote Control** from the Home drawer, from Settings, or by long-pressing the app icon. Switching it to a red cross drops the picture immediately. The phone can still read sessions.

The computer captures its screen only while a phone has this page open and in front. Leaving the page or switching apps stops the capture, and on macOS the screen-recording indicator goes out. Both need a phone and computer on this release; an older phone keeps the picture running while it is connected, and iPhone does not show the desktop of an older computer.

On macOS, Vetta needs **Screen Recording** to show the picture and **Accessibility** to take taps and typing (System Settings → Privacy & Security). When either is missing, the phone says which one, and the computer shows a notification that opens the right pane. Restart Vetta after granting Screen Recording.

On iPhone, the whole screen works like a trackpad, inside the picture or outside it: move one finger to move the pointer, tap to click, tap with two fingers to right-click, and hold a finger for half a second to drag. Pinch with two fingers to zoom, and move two fingers to move a zoomed picture. The pointer follows your finger at once, always shows, and takes the shape it has on the computer (arrow, I-beam, hand); a zoomed picture moves only with two fingers. There is no scrolling gesture yet: drag the scroll bar. The bar above the keyboard adds Esc, Tab, the arrow keys, and ⌃ ⌥ ⌘ ⇧: tap one to hold it for the next key, or tap it twice to lock it. **Paste** types the iPhone's clipboard on the computer. Shortcuts from a hardware keyboard go straight through. Only the remote desktop turns to landscape.

The picture is set up through the relay and then travels directly between phone and computer, so the computer icon stays hidden when away-from-home access is off or the phone is offline. Once a direct connection is up, sessions and chats use it too. Some networks cannot connect directly: sessions then keep working through the relay, and the phone says the desktop cannot be shown on this network. The Agent's own execution mode, tool permissions, and confirmations are unchanged.

## Away from home

**Allow access away from home** is on by default. Turn it off and phones can connect only on the same Wi-Fi.

The settings button beside it can replace the relay address, test before saving, or restore the default. The address must start with `wss://` or `https://`. The test reports whether the address is reachable, whether it is a compatible Vetta relay, and whether it supports connection codes.

Saving refreshes the current QR code. An Android phone that is already connected switches to the new address. A phone that is offline learns the new address the next time it connects on the same Wi-Fi. If the computer uses its own relay, turn on **My computer uses its own relay** while pairing with a connection code and enter that same address.

## Safety

- The QR code, the 8-character connection code, and the 6-digit password are one-time pairing material. Do not put them in chat, screenshots, issues, or project files.
- Sessions are encrypted between the phone and the computer. The relay cannot read them.
- A manual pairing must be approved on the computer after the codes match. A QR code works for the first phone only.
- Quitting Vetta on the computer disconnects session sync and the remote desktop.

## Remove a phone

Choose **Remove** on that row on the computer, or unpair from the phone's computer settings. Sessions on the computer stay.

- iPhone clears the sessions cached on that phone. Pair again to reconnect.
- Android keeps sessions already synced on the phone. You can still read them, but they stop updating until you scan the same computer again.

## When it will not connect

1. Confirm the computer is still running and the settings page is not showing an error. Sleep or quit makes the phone go offline.
2. When a QR code or connection code expires, wait for the replacement or click **Refresh**. Do not reuse a code that was already used.
3. If a manual address fails, confirm both sides show the same code and that the network does not isolate the two devices.
4. If the same Wi-Fi works and leaving home does not, check **Allow access away from home**, the relay address, and whether the network blocks WebSocket.
5. If sessions work but the phone has no desktop picture, confirm that phone is online, away-from-home access is on, and the computer icon beside it has a green check. A message on the phone names a missing macOS permission or a network that cannot connect directly.
