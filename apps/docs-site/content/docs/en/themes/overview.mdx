Theme modules can replace more than colors: they can provide host components, register pages, fill public regions, and mount theme runtime logic. Use a theme when you need a coherent experience; for colors, dark mode, or sidebar styling, use **Settings → Appearance** instead.

## What a theme can provide

<Cards>
  <Card title="appearance" description="Color tokens and surface appearance." />
  <Card title="components" description="Replace host component slots that are public to themes." />
  <Card title="pages" description="Add theme pages with navigation entries." />
  <Card title="regions" description="Fill public host regions." />
  <Card title="runtime" description="Mount headless logic for the lifetime of an active theme." />
</Cards>

Themes load through Module Federation. React, the Theme SDK, and host UI packages are shared singletons. Theme code runs in the desktop renderer and must be treated as trusted code.

## Current distribution boundary

<Callout title="Curated distribution" type="info">
  The current theme system targets built-in or curated theme development. It does not provide a general remote installation or marketplace process for arbitrary third-party themes. Integrate and build themes in the Vetta monorepo and validate them with the desktop application; do not promise users that any external theme archive can be installed directly.
</Callout>

The appearance page may be controlled by a feature flag, and only themes bundled with the application can be selected.
