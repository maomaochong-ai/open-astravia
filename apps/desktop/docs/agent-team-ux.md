# Agent Team UX 合同

## UX Brief

- 主要用户：需要把复杂任务拆给研究、实现、审查等角色的 Desktop 用户。
- 页面唯一任务：选择一个现成团队开始对话，并在需要时配置或创建团队。
- 关键决策：选择哪些智能体、是否引用或复制其能力配置、谁是 Leader、当前消息路由给谁。
- 主要行动：在“对话”下拉框切换到“团队”，打开默认团队后直接发送请求；需要定制时再进入智能体库或团队设置。
- 成功反馈：聊天流中显示用户消息、成员最终结果和明确的成员委派；重发同一请求不会重复执行。
- 不在范围内：用户编辑预设系统提示词、查看其他成员的工具调用/推理过程、跨设备同步和实时协同编辑。

## 状态矩阵

| 状态 | 用户看到什么 | 可执行操作 | 恢复方式 |
| --- | --- | --- | --- |
| 首次进入团队 | “对话”下拉框中的团队来源、默认团队和预设成员 | 直接开始对话 | 无需先创建团队 |
| 首次进入智能体库 | 应用内置的 Leader、研究、执行和审查预设 | 配置能力或添加自定义智能体 | 内置身份固定，能力可修改 |
| 能力加载中 | 页面骨架，能力开关不可用 | 等待 | 加载失败显示错误并重试页面 |
| 能力不可用 | 开关禁用并标注全局禁用 | 仍可查看配置 | 到能力市场启用后返回 |
| 能力很多 | 按类型分组的固定高度列表、图标、搜索和启用数量 | 搜索、滚动或使用全部能力 | 清空搜索恢复全部分组 |
| 保存影响多个团队 | 显示受影响团队数量和名称 | 二次确认或离开 | 重新加载后再次预览 |
| 团队无成员 | 创建按钮禁用 | 添加至少一名成员 | 选择成员并指定 Leader |
| 聊天处理中 | 输入和发送按钮禁用，结果逐成员追加 | 等待 | 错误保留输入文本，可重试 |
| 会话读取失败 | 错误提示，不伪造空会话 | 返回团队列表或重试 | 修复配置/会话后重新进入 |
| 委派完成 | 显示委派关系和目标成员最终文本 | 继续追问或 `@` 指定 | 目标失败时由 Leader 说明风险 |

## Visual Spec

- 信息层级：对话来源与当前团队 > 消息结果 > 输入和成员路由；配置页则是对象身份 > 能力搜索/开关 > 共享影响提醒。
- 视觉语言：聊天复用普通对话的 PageHeader、Virtuoso 消息容器、Markdown 渲染、Input Card、SendButton 和 ActivityPanel；配置页沿用 Desktop 的 border、muted、primary Token 和设计系统表单组件。
- 响应式：所有页面根节点占满 `MainContentFrame` 的剩余宽度并允许收缩；成员网格在窄窗口降为单列，聊天内容可滚动，输入区固定在底部。
- 可访问性：表单字段有可见 label，能力使用设计系统 Switch，引用/复制使用设计系统 Select，成员路由使用按钮语义；键盘焦点可见，处理中状态禁用重复提交。
- 差异化选择：成员提及条把内部成员 ID 转换成可识别的 `@handle`，降低群聊路由的记忆成本。
