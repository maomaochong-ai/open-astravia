# Markdown 公式与页面预览

聊天回复和 Markdown 文件预览默认支持以下内容。

网页链接会按需加载目标站点的 `/favicon.ico` 作为图标，不向第三方图标服务发送链接，也不下载网页正文。图标请求不包含原链接的路径、查询参数、片段或内嵌账号密码，并禁用 Referer；加载期间或失败时显示通用网站图标。成功加载遵循浏览器缓存，失败结果在当前窗口最多缓存 128 个站点、持续 5 分钟，过期后重新挂载链接时可重试。只在页面 HTML 中声明自定义图标、没有标准 favicon 的网站会显示通用图标。文件、页内锚点、邮件与电话链接不请求网站图标。

| 内容 | 写法 | 行为 |
| --- | --- | --- |
| 行内公式 | `$E=mc^2$` | 按公式排版，支持屏幕阅读器使用的 MathML |
| 独立公式 | 单独一行 `$$` 开始和结束 | 居中显示，较宽公式可横向滚动 |
| 公式代码块 | `math`、`latex` 或 `tex` 围栏 | 独立公式 |
| SVG | `svg` 围栏或完整 `<svg>...</svg>` | 直接显示图形；围栏提供源码切换与复制 |
| HTML | `html` 围栏、独立 HTML 块或完整 `<html>...</html>` | 静态预览，点击「在独立窗口运行」启用交互 |

推荐使用围栏传递 HTML 页面和 SVG，这样可以完整保留源码，包括空行和 Markdown 标记。公式不在普通代码、行内代码中识别；不是所有 LaTeX 宏都受 KaTeX 支持，不合法或过大的公式显示源码。

HTML 可以使用内联样式、脚本、Canvas 和 DOM 事件；可以嵌入 data 图片与字体。它不能访问 Vetta 的文件、账号、会话或宿主 API，也不能加载 CDN、外部图片、网络 API、其他网页或提交表单。需要外部依赖的页面应通过原有浏览器/项目预览功能打开。

预览过程中可以随时切换「源码」或复制原文。HTML 的「停止」会销毁运行页面并恢复静态预览；重新运行从头开始，页面输入与脚本状态不会保留。生成中先显示源码，生成完成后再预览。切换源码、滚出可见区域、窗口进入后台、内容被改写或连续运行达到 30 秒时，脚本会停止；返回后需再次点击运行。

公式使用按需启动的 Worker，持续变化时最多每 250ms 提交一次计算；相同公式复用结果。原始 SVG 的流式图像更新最多每 500ms 一次。不可见内容不进行重计算，HTML 不会随每个新 token 重新执行脚本。SVG/HTML 超过 256000 字符时保留源码、暂不预览。

长回复的 Markdown 解析也会合并更新：仍在变化的尾块达到 12000 字符时，每 200ms 更新一次；达到 50000 字符时，每 400ms 更新一次。小尾块维持原有节奏，已冻结的代码块不计入尾块预算。生成结束或内容被替换时立即对齐完整内容，不截断原文。未闭合的行内公式、多反引号代码和含括号的链接会短暂等待闭合；等待有时长和长度上限，生成结束时仍不完整的语法按原文展示。

代码高亮只在生成完成、接近可见区域且预算允许时执行。超过 30000 字符、1000 行或单行 2000 字符的代码保留完整等宽文本与复制能力；高亮生成结果超过 256000 字符时也回退为文本。高亮缓存最多 128 项，键与结果合计最多 400 万 UTF-16 code units（字符串载荷约 8MB，不包含对象与 DOM 开销）。这些限制减少主线程计算和历史消息缓存占用，代价是特别大的代码不显示语法颜色。

交互 HTML 在独立 Electron 沙盒窗口中运行，使用独立的临时会话，不加载 preload。主进程最多同时打开两个预览，30 秒后强制结束其渲染进程；同步死循环不会阻塞聊天线程。它不提供操作系统级内存配额，短时间的极端内存申请仍可能影响系统。静态预览始终禁用脚本，交互页面不会在打开历史或收到回复时自动运行。

`mermaid` 围栏支持流程图、时序图等 Mermaid 图表。生成完成且进入可见区域后才启动独立渲染进程，支持切换源码、放大、复制图像和导出 SVG。渲染失败可以重试，源码始终保留。每个图表最多 12000 字符、200 条边，执行最长 8 秒；任务串行，排队最多 8 个，结果缓存最多 32 项、键和内容合计 200 万 UTF-16 单元（约 4MB）。引擎按需加载，不进入聊天渲染器。

图片支持失败重试、灯箱缩放、复制 PNG 与另存原格式。聊天中的相对路径以会话工作目录为基准，文件预览以 Markdown 所在目录为基准；本地和 SSH 图片继续经过现有文件访问权限检查。公开网络图片的复制与保存最多 8MB、15 秒、4 个并发请求；本地图像沿用文件预览大小上限，转成剪贴板 PNG 时最多 1600 万像素。不能读取的资源保留替代文字和重试入口。

链接图标会读取网站首页声明的 `icon` / `apple-touch-icon`，再回退 `/favicon.ico` 与通用图标。只请求来源域，不发送页面路径、查询参数、Cookie 或登录凭据。可见链接才触发发现；最多 4 个并发、64 个排队来源，单来源最长 10 秒；成功缓存一小时，失败缓存五分钟，最多 64 个来源。Main 的资源请求仅允许公开地址，逐跳校验重定向并固定解析后的 IP，使用直接连接，不携带应用代理认证；不可直连的站点会回退。内网或需登录的图像可能可以展示，但无法通过该公开资源通道复制/保存。

公式按钮复制原始 TeX。单美元符号遵循分隔符内侧不为空白、结束符后不紧接数字的规则，避免把 `$5 and $10` 等金额误识别为公式；字面量美元仍可写成 `\$`。

开发验证：

```powershell
bun scripts/quality/run-vitest.mjs --config apps/desktop/vitest.config.ts --run apps/desktop/src/renderer/domains/conversation/components/blocks/MarkdownRichContent.test.tsx apps/desktop/src/renderer/domains/conversation/components/blocks/markdown-math-client.test.ts
node --test apps/desktop/scripts/markdown-preview.node-test.mjs
node apps/desktop/scripts/markdown-render.bench.mjs
node apps/desktop/scripts/markdown-isolation.test.mjs
```

第二条命令使用 Playwright 的独立无头 Chromium 与临时构建，不连接真实 Vetta 实例。需已安装该版本的 Playwright Chromium；可用 `VETTA_TEST_BROWSER` 选择已安装的浏览器通道。

第三条是可重复运行的长消息基准，包含长正文、大表格和长代码，每个场景按 50ms 间隔追加 40 次，输出解析次数、累计解析字符数和 React 渲染耗时；可追加输出 JSON 文件路径。它使用 production profiling 构建与简化样式，衡量渲染计算，不代表真实 Desktop 的 GPU、滚动或完整布局耗时。耗时只用于同机对比，不作为跨机器的硬性测试门槛；组件测试约束解析频率与最终内容完整性。

2026-09-23 在 Windows、Chromium 151.0.7922.10 上，以相同夹具分别运行本轮优化前后的观察值：

| 场景 | 最终字符数 | 解析次数（前 → 后） | 累计 React 渲染耗时 ms（前 → 后） |
| --- | ---: | ---: | ---: |
| 长正文 | 32886 | 42 → 12 | 1146.0 → 361.6 |
| 大表格 | 21878 | 42 → 12 | 1744.1 → 490.3 |
| 长代码 | 60876 | 43 → 8 | 288.3 → 57.8 |

这是单次运行的观察记录，机器负载会影响耗时。合并快照会引入轻量状态提交，因此总 React commit 数不一定减少；优化目标是减少昂贵解析与渲染工作，不能把上述耗时降幅当作整个桌面应用的性能提升比例。此基准也不证明任意超大文档的首次解析不会阻塞主线程。

第四条命令在临时数据目录启动独立 Electron 测试进程，验证不同进程 ID、JavaScript 交互、宿主和网络隔离、Mermaid 错误恢复，以及同步死循环的 30 秒强制终止；不附着用户的 Desktop 实例。
